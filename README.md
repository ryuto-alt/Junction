# JUNCTION / 継ぎ目

白い施設。四方の部屋は 4m の隙間を挟んで並び、その隙間を窓が貫いている。
**隣の部屋は見える。歩いては行けない。入口が無い。**

道は一つだけ。**手前の枠の中に、向こうの枠を重ねる。**

> **見えている物としか、繋がれない。**

## すぐ遊ぶ（エンジン不要・Windows）

```
cd Junction/build/game
Game.exe
```

`build/game/` はビルド済み（起動シーンは**第3面「継ぎ目の館」**）。
Windows 10/11 + DirectX 12 対応 GPU だけあればいい。

## ★2026-09-04 — v11「見て、重ねて、繋ぐ」

契約書は **`docs/V11.md`**。**ここが心臓なので、触る前に必ず読むこと。**

v10 の「暗い筒を抜けたら別の場所」は**行き先が分からない = 意味不明**だったので破棄した。
v11 は転送の理由を**プレイヤーの目**に返す。

### ★継ぎ手の枠（gate）— カメラが地図を編む

```
        ┌─ 手前の枠 ─┐
  目 ●──┤            ├──→  向こうの枠が【この開口の中に見えている】
        └────────────┘      ⇒ 二枚は繋がる。くぐると向こうの枠の裏に出る
```

- 判定は「向こうの枠の中心へ引いた線が、手前の枠の開口を通るか」
- 向こうの枠は**正面をこちらへ向けて**いること。裏からは繋がらない
- **どこへ出るかは通る前に見えている**（枠の膜が裂けて、その向こうに行き先が映る）
- ★重ねた事は 1.2 秒覚える。枠に寄ると自分が正面から外れて判定が切れるため

窓ごしに隣の部屋の枠を見つけて重ねる ── **施設まるごとが視線のパズル**になっている。

### 道筋（v11.2・通しでクリア確認済み）

```
始まりの帯 --琥珀--> 中の帯 --水色--> 傾く部屋（玉を青い板へ）--水色--> 中の帯 --青--> 出口
```

**中の帯に立つと、谷の向こうの出口と、消えている青い枠と、東の窓の向こうの青い板が
全部同時に見える。** 青い板を押すと青い枠が点く。色だけが理屈で、文字は出さない。

機械室（エイムズの部屋）／仕分け廊（画角の嘘）／保管庫（人型）は**寄り道**。行かなくても終われる。

案内は**光の玉**が次にやる事の上に浮く。重なり具合は照準の真下の細い線 1 本だけ。

### 傾く部屋（v11.3）

**ボタンは要らない。歩いている間だけ、進む向きへ床が下がる。** 止まれば水平へ戻って玉も止まる。
歩いて玉を追うと床が前へ傾いて玉が逃げる ── 玉を追い立てる感覚になる。
床の上の什器（ロッカー等）も一緒に上下する（KINEMATIC にしてある）。

★**`physics:setPosition` は【コライダーの中心】を指す。** 原点（足元）を渡すと半径ぶん地面へ埋まる。
`dynprops` の `off`（中心までの高さ）を必ず足すこと。

### ★遊び方を教える層（v11.1）

ルールが特殊なので、放っておいて発見できるものではなかった。次を足してある。

- **対の色** … 同じ色の枠どうしだけが繋がる（枠の灯りと膜の色相）
- **重なり具合のバー** … 枠の前に立つと出る。動くと伸び縮みするので**手探りで探せる**
- **立ち位置の印** … 最初の 2 組だけ、床に対の色のレーン。そこに立てば必ず重なる
- **電源の無い枠は消灯** … 重量板を押すと、板からその枠へ光の帯が飛ぶ
- **繋がっている間は枠と枠の間に光の帯** … 壁を突き抜けて見える
- **傾く床は右クリック（または SHIFT）を押している間だけ** … 離せば止まる

見張りの人型は**視線をふさぐ物**。線の上に立たれると繋がらないので、押しのける（34kg の剛体）。

### ★物理

什器に当たり判定を入れた。棚・ロッカー・ベンチ・柱は動かない壁。
**ドラム缶(26kg) / 木箱(17kg) / 鋼球(48kg) は歩いてぶつかると転がる。**
重量板に物を乗せると継ぎ手の組が開く = 施設の鍵。

★がくがくさせない値: `restitution` 0.2 以下 / `linearDamping`・`angularDamping` を入れる /
**mass は現実の値**（軽いと人にぶつかった瞬間に吹き飛んで嘘に見える）。

### ★傾く部屋 — 見た方へ床が下がる

床は 1 枚の動く板。**視線の向きへ床が下がる**ので、鋼球は**自分が見た方へ**転がる。
重力はワールドの真下のままなので、純粋に物理で解ける。
★どちらを向いても手前が下り坂。振り返っても下っている ── 現実にはあり得ない床。

低い壁で囲った重量板へ玉を入れるのがパズル。**見る方向が唯一の操作。**

### ★視野角のトリック

仕分け廊（36m）を歩くと画角が **74° → 46°** へ絞れる。絞ると近づいても大きくならないので、
**歩いても奥が近づかない廊下**になる。同時に視界が 8 度傾き、振り返ると水平に戻る。

### ★HLSL — `assets/shaders/Membrane.hlsl`

枠に張ってある膜。**左半分と右半分が別々の場所の表面**で、逆向きに流れている。
真ん中の縫い目（ファスナーの歯）だけが二枚を留めている。
繋がると歯が左右へ開き、間に**向こうへ抜けた裂け目**が空く。

くぐる瞬間は**膜そのものがカメラの前を通り過ぎる**（暗転はしない）。
閉じた膜が顔を覆い、そこから縫い目が裂けて向こう側が現れる。

★実測: engine v1.12.9 の post は `wave`/`radial`/`chromatic`/`invert`/`pixelize` が
**値は入るのに描画へ出ない**。効くのは bloom / vignette / grain / exposure だけ。

契約書は **`docs/V10.md`**。**ここが心臓なので、触る前に必ず読むこと。**

**プレイヤーが勝手に作っている心の地図**だけ。

### 継ぎ手（port / link）

このゲームの中心装置。口の奥は **4.2m の暗い筒**で、両端の筒は寸法も材質も灯りも同じ。
筒の**真ん中**を越えた瞬間に、相手の筒の同じ横位置・同じ姿勢へ置き換える。

- ★**転送面は筒の真ん中(`P = D/2`)でなければならない。** 入る側の「奥の板までの距離」と
  出る側の「向こうの口までの距離」が違うと、**画角が変わって切り替わりが一目で分かる**
  （実測: D=2.0 / P=1.55 だと転送直後に部屋が画面の 7 割を占めた）
- ★**筒を真っ黒にすると逆に目立つ。** 転送前が暗黒・転送後は部屋の光で灰色になり、
  **明るさの落差そのものが手掛かりになる**。薄暗いが見えている、が正しい
- ★残る落差は**転送面に近いほど画面を落として**消している（`portDark`）。
  暗い筒の中でさらに暗くなるだけなので、演出としては見えない

### 面の道筋

```
受入ホール(40m四方・真ん中に幅14mの谷) → 東の戸 → 仕分け廊(36m)
   → ★東の端の戸が、ホールの西側に出る
   → ホールに据えてある機械に入る → 26m の機械室
   → 北の別棟 = エイムズの部屋 → 傾斜廊 → 傾いた部屋 → 保管庫 → 長廊(三周)
   → ★谷の【向こう岸】に出る。一度も谷を渡っていないのに
```

**最初の 10 秒で「見えている物は全部、歩いては行けない」が分かる。**
出口の門も、機械も、谷の向こう岸も、全部見えている。柵も谷も越えられない。

## 作り方

```
python source/gen_textures.py          # tex/*.png
python source/gen_sfx.py               # audio/**
python source/gen_stages.py            # scenes/*.json, Junction.lua の STAGES, models/gen/manifest.json(壁・床・廊下)
# 壁・廊下のモデルが足りないと言われたら（BlenderMCP は要らない）:
blender.exe --background --factory-startup --python source/run_kit.py
```

★**BlenderMCP が落ちていてもモデルは出せる。** `source/run_kit.py` が
`JX_MANIFEST_ONLY=True` と `JX_ROOT` を渡して `blender_kit.py` を叩くだけなので、
`blender.exe --background` で回る（実測: Blender 5.1）。
★**システムの `python` が Microsoft Store のスタブだと何も動かない。**
`gen_stages.py` は標準ライブラリしか使わないので、Blender 同梱の python でよい。

`gen_stages.py` はステージを書き出す前に **全状態 (部屋, 区画, 大きさ) を総当たり**して、
出口に着けるか / 想定手数（`minHops`）より短く解けないか / **到達できる全状態から出口へ戻れるか（詰み無し）** /
什器が扉の助走を潰していないか / 什器が柵の踏み台にならないか（★縮尺込みで判定）/
**偽の廊下が到達できる区画に付いているか** を検査する。案内の光の経路（`hint`）もこの最短手順から出る。

`gen_stages.py` は `Junction.lua` の `>>>STAGES`〜`<<<STAGES` を書き換える。配布ビルドは MCP の `dx12_build_game`。

| 担当 | 触ってよい | 触ってはいけない |
|---|---|---|
| モデル | `source/blender_kit.py`, `assets/models/**` | `gen_stages.py`, `*.lua` |
| Lua | `assets/components/*.lua` | `source/**`, `assets/scenes/**` |
| レベル | `source/gen_stages.py`, `assets/scenes/**` | `assets/components/**` |

### 面を書くときの語彙（v10）

```python
PORT("a_e", "A", wall="E", off=-17.0)            # 継ぎ手の口(壁に開ける)
PORT("a_u", "A", at=(-14.0, -10.0), into="E")    # 継ぎ手の口(部屋の中に単体で立てる)
PORT("e_x", "D", ames=("E1", 0.0, 8.6), into="N")  # 別棟の中に立てる
JOIN("a_e", "b_w")                                # 両通行の結線
LINK("i_n", "i_s", times=2)                       # ★最初の 2 回だけ別の所へ
AMES("E1", "D", "N", w=9.0, d=15.0, h=5.0, alpha=0.07, props=[...])
WATCH("W1", "H", (-9.0, 7.2), near=5.0, step=1.6, wait=0.8)
CREEP("c_ceil", ["I_Ceil", "I_CeilM", ...], zone=(...), axis="z", a=42, b=68, dy=-1.9)
ROLL(zone=(...), axis="z", a=48, b=73, deg=(0.0, 9.0))
R("G", "tilt16", (95.0, 105.0), tilt=9.0, tiltAxis="z", tiltAt=(0.0, 1.30, -8.0))
R("A", "atrium40", (0.0, 0.0), floorMat="concrete", intensity=3.4)
```

★`from` が同じ結線は**上から順に**使う。`times>0` を先に書くこと。

### `assets/models/` の置き場所

```
arch/wall/   壁。wall / wall8 / wall18 / wall20 と、その開口違い(_door/_hatch/_vent/_gate/_window/_hi)
arch/slab/   床と天井の板。floor* / ceiling*
arch/trim/   部屋の造作。column / doorleaf / eave / seam / divider / blocker / barrier / railing
props/       什器と設備。bench / locker / crate / vent / pipes / troffer
game/        ゲームの仕掛け。goal / pin / band / lane / figure / hand
gen/         ★自動生成。手で置かない・手で消さない
  manifest.json  gen_stages.py が書き、blender_kit.py が読む注文書
  floor/   fm_*   床(部屋ごとの寸法)
  ceil/    cm_*   天井(同上)
  tunnel/  tn_*   継ぎ目の台形の廊下
  wall/    wm_*   開口が複数ある壁
tex/         テクスチャ。gen_textures.py が書く
```

★どのモデルがどこへ行くかは **`dest_of()` が唯一の正**。`source/blender_kit.py` と
`source/gen_stages.py` の **両方に同じ物がある。片方だけ直すと**、シーンが書くパスと
実ファイルの場所がずれて **モデルが丸ごと消える**。新しいモデルを足したら両方に足すこと
(知らない名前は例外で落ちるので、`models/` 直下に散らかることはない)。

★`.gltf` の中の `"uri"` は **その `.gltf` からの相対**。`tex/` は `models/` 直下のままなので、
深さ 2 のフォルダ(`arch/wall` など)からは `../../tex/xxx.png` になる。
`blender_kit.py` の `export()` が書き出し時に付け直している。

### 幾何の規約

- 部屋は内寸の面と面が **`GAP = 4.0m`** 離れて隣り合う。その 4m を台形の廊下が貫く。
- 口の位置 `off` は部屋の**単位座標**（縮尺前）。壁モデルは単位寸法で作り transform scale で縮尺を掛ける。
- 照明は位置と range を縮尺倍、強さはそのまま（エンジンの減衰は逆二乗ではない。k² だと白飛び）。
- 絶対寸法の物（柵・隙間・溝・敷居・出口）は縮尺を掛けない。
- 溝は部屋に 1 本。落ちると直前の廊下の出口へ戻る。

## 踏んだ罠（時間を溶かした順）

### v10（継ぎ手・エイムズ・傾いた部屋）

- ★★**継ぎ手の転送は「筒の奥の面までの距離」で見え方が決まる。** 入る側と出る側で
  違うと画角が変わり、切り替わりが一目で分かる。転送面は必ず**筒の真ん中**（`P = D/2`）
- ★★**筒を真っ黒にすると逆に目立つ。** 明るさの落差そのものが手掛かりになる（0.072 が正）
- ★**筒の横の余裕（MG）を空けると、口の縁との隙間から母屋の明るい壁が覗く。** 0.02 にする
- ★★**モデルが存在しないままシーンを開くと、そのエンティティは丸ごと落ちる。**
  「生成 → Blender → **シーンを開き直す**」の順を守る（`reload_assets` だけでは戻らない）
- ★**Blender のモデルを `build_divider()` などに足すと出ない。** `run_kit.py` は
  `JX_MANIFEST_ONLY=True` で回るので `build_all/build_rooms/build_divider` は丸ごと飛ぶ。
  新しいモデルは **`build_v10()`** に置くこと（`fence` がこれで 2 回消えた）
- ★**継ぎ手の口には扉板を立てない**（`wall_model` は全 door 開口に置くので `self.noleaf` で外す）
- ★**エイムズの部屋は、歪めた床を水平へ戻さないと壁の下に虚空が覗く。**
  戸口から奥へ伸びる線を軸に転がして戻す（`check_ames` が 2cm 以内で検査）
- ★**部屋ごと傾けるときはグループの目印（marker）を動かさない。** 子が付いて回る
- ★**エンジンの Transform は行ベクトル・ZXY 順**（`Rz(z)·Rx(x)·Ry(y)`）。
  傾けた板・傾けた部屋は**行列で組んでから分解する**
- ★**柵と谷は同じ軸に並べる。** 柵は部屋の全幅に張るので、違う軸だと**谷の上に柵が浮く**
- ★**塞いだ板の柵（barrier）を 40m のホールに置くと視界の下半分が消える。**
  見通せる柵（`fence`）を使う。しかも**白い壁の前の白い柵は見えない**ので濃い材質にする
- ★**Play 直後は開幕カメラが回っていて OnUpdate が早期 return する。**
  MCP から仕掛けを試すときは**先に 400 フレーム進める**（でないと「動かない」と誤診する）

### v5〜v9


- ★★**台形の廊下メッシュの「突き当りの壁」は偽の廊下だけのもの。** 本物の継ぎ目や窓に付けると、
  向こうの部屋の開口を同寸の白い板がぴったり塞ぐ。**当たり判定が無いので歩けば抜けてしまい**、
  「壁に見えるのに通れる」という一番たちの悪い絵になる（v9 まで 8 面すべてで起きていた）。
- ★★**傾いた床の当たり判定を「区間ごとの軸並行な箱」で作ると階段になる。** 段差登りが
  そのたびカメラを持ち上げるので「がくんと跳ねる」。平面は**傾けた箱 1 枚**で厳密に表せる。
- ★**`resetRun` は Play のたびにシーンの設定を上書きする。** 環境光をシーン JSON で直しても、
  ここに古い値が直書きされていると Editor でしか効かない。
- ★**同じ口に栓(plug)を 2 つ作らない。** `plugs` と morph の `seal/unseal` は別々に栓を作る。
  名前引きは 1 体しか掴めないので、もう 1 体が口を塞いだまま残り**扉が永久に開かない**。
- ★**部屋どうし・廊下と部屋の重なりは目で見つからない。** 壁が壁を貫くだけなので絵は一見それらしい。
  `check_layout` / `check_corridors` に任せること。
- ★★**エンジンの重力は 9.8 ではなく 14 m/s²**（`PhysicsSystem.cpp`）。`jumpSpeed` を 9.8 で
  計算すると跳べる高さが 0.9 → 0.63 になり、高い口に届かない。
- ★**空中でも WASD は効く**が、`physics:jump` を Lua の task から撃った実験では水平に進まなかった。
  跳ぶ距離は必ず **人と同じ入力（W+SPACE）で実測**すること。実測: 大きさ 1 で 1 跳び 2.10m / 滞空 0.62 秒。
- ★**大きさを変える時は床の高さを渡す**（`useBody(..., floorY)`）。敷居 0.9m の廊下の中で
  床 0 に置くと床下へ落ち、復帰→落下のループになる。
- ★**目の高さは「体の足元 + 1.7 × 見た目の縮尺」**で置く。廊下の中は体と見た目の縮尺が違う。
- ★★**シーンを開いた時点で存在しなかった entity は `scene:spawn` しても描画されない。**
  → 実行時に動かす物は全部シーン JSON に置いて床下（y=-200）へ隠す（Pilot / Body_*）。
- ★**`CharacterController` の寸法は実行時に変えられない。** → 大きさごとに `Body_0..4`。
- ★★**Play 開始直後に書いた transform はシーンの復元に黙って上書きされる。** → 体は 1 秒押し込む。
- ★**`motionType 0`（STATIC）の当たり判定は transform を書いても動かない。**
- ★**Blender のエクスポータが `tex/*.png` を上書きする** → temp へ出して gltf/bin だけ持ち帰る。
- **エンジンはテクスチャをパス単位で一生キャッシュする** → `dx12_reload_assets{force:true}`。
- **MCP の `key_down` は `isKeyDown` に効くが、Play 中は実時間で走り続ける**ので
  `step_frames` の数で距離は測れない。検証用に `saveNum("dbg_lockYaw",1)`（マウス無視）と
  `saveNum("dbg_size", 2)`（その場で大きさ変更）のフックを残してある。
- **1 灯しか無い小部屋で蛍光灯を明滅させない**（部屋ごと真っ暗になる瞬間が出る）。
- 開口の寸法は `blender_kit.py` と `gen_stages.py` の **OPENINGS 2箇所**にある。
- `build/game/` を作り直し忘れると、clone した人は古い版を遊ぶ。
