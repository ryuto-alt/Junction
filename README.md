# JUNCTION / 継ぎ目

白い虚無しかない建物で、ドアとドアを繋ぎ直す一人称パズル。GDD v1 の実装。

> 検証したい 1 点: **「同じドアでも、入り方が違えば出る場所が違う」は気持ちいいか。**

## すぐ遊ぶ（エンジン不要・Windows）

```
cd Junction/build/game
Game.exe
```

`build/game/` はビルド済みでリポジトリに入れてある（起動シーンは第1面）。
Windows 10/11 + DirectX 12 対応 GPU だけあればいい。

## 操作

| | |
|---|---|
| WASD | 歩く（Shift で走る） |
| マウス | 視点 |
| E | ドアに触れる → 虚無の候補を狙って もう一度 E で接続 |
| 右クリック | 接続をやめる（ドアから離れても閉じる） |
| **TAB（押しっぱなし）** | **結線ビュー。部屋と接続と残り予算が見える** |
| R | やり直し |
| 1〜8 | 面を直接選ぶ |
| H | 押している間、操作キーを全部出す |
| ESC | マウス解放（エディタの Stop を押したい時） |

## ★2026-09-01(5) — 選択装置を「向き」から「場所」へ変えた

`docs/GATE.md` が契約書。**ここが今のゲームの心臓なので、触る前に必ず読むこと。**

### 何が起きたのか

前の版は「**ドアに入る角度**で行き先が変わる」だった。
床に扇を描き、入射角の針を立て、ドアの中を行き先の色に染めるところまで作った。
**それでも伝わらなかった。**

> 矢印の位置が意味わからない。ADWS押すたびに変わる。矢印の意味が伝わらない。
> 入射角の概念が意味わからん。何をしようとしてるのか。

診断:

1. **矢印が指していたのは「WASD の押し方向」＝入力そのものであって、行き先ではない。**
   一人称のプレイヤーは「ドアの方へ歩く」としか思っていない。その歩きの**微妙な角度**を
   選択装置にしたので、A を押すたびに矢印が飛ぶのが**情報ではなくノイズ**に見える。
2. **一人称では「自分が今どの向きに動いているか」は画面に存在しない量。**
   見えないものを選択装置にした以上、どれだけ丁寧に表示しても
   「表示を読んで理解する」作業にしかならず、体で分かる瞬間が来ない。
3. **現実に比喩が無い。** 入る角度で行き先が変わる扉は存在しない。
   一方「**どのゲートを通ったかで行き先が決まる**」は改札で誰でも知っている。

### 今の機構

**ドアの開口が、行き先の数だけ縦の色帯(band)に割れる。通った帯の色のドアから出る。**

```
      【旧】角度で選ぶ                    【今】通る場所で選ぶ
                                          ┌────┬────┬────┐
        ┌──────────┐                      │ 青 │ 黄 │ 緑 │  ← 開口が帯に割れる
        │   ドア   │                      └────┴────┴────┘
        └────┬─────┘                        │    │    │
         ╱   │   ╲                        ┌─┘    │    └─┐
      青 ╱   │黄  ╲ 緑                    │      │      │  ← 床のレーンが
       ╱     │     ╲                      │      │      │     そのまま帯へ続く
   自分の角度は矢印を                     歩いて入った帯の色の
   見るしかなかった                       ドアから出る
```

- 帯は**開口の高さいっぱい**。遠くからでも「あの扉は3つに割れている」と分かる
- 床のレーンは帯と**同じ幅・同じ色**で、開口からまっすぐ手前へ 3.5m 伸びる。
  **レーンと帯が地続きに見えること**が全て
- 近づくと、**今そのまま歩けばどの帯を通るか**だけが明るくなる（他は 0.35 倍）
- 帯の境目をまたぐと「カチッ」と鳴る
- **`DOORW = 2.0`**（1.5 から広げた）。4 出口でも帯が 0.5m 残る。
  広い開口は「扉」ではなく「**門**」に見えるので、帯で割れている説得力も上がる

判定（**表示と判定は必ずこの 2 つを通す**。片方だけ直すと見えている物と出る場所がズレる）:
```
lat  = ドア平面を横切る瞬間の、ドア中心からの横ずれ（プレイヤーから見た左右）
band = clamp(floor((lat + DOORW/2) / (DOORW/n)) + 1, 1, n)
```
角度の条件は**無い**。残っているのは「ドアへ向かって歩いている」(`dot(move,outward) > 0.3`) だけ。
横から壁ズリしながら滑り込んでも、**通った場所が正**。

「合流するほど的が狭くなる」（GDD 02章）は帯の幅で保たれる:

| 合流枚数 | 出口 | 帯の幅 |
|---|---|---|
| 2 枚 | 1 | 2.00m（割れない） |
| 3 枚 | 2 | 1.00m |
| 4 枚 | 3 | 0.67m |
| 5 枚 | 4 | 0.50m |

### 幾何で教える（第2面）

**ドアの正面に衝立を置き、左右を開けておく。** 真っ直ぐは入れないので、
必ず左右どちらかへ回ることになる ＝ **どちらの帯を通るかを必ず「選ぶ」**。
制限時間は無いので、間違えて元の部屋に戻っても自分で気づいて歩き直せる。

★以前は**仕切りをドアの真正面・中心線上**に立てていた。左右から入らせるつもりが
**真ん中しか通れない形**になり、しかも真ん中は 2 つの帯のちょうど境目だった
（「2面から動けない」の正体）。**塞ぐのは中央、開けるのは左右。**

### 第1面は前提を渡す面

**東の窓越しに出口の部屋が見えているのに歩いては行けず、北のドアをくぐるとそこに出る。**
「ドアの向きと行き先は関係ない」を最初に無言で渡す。これが無いと以降の話が宙に浮く。

## ★2026-09-01(4) — 「条件が分からない」を直した（この版から生きている物）

診断と方針の全文は `docs/REDESIGN.md`、8 面の設計は `docs/LEVELS.md`。

**A. 結線ビュー（TAB）** — 文字のないノードグラフ。部屋 = 四角（今いる部屋だけ塗り、
出口は緑枠）、接続 = ドア色の点線、残り予算 = 下に並ぶピン。レイアウトは部屋の
ワールド XZ を正規化するだけで、別のレイアウト表を持たない。
★グラフの外接矩形だけに薄い暗幕を敷いてある。**これが無いと白い部屋の前で読めない。**
★**このゲームはグラフパズルなのに、それまでグラフが一度も見えなかった。**

**B. 接続ピン** — 繋いだ瞬間ピンがドア枠に刺さり、以後そこに残る。
予算を使ったことが画面の隅の消灯ではなく**世界の変化**として残る。

**C.「繋がった」瞬間の演出**（2.2秒。任意のキーで飛ばせる）— ピンが光るだけでは
**「部屋を選んで終わり」**にしか見えなかった。繋ぐ行為が世界に何をしたのかを見せる:
1. **光の糸**（0.4s）… `fx:beam` が虚無の中を繋いだ先のドアへ伸びる
2. **繋いだ先の部屋を一瞬見せる**（0.8s）… 同じ部屋へは 1 回だけ
3. **結線ビューが自動で開く**（1.0s）… 新しい線が引かれるアニメーションを見せて閉じる。
   ★**接続＝グラフに辺が 1 本増えること**を、自分で TAB を押す前に見せてしまう

**D. レベルデザイン** — 部屋の形を 4 種類にした。

**E. 音** — `source/gen_sfx.py` が numpy で合成（外部素材なし）。触れる / 開く / カチッ /
接続 / ピン / 拒否 / 通過 / クリア / 失敗 / 蛍光灯のハム。

## 段階チュートリアル（キーは「まだ覚えていない操作」だけ出る）

一度に出るキーは多くても 1〜2 個で、規定回数やったら二度と出ない。
覚えた回数は `saveNum`（メモリのみ）なので**面をまたいで持ち越し、アプリを閉じると忘れる**。
20 秒何も操作していない人には、覚えた事でも 1 回だけ出し直す（詰まり救済）。
`H` を押している間はいつでも全部出る。

| 段 | 出るキー | 出る条件 |
|---|---|---|
| ⓪ | `W A S D` | 面が始まった直後（1.2 秒歩いたら消える） |
| ① | `E` | 繋げるドアの射程内（2 回触れたら消える） |
| ② | `E` | 虚無で候補に照準が合った（2 回繋いだら） |
| ③ | `TAB` | **初めて接続が成立した瞬間に 1 回だけ** |

常設なのは**照準の輪**（触れるドアが射程に入ると点のまわりに輪が開く）。

★**`Q`（接続をやめる）は廃止した。** 専用キーを覚えさせる価値が無い。
ドアから離れれば閉じるし、右クリックでも閉じる。

## 実装メモ（次に触る人向け。ここは全部、実際に踏んだ罠）

### 生成物の正

- **シーンは `source/gen_stages.py` が唯一の正。** エディタで手で足した物は次の実行で消える。
  Lua 側のステージ表も**このスクリプトが `Junction.lua` の `-- >>>STAGES` 〜 `-- <<<STAGES`
  に差し込む**（エンジンの Lua に `require`/`dofile` が無いので別ファイルに切り出せない）。
- 内装は `source/blender_kit.py` を BlenderMCP で叩いて作る glTF キット。
  テクスチャは `source/gen_textures.py`。音は `source/gen_sfx.py`。
- python は **Blender 同梱のもの**（numpy が要る）:
  `"C:/Program Files/Blender Foundation/Blender 5.x/5.x/python/bin/python.exe"`
- ★`DOORW` は `gen_stages.py` と `Junction.lua` と `blender_kit.py` の**3 箇所にある**。
  片方だけ変えると「見た目は開いているのに見えない壁がある」になる。

### 罠

- ★**シーン読み込み時に参照されていないモデルは、`scene:spawn` しても絵が出ない。**
  entity は valid、MeshRenderer も付き、AABB も正しく、Lua はエラーを出さない。**ただ描画されない。**
  `dx12_reload_assets` を撃つと一斉に出る＝ GPU アップロードがシーン読み込み時にしか走らない。
  → `band` / `lane` / `pin` は各シーンの `[System]/Preload` に **y=-200 のダミー**を置いてある。
  **消すと帯もレーンもピンも無言で出なくなる。**
- ★**エンジンはテクスチャを「パス」をキーに、プロセス起動から一生キャッシュする。
  しかも【読めなかったという結果も同じようにキャッシュする】。**
  まだ存在しない PNG を一度でも参照したエディタは、あとからファイルを置いても
  **真っ黒を返し続ける**。`scene:setColor` は乗算なので、黒に何を掛けても黒 →
  「モデルのアルベドが壊れている」ようにしか見えず、モデル側を延々疑うことになる。
  → **`dx12_reload_assets{force:true}` を撃つ**（またはエディタ再起動）。
  ★切り分けの決定打は「**同じバイト列を別名でコピーして参照する**」。
  それで直るなら中身ではなくパスのキャッシュが原因。
- ★**Blender のエクスポータが `tex/*.png` を再エンコードして上書きする。**
  `assets/models` へ直接書き出すと `gen_textures.py` が描いた PNG が Blender の再圧縮版に化ける。
  一旦 temp へ出して `.gltf`/`.bin` だけ持ち帰ること。
- ★**OnStart で `task.spawn` してはいけない。** OnPlayStart の後に走るタスク機構のクリアで
  黙って消える（開幕カメラが出なかった原因）。`pendingIntro` を立てて次の `OnUpdate` で仕掛ける。
- ★**`camera:project` は「:」で呼ぶ。** 「.」だと `expected userdata` で `OnUpdate` ごと落ちる。
- ★**`scene:findEntity` は見つからなくても nil ではない。** 必ず `e:isValid()` で確かめる。
- **ホットリロードで `self` が作り直される。** `scene:spawn` する物は必ず名前で探してから作る
  （前回これを忘れて `Needle` が何本も積み上がった）。
- 演出中の位置は `physics:setPosition` で毎フレーム押し込む
  （スクリプトは物理より前に走るので transform に書くだけでは CharacterController に上書きされる）。
- **通過は `loadNum("moving")>0.5` を必須にする** + 接続後 0.5 秒の猶予。
  これが無いと、ドアに張り付いたまま接続した瞬間に吸い込まれる。
- **虚無の候補が白飛びするのは彩度ではなく光量。** `VoidLight` を上げすぎると
  候補の板だけが逆二乗で焼かれ、ブルームで白い霞がかかる。背景の白は白のまま光量を落とす。
- ★**HUD は即時モード（`ui:text`/`ui:rect` = ImGui 経由）で、`dx12_screenshot*` に写らない。**
  HUD を見るには `docs/shot.ps1`（PrintWindow で窓ごと撮る。手前に別のアプリの窓があっても平気）。
- **ポータル描画はしていない。** ドアの向こうは常に白板で塞がっていて、近づいたフレームに
  テレポートする（+0.2 秒の白フェード）。
- MCP から Play を駆動するとマウスキャプチャで視点が暴走する。
  `input:setMouseCapture(false)` + `saveNum("tpYaw"/"tpPitch"/"tpSeq")` で向きを直接置く。
- `dx12_key_press{key:"3"}` は VK 3 になる。数字キーは 51/52 のように VK 整数で送る。
- ★**`build/game/` を作り直し忘れると、clone した人は古い版を遊ぶ。**
  アセットを触ったら MCP の `dx12_build_game`（＝ツールバーの「ビルド」）を撃ってからコミットする。
