# JUNCTION / 継ぎ目

白い虚無しかない建物で、ドアとドアを繋ぎ直す一人称パズル。GDD v1 の実装。

> 検証したい 1 点: **「同じドアに違う角度で入ると、違う場所に出る」は気持ちいいか。**

## すぐ遊ぶ（エンジン不要・Windows）

```
cd Junction/build/game
Game.exe
```

`build/game/` はビルド済みでリポジトリに入れてある（起動シーンは第1面）。
Windows 10/11 + DirectX 12 対応 GPU だけあればいい。

## 操作

| | |

## ★このゲームは文字でルールを説明しない（2026-09-01 の作り直し）

「説明文が多すぎる／ステージが単調」という指摘を受けて、**画面に出る文字を操作キーだけ**にした。
以前あった「今やること」の 1 行・下段の解説パネル・[H] のルール全文は**全部消してある**。
代わりにルールはこの 4 つで教える。

1. **開幕のカメラワーク** — 面が始まると、まず**出口の部屋（緑の光柱）**を見せてから、
   開始の部屋へ切り替わって**触れるべきドア**へ寄る。「どこへ行けばいいか」を文字なしで渡す。
2. **ドア固有色** — ドアごとに色があり、枠 / 虚無に浮かぶ候補 / 床の助走レーン / レーンの先の柱が
   全部その色。**青い柱の側から助走してドアに入れば、青いドアから出る。**
3. **角度の授業（第2面）** — 3枚合流ができた瞬間だけカメラが奪われ、ドアの真上から扇を見下ろし、
   色レーンを 1 本ずつ舐めて「左のレーン＝青、右のレーン＝黄」を見せる。ここも文字ゼロ。
4. **案内の光（Pilot）** — 第1・2面だけ、次に触る物の上を小さな光が漂う。

クリア／失敗も文字を出さない。**クリア＝白へ抜けて次の面へ自動で進む**、
**失敗＝建物が白に還ってやり直し**（GDD の「白に還る」そのまま）。
残り時間は数字ではなく画面上部の細い帯で、残り 30 秒で照明が落ちて焦らせる。

## ステージ（8面。1面につき新しい事を 1 つだけ足す）

| | 面 | 教える事 | ドア | 予算 | 時間 |
|---|---|---|---|---|---|
| 1 | 触れる | 触れる・選ぶ・通る。候補 1 枚で失敗しようがない | 2 | 1 | なし |
| 2 | 合流 | 3枚合流と角度。左右のレーンで行き先が変わる（授業カメラ） | 3 | 3 | なし |
| 3 | 予算 | 制限時間の導入 | 3 | 3 | 3:00 |
| 4 | 二つの出口 | GDD で開示した面。ドア c は触ると予算を失って詰む | 4 | 2 | 3:00 |
| 5 | 遠近の罠 | 虚無の見かけの大きさ＝実距離。遠い出口が小さく見える | 5 | 3 | 3:00 |
| 6 | 四枚合流 | 40°スライス。助走の設計が要る | 5 | 4 | 3:00 |
| 7 | 精密射撃 | 2枚ドアの中継室。5枚合流＝30° | 7 | 4 | 3:00 |
| 8 | 一棟 | ドア 8 枚・予算 3。合流点の崩壊（6枚目）が初めて起こり得る | 8 | 3 | 3:00 |

## 見た目（2026-09-01 に作り直した）

内装は `source/blender_kit.py` を BlenderMCP で叩いて作った glTF キット。

- `source/gen_textures.py` … 壁紙／絨毯／落とし天井／塗装／金属／コンクリを numpy で描いて PNG 直書き
  （1024px・2m で 1 タイル＝512 texel/m）。**エンジンは glTF の `baseColorFactor` を読まない**ので、
  白い壁ですら col テクスチャが要る。
- `source/blender_kit.py` … 床 / 天井 / 壁 / 開口付きの壁 / 埋込照明 / 通気口 / 角柱 / 長椅子。
  Blender の **-Y がエンジンの +Z**。壁は法線 -Y で作ってある。
- 当たり判定は今まで通り**色付きの箱**が持ち、その 5mm 手前に内装モデルを置いて箱を隠している。
  モデル側に `rigidBody` を付けない＝物理に載らない。
- 照明は 1 部屋 4 灯（2x2）。**2 灯だと 12m 角の隅まで届かず天井が灰色に沈んでリミナルに見えない。**
  強度 8.0。一部の蛍光灯は `Flicker(light,"broken"/"fluorescent")` で明滅させている。

## 実装メモ（次に触る人向け）

- **シーンは `source/gen_stages.py` が唯一の正。** エディタで手で足した物は次の実行で消える。
  Lua 側のステージ表も**このスクリプトが `Junction.lua` の `-- >>>STAGES` 〜 `-- <<<STAGES` に差し込む**
  （エンジンの Lua に `require`/`dofile` が無いので別ファイルに切り出せない）。手で編集しないこと。
- 実行する python は **Blender 同梱のもの**（numpy が要る）:
  `"C:/Program Files/Blender Foundation/Blender 5.1/5.1/python/bin/python.exe" gen_stages.py`
- **ポータル描画はしていない。** ドアの向こうは常に白板で塞がっていて、近づいたフレームに
  テレポートする（+0.2 秒の白フェード）。
- **角度は WASD の押し方向で測る。** カメラの向きでも実速度でもない。出所は `FreeLook.lua` の
  `saveNum("moveX"/"moveZ")` 1 箇所。
- **カメラ演出は `task.spawn` + `wait` のコルーチン。** 演出中は `saveNum("cineLock",1)` で
  FreeLook の入力を殺し、位置は `physics:setPosition` で毎フレーム押し込む
  （スクリプトは物理より前に走るので transform に書くだけでは CharacterController に上書きされる）。
  ★**OnStart で `task.spawn` してはいけない**。OnPlayStart の後に走るタスク機構のクリアで
  黙って消える（開幕カメラが出なかった原因）。`pendingIntro` を立てて次の `OnUpdate` で仕掛ける。
- **`camera:project` は「:」で呼ぶ。** 「.」だと第1引数が数値になって
  `expected userdata` で `OnUpdate` ごと落ちる。
- **白い虚無の上では淡い色が全部同じに見える**（橙と黄が判別不能だった）。候補は `vivid()` で
  無彩色ぶんを抜いてから塗る。教える第2面は最も遠い 2 色（青・黄）を使っている。
- エンティティ名の規約（`gen_stages.py` と `Junction.lua` が対）:
  `Door_<id>` / `Void_<id>` / `VoidLight_<id>` / `Frame_<id>_*` / `Mark_<id>_1..5` /
  `Slice_<id>_1..6` / `Lane_<id>_1..5` / `Post_<id>_1..5` / `Proxy_1..8` / `Pilot`。
  片方だけ変えると無言で壊れる。
- HUD は即時モード（`ui:text` / `ui:rect` = ImGui 経由）で、**MCP の `dx12_screenshot*` には写らない**。
  HUD の確認は PrintWindow でウィンドウごと撮るしかない。
  出している文字は ASCII の操作キーだけなので、日本語グリフの豆腐問題はもう起きない。
