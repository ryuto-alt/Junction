# JUNCTION / 継ぎ目 — 最小プロトタイプ

GDD v1 の **09 章「最小プロトタイプ」** を dx12 エンジンで動くところまで作ったもの。
検証したいのは 1 点だけ:

> **「同じドアに違う角度で入ると、違う場所に出る」は気持ちいいか。**

## すぐ遊ぶ（エンジン不要・Windows）

```
git clone <このリポジトリ>
cd Junction/build/game
Game.exe
```

ビルド済みの `build/game/` を**リポジトリに含めてある**ので、clone してそのまま起動できる。
必要なのは Windows 10/11 + DirectX 12 対応 GPU だけ（Visual Studio もエンジンも要らない）。

## エディタで開く（改造する人向け）

dx12 エンジンのエディタで `Junction.dx12proj` を開いて Play（既定シーンは `scenes/stage3.json`）。
`assets/` と `source/` を直したら、エディタのビルドで `build/game/` を作り直してからコミットすること。

| 操作 | |
|---|---|
| WASD / 左スティック | 歩く |
| Shift / RB / 左スティック押し込み | ダッシュ |
| Space / A | ジャンプ |
| マウス / 右スティック | 視点 |
| E / X | インタラクト（ドアに触れる / 開ける / 拾う等を統一） |

## ステージ

- **第3面「合流」** — 部屋 S / A / G、ドア 3 枚、予算 3（1 本余る）。
  3 枚合流を作って、入る角度で A（行き止まり）と G（出口）を撃ち分ける。
- **第4面「二つの出口」** — GDD で開示した面そのまま。部屋 S / P / Q / G、ドア 4 枚、予算 2。
  正解は `a-b` → `a-d` の 3 枚合流を作り、**部屋 S の右寄りから助走して a に入る**。
  ドア `c` に触れると予算を 1 本失い、その瞬間に孤立して詰む。

## 実装メモ（次に触る人向け）

- **ポータル描画はしていない。** ドアの向こうは常に白板（`Void_<id>`）で塞がっていて、
  近づいたフレームにテレポートする（+0.2 秒の白フェード）。
  ステンシル再帰を書く前に「角度で行き先が変わる快感」だけを測るための構成。
  ここが鈍いなら描画を足しても救えない、というのが GDD 09 章の主張。
- **角度は WASD の押し方向で測る。** カメラの向きでも実速度でもない。
  カメラの向きだと歩きながら見回すだけで行き先が変わり、実速度だとドア際の
  壁ズリで意図と違う向きになる。出所は `FreeLook.lua` の `saveNum("moveX"/"moveZ")` 1 箇所。
- **シーンは `source/gen_stages.py` が唯一の正。** エディタで手で足した物は次の実行で消える。
- エンティティ名の規約（`gen_stages.py` と `Junction.lua` が対）:
  `Door_<id>` / `Void_<id>` / `VoidLight_<id>` / `Mark_<id>_1..5` / `Slice_<id>_1..6` / `Proxy_1..8`。
  片方だけ変えると無言で壊れる。
- HUD は即時モード（`ui:text` / `ui:rect` = ImGui 経由）。
  **MCP の `dx12_screenshot*` には写らない**ので、HUD の確認は実機の画面で見るしかない。

## 次にやること

1. まず遊んで、**角度で撃ち分ける瞬間が気持ちいいか**だけを判断する。
2. 気持ちよければ: 4〜5 枚合流（40°/30°）の面を足して、狭いスライスの精密さを測る。
   ドアを 6 枚以上にすれば合流点の崩壊も初めて発火する。
3. その次に、白の侵食とスコアを載せる。ポータル描画はいちばん最後でいい。
