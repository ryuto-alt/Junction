# JUNCTION — 8 面のレベルデザイン（2026-09-01(4) 作り直し）

`docs/REDESIGN.md` の D 節の具体化。**`source/gen_stages.py` はこの通りに書き直す。**

## 直そうとしている事

今の 8 面は**全部 12m 角の同じ箱・同じ湧き位置 (0,-3.5)・同じ北壁のドア・同じ開幕カメラ**で、
「1 面につき新しい事を 1 つ足す」つもりが**画面が同じなので新しく見えない**。
さらに、このゲームの核である「**入る角度で行き先が変わる**」を、
プレイヤーが**自分の意思で試す前に**理解する手段がどこにも無い。

この 2 つを、**部屋の形**と**部屋の中に立っている物**で直す。

## 0. 部屋の形（`gen_stages.py` の `room()` を寸法パラメータ化する）

今 `HALF = 6.0` が定数で埋まっている。これを部屋ごとの引数にする。

| 形 | 内寸 (X x Z) | 天井 | 性格 |
|---|---|---|---|
| `box12` | 12 x 12 | 4.0 | 標準。既存 |
| `hall20` | 20 x 20 | 7.0 | 吹き抜け。**合流点を置く主室**。カメラが引ける |
| `corr18` | 18 x 8 | 3.2 | 廊下。**助走が一直線に強制される** |
| `cell8` | 8 x 8 | 3.0 | 小部屋。**行き止まりと罠**。狭さで「ここは違う」と分からせる |

★**行き止まりの部屋を物理的に狭くする**のは、このゲームで一番効く無言の説明。
「間違えた」を文字ではなく**天井の低さと壁の近さ**で伝える。

照明は部屋の広さに応じて数を変える（box12 = 2x2、hall20 = 3x3、corr18 = 3x1、cell8 = 1）。
2 灯だと 12m 角の隅まで届かず天井が灰色に沈んでリミナルに見えないので、**減らしすぎない**。

## 1. 「ドアは、見た目の先ではなく繋いだ先に出る」

**このゲームの前提を、最初の 30 秒で、文字ゼロで渡す面。**

- `S` box12 @ (0, 0)。**北壁にドア `a`**。**東壁は窓**（`models/wall_window.gltf`）
- `G` box12 @ (12.6, 0)。**西壁は窓**（S の東窓と向かい合う）。北壁にドア `g`。出口の光柱は (12.6, 2.6)
- 予算 1 / 制限時間なし / 候補は `g` の 1 枚だけ = **失敗しようがない**

**体験の順番**:
1. 湧いた瞬間、**東の窓の向こうに出口の緑の光柱が見えている**。行きたい場所が最初から見えている
2. 窓には腰高の壁があって**歩いては行けない**（窓の下端 y=1.0）
3. 部屋にあるドアは北壁の `a` だけ。触ると虚無が開き、候補は 1 枚。繋ぐ
4. **北の**ドアをくぐると、**東に見えていたあの部屋に出る**
5. 出た先で振り返ると、窓の向こうにさっきまで居た部屋が見える

★ここで渡している命題は「**ドアの向きと行き先は関係ない**」。
これが分かっていないと、以降の角度の話が全部宙に浮く。前作にはこの一手が無かった。

**カメラ**（2 手。どちらも部屋 S の内側、遮る物なし）:
```
("S", (-3.0, 1.9, -2.0), "G", (0.0, 1.6, 0.0), 2.4)   # 窓越しに出口を見る。ゆっくり寄る
("S", ( 0.0, 1.7, -3.5), "S", (0.0, 1.5,  6.0), 1.6)   # 振り向いて、北壁のドアへ
```

## 2. 「入る側で行き先が変わる」— **幾何で強制する**

**カメラの授業は廃止。** 代わりに、**間違えようがない状態で結果だけ先に見せる。**

- `S` box12 @ (0,0)。北壁にドア `a`
- `A` box12 @ (0, 52)。南壁にドア `d`。★**この部屋の床に仕切りが立っている**
- `G` box12 @ (52, 52)。南壁にドア `g`。出口の光柱
- 予算 3（余る）/ 制限時間なし

**仕切り** `models/divider.gltf`（腰高 1.15m）を、部屋 A の中に **x=0 / z=-1.0 〜 +5.0** に立てる
（＝ドア `d` の手前 6m を左右に割る。北端はドアの 1.15m 手前で止める）。
南側は開いているので**回り込める**が、**ドア `d` へは左の通路か右の通路からしか入れない**。

**体験の順番**:
1. S でドア `a` を繋ぐ（候補は `d` と `g`。どちらでもよい）→ 通る
2. 着いた部屋 A で、ドア `d` からもう 1 枚を繋ぐ → **合流点が 3 枚**になり、床に扇が出る
3. ドア `d` の出口は 2 つ。**左の通路から入れば片方、右の通路から入れば片方**
4. たぶん最初は**さっき居た部屋 S に戻ってしまう**。見覚えのある部屋に出るので、間違いだと分かる
5. 歩いて戻り、**今度は反対側の通路から**入る → 出口の部屋に出る

★**失敗が安全で、しかも自分の間違いが自分で分かる**のが要点。制限時間を入れないのはこのため。
★仕切りがあるおかげで「なんとなく真ん中から入って、なんとなく出た」が起こらない。
**選んだという自覚**が必ず残る。

**カメラ**（部屋 A を先に見せて仕切りを予告する。ただし答えは見せない）:
```
("A", ( 0.0, 5.2, -7.0), "A", (0.0, 0.6,  3.0), 2.2)   # 仕切りを俯瞰。左右に割れているのが分かる
("S", ( 0.0, 1.7, -3.5), "S", (0.0, 1.5,  6.0), 1.4)   # 開始の部屋。ドアへ
```

## 3. 「今度は自分で助走を決める」＋ 制限時間

第2面と同じ形の問題を、**仕切り無し・広い部屋**で出す。手すりも案内も無い。

- `S` **corr18** @ (0,0)。**西の短辺**にドア `a`（廊下の端）
- `A` **hall20** @ (0, 60)。南壁にドア `d`。**天井 7m の吹き抜け**。仕切りは無い
- `G` box12 @ (60, 60)。南壁にドア `g`
- 予算 3 / **制限時間 3:00（ここで初めて時計が入る）**

★corr18 の廊下から始めることで、**まず「まっすぐ歩く」しかない空間**を通ってから、
急に 20m 角の吹き抜けに出る。**選択肢が増えた事を、部屋の広さで感じさせる。**

## 4. GDD 第4面 —「全部繋ぎたくなる誘惑が罠になる」

GDD 03 章で開示した面。**行き止まりを狭い部屋にする**ことで、間違いを体で分からせる。

- `S` box12 @ (0,0) — ドア `a`
- `P` **cell8** @ (0,52) — ドア `b`。**天井 3m の物置**。行き止まり
- `Q` **cell8** @ (52,0) — ドア `c`。**触ると予算を失って詰む罠**
- `G` **hall20** @ (52,52) — ドア `d`。出口
- 予算 2 / ドア 4 / 3:00 / 照明は**電球色で暗め**（`lightcol=(1.0,0.90,0.72)`, `intensity=6.0`）

解は GDD のとおり: `a`-`b` → `a`-`d` で 3 枚合流。`c` には一度も触らない。

★`P` と `Q` を cell8 にしたのは、**間違って出た瞬間に「狭い」で分かる**ため。
`G` を hall20 にしたのは、**正解に出た瞬間に「開けた」で分かる**ため。
広さそのものが正誤のフィードバックになっている。

**カメラ**（選択肢を 3 つ並べて見せる。速い刻み）:
```
("P", (0.0, 2.2, -2.6), "P", (0.0, 1.2, 1.0), 0.9)   # 狭い物置
("Q", (0.0, 2.2, -2.6), "Q", (0.0, 1.2, 1.0), 0.9)   # 狭い物置
("G", (0.0, 4.0, -8.0), "G", (0.0, 1.4, 2.6), 1.6)   # 広い。緑の光柱
("S", (0.0, 1.7, -3.5), "S", (0.0, 1.5, 6.0), 1.4)
```

## 5. 「遠くの物は小さく見える」— 遠近の錯覚

虚無に浮かぶ候補の**見かけの大きさは実距離で決まる**。これを問題にする。

- `S` **corr18** @ (0,0) — ドア `a`
- `P` **corr18** @ (0,60) — ドア `b`
- `Q` **cell8** @ (60,60) — ドア `c`
- `R` box12 @ (60,0) — ドア `d`
- `G` **hall20** @ (208,156) — ドア `g`。**ずっと遠く**

★近い `d` と、ずっと遠い `g` が**虚無の中で同じくらいの見かけ**になるよう距離を調整する。
「小さい＝遠い＝たぶん出口」に気づけるかの面。

## カメラの掟（`docs/REDESIGN.md` D-4 と対）

`gen_stages.py` の各ステージに `cine` を**手で書く**。座標は**部屋ローカル**で書き、
生成側がワールドへ直す。**絶対座標を手書きしない。**

```python
cine=[  # (居る部屋, 目のローカル位置, 見る部屋, 見る点のローカル位置, 秒)
    ("S", (-3.0, 1.9, -2.0), "G", (0.0, 1.6, 0.0), 2.4),
]
```

生成側で **assert** すること:
1. 目の位置が、その部屋の内側に **1.2m 以上の余裕**を持って入っている（壁に刺さらない）
2. 目の y が **0.8 以上・天井 -0.5 以下**
3. 目と注視点を結ぶ線分の近くに、その部屋の什器（柱・ロッカー・仕切り）が**無い**
   （XZ 距離 0.9m 以内に什器の中心があったら assert で落とす）

★**刺さるカメラをコミットできないようにする**のが目的。目で見て気づくのでは遅い。

Lua 側は毎フレーム `physics:raycast` で目→注視点を確認し、遮られていたら上へ最大 +2.5m 逃がす
（二重の保険。生成側の assert が一次、raycast が二次）。

**8 面で同じ絵を作らない。** 第1面=窓越しの寄り / 第2面=俯瞰 / 第3面=吹き抜けの降下 /
第4面=速い刻み / 第5面=廊下の押し込み / 第6面=回り込み / 第7面=あおり / 第8面=引き。
