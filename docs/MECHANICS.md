### 1.3 遊びの手順が 24 回とも同じ

判定はどの継ぎ目も `liminal_runtime.lua` の同じ 1 本のゲートを通る:

```
焦点から 7m 以内 (FOCUS_LOCK)
  かつ 速さ 1.10 m/s 以下 (STILL)      ← 止まる
  かつ 視野 26 度以内に中心 (CONE)      ← 見る
  かつ 角度差 < lock                    ← 合っている
  かつ 0.36 秒 保つ (DWELL)             ← 待つ
```

**「近づく → 止まる → 見る → 待つ」を 24 回繰り返す。** 規則が 12 種あっても、
手はこの 1 種類しかない。押すボタンが無いのは正しい判断だが、
**歩く以外の入力が無いのに、歩くことが誤差の調整にしか使われていない**のが問題。
前後に歩いても角度差が少し変わるだけで、**世界の側は何も起きない**。

### 1.4 ★ランタイムに「使われていない規則」が 6 つ眠っている

`Conn.__init__` と `liminal_runtime.lua` の両方に実装があるのに、
**どの継ぎ目からも呼ばれていない**もの（`grep -c` で確認。定義と `data()` の 2 か所だけ）:

| 規則 | 状態 | 場所 |
|---|---|---|
| `sweep=` **なぞる** | 定義済み・未使用 | `SWEEP_CONE`（runtime:65） |
| `trail=` **踏んでなぞる** | 実装済み・未使用（V15 で「錯覚を使っていない」と却下） | runtime:1876-1890 |
| `relay=` **送り（二度見）** | 実装済み・未使用 | runtime:1816-1874 |
| `touch=` **触れる（2 点を画面で重ねる）** | 実装済み・未使用 | runtime:1275-1278 |
| `anti=` **負の継ぎ目（解くと塞がる）** | 実装済み・未使用 | runtime:1240 |

ランタイムを 1 行も書かずに新しい継ぎ目が作れる。これは後の提案 F / G で使う。

### 1.5 まとめ — 何を足すべきか

足りないのは「規則の種類」ではない。**動詞が 1 つしかない**こと。
足すべきは、次のどれかを変える動詞:

1. **見る道具を変える**（枠越し・自分の影・体の大きさ）
2. **世界の側を動かす**（押す・乗る）
3. **取り返しのつかない選択をする**（多義・負）

## 2. 参照作品を分解する

### 2.1 Viewfinder（2023, Sad Owl Studios）

**動詞**: 拾う / 構える / 前後に歩く / **貼る** / 回す / 巻き戻す / 複製する / 撮る

**中核の正体**: 写真は 2D の絵ではない。**視錐台（frustum）の近平面**である。
撮影は「そのカメラの視錐台に入っていた 3D ジオメトリを複製し、錐台の外を切り落とす」。
貼るときは「今のプレイヤーの視錐台に、その中身を移植し、世界側のメッシュを
同じ錐台の形にくり抜く」（開発者 Matt Stark 本人の説明。80.lv）。

**何を変えるか**: 位置・大きさ・形・存在の全部。
**大きさの規則が肝**: 錐台はピラミッドなので、**近くに貼れば小さく、遠くに貼れば大きくなる**。
だから**前後に歩くことがそのままパズルになる**。JUNCTION に一番欠けているのがこれ。

**なぜ気持ちいいか**: 「空の写真を壁に貼ると、壁が抜けて通れる」。
中身が無い錐台＝空洞、という**幾何の帰結が直感を裏切る**。
自分で気づいた感じが残るのは、答えが「知識」ではなく「幾何」だから。

**破綻しやすい所**: (a) メッシュのリアルタイム切断が最大の技術負荷、
(b) 自分がジオメトリに埋まる（巻き戻しで救済）、
(c) 終盤の**制限時間チャレンジ**が「失敗を罰しない」という設計思想と矛盾して酷評された、
(d) 「1 枚撮るだけで解ける部屋が 5 連続」する中だるみ。

**チュートリアルの順**: ①置いてあるポラロイド → ②コピー機（複製） → ③自分のカメラ。
Stark は「カメラを最初から渡すとプレイヤーは圧倒される」と明言している。

**JUNCTION が借りるべき芯**: 写真ではなく、**「枠が世界を切り取る」の 1 点だけ**。
撮影も切断も要らない。→ 提案 **B「枠に収める」**。

### 2.2 Superliminal（2019, Pillow Castle）

**動詞**: 掴む / 見る向きを変える / **離す**

**中核の正体**: 掴んでいる間、**画面上の見かけの大きさ（視角）が一定に保たれる**。
毎フレーム、物体の頂点群へレイを飛ばし、当たった距離 d から
`scale = scale0 * (d / d0)` を計算して置き直す。**離した瞬間に確定**して剛体になる。
質量・落下音・床の揺れまで scale に連動している（PlayStation Blog の技術解説）。

**何を変えるか**: 大きさ。ただし本当に変えているのは
**「大きさは絶対量である」というプレイヤーの思い込み**。

**バリエーション**（1 つの動詞では持たないので章ごとに足している）:
だまし絵（ある一点から見ると 2D の落書きが立体になる ← **JUNCTION の既存機構そのもの**）/
影が実体になる / 出口の看板が嘘をつく迷宮 / 複製（Clone）/ 暗闇の懐中電灯 /
入れ子のドールハウス / 自己言及の扉。

**破綻しやすい所**: (a) 離すタイミングのブレで狙いと違う大きさになる
→ **クランバー（よじ登り）を後から足して成否を即座に返す**ようにした、
(b) 巨大化した物にカメラが埋まる / ボイドに落ちて異常巨大化
→ **中心から一定距離超で強制削除**というフェイルセーフ、
(c) 批評の一致点は「**Clone 章あたりでアイデアが枯れる**。結局どれも
『変な角度から見て大きくする』に帰着する」。

**原型 Museum of Simulation Technology（2013, CMU ETC）**: 2 週間の課題。
Albert Shih 本人が「満足のいくパズルは実質 1 つ、残りは水増し」と言っている。
**原型はメカニクスが多かったのではなく、逆に 1 つしかなかった。**
章ごとの多様さは商業化の過程で足したもの。

**JUNCTION が借りるべき芯**: 掴む操作ではなく、
**「自分の目の高さが変われば、同じ部屋が別の部屋になる」**。→ 提案 **A「くぐって縮む」**。

### 案 A ★★★「くぐって縮む」— 体の大きさが解の一部になる

**1 行**: 天井が下がっていく廊下を抜けると、体が半分になる。
目の高さ・歩幅・歩く速さ・跳べる高さが同時に変わり、**同じ部屋が別の部屋になる**。

**元ネタ**: Superliminal（大きさは相対的でしかない）/ `docs/SCALE.md` の既存資産。

**なぜ動詞が違うのか（ここが一番大事）**

今の焦点 F は `(x, EYE, z)` で、**y は 24 本すべて 1.70 固定**である
（`gen_liminal.py:89` `EYE = 1.70`。「継ぎ目の焦点はすべて y=EYE」と冒頭に書いてある）。
体が 0.5 倍になると目は **0.85m**。
つまり **焦点の 3 番目の座標が、初めて選択肢になる。**

- 同じ床・同じ破片で、**1.0 の体ではどこに立っても合わず、0.5 の体でだけ合う**継ぎ目が作れる
- 「立ち位置を探す」が 2 次元（床の上）から 3 次元（床 × 大きさ）になる
- `Conn(min_y=, max_y=)` は**既にある**（継ぎ目 7,8,12,13,14,16,24,25 が使用中）。
  規則を 1 つも増やさずに「その大きさでしか通らない窓」が書ける

**★制約との相性が良い**: ユーザーの掟「人間の尺度。天井 4m 前後。巨大な空間は作らない」に対し、
**縮む方向だけ使えば矛盾しない**。むしろ、
**天井 2m の小さい部屋を建てて、0.5 の体で入れば天井 4m の部屋に見える**。
巨大空間を作らずに巨大空間の感覚が手に入る。**大きくなる方向（2.0 = 身長 3.6m）は使わないこと。**

**実装（API 名で）**

1. **体**: `physics:addCharacterController` は実行時に寸法を変えられない
   （`ScriptEngine.cpp:2341` `if (reg.all_of<CharacterController>(...)) return;`）。
   → `gen_liminal.py:2762` の `p["characterController"]` を、
   `Body_0`(0.25) / `Body_1`(0.5) / `Body_2`(1.0) の **3 体**に増やす
   （`radius=0.34*s, halfHeight=0.56*s`）。使わない体は y=-200 に沈める。
   `FreeLook.lua` の `SCALES` / `body()` がそのまま雛形になる。
2. **目の高さ**: `liminal_runtime.lua:33` の `EYE_OFF = 0.80` を `0.80 * s` にするだけ。
   （体の中心 0.90*s − 体の半分 0.90*s + 目 1.70*s = 中心 + 0.80*s）**1 行**。
3. **歩く速さ**: `SPEED * s^0.6`。`FreeLook.lua:speedOf()` の実測済みの式。
   0.5 倍で 2.5m/s、0.25 倍で 1.65m/s ＝ 遊べる速さが残る。
4. **歩幅**: ヘッドボブの周期を `BOB_FREQ / s^0.5`（同じく FreeLook から）。
5. **足音**: ★`FreeLook.lua` は「大きさで**変えない**（教えてしまう）」と決めている。
   `docs/SCALE.md` は「変える」と書いてある。**矛盾しているので決め直すこと。**
   この作品の芯（合図を出さない）に合うのは FreeLook 側＝**変えない**。
   歩幅（テンポ）だけで伝わる。
6. **切り替え位置**: 廊下の途中に薄い判定板（`hit()`）を置き、目がその面を越えたら体を入れ替える。
   `physics:setPosition(Body_next, ...)` → 前の体を y=-200 へ。
   ★`docs/SCALE.md` の実測: **Play 直後は CC が物理世界に未登録で `physics:setPosition` が黙って効かない。**
   入れ替えのたびに「1 秒間押し込み直す + `y < -50` なら置き直す」保険を入れること。
7. **見えない切り替えにする**: runtime に既にある**変化の見落とし（change blindness）**の仕掛けを流用する
   （`MASK_TURN=55°/s` / `MASK_MOVE=1.20m/s`。視線か体が動いている瞬間に差し替える）。
   扉の敷居をまたぐ瞬間は必ず歩いているので、**まず気づかれない**。

**手間**: **大**。ただし FreeLook.lua に実装が丸ごと残っているので、
書き起こしではなく**移植**。

**芯を壊すか**: 壊さない。文字も数字も出ない。案内は「廊下の天井が下がっていく」という形そのもの。
★ただし**触る範囲がいちばん広い**（落下復帰 `CHECKS` の高さ、跳べる高さ、
`add_walk_colliders(p_height=1.80, p_step=0.32)` の閾値、`calib_marks.py` の測り方）。
だから**実装順は最後**にする（§6）。

### 案 B ★★★「枠に収める」— 窓枠越しに全部が入った時だけ合う

**1 行**: 部屋に立っている空の窓枠越しに見て、**破片の全体が枠の中に収まる**位置に

**元ネタ**: **Viewfinder の中核をそのまま**。写真は視錐台の近平面である、という一点だけを借りる。
撮影もメッシュ切断も要らない。

**なぜ動詞が違うのか**

- 今までは「**点**（焦点）を探す」。枠は**面**なので、探す対象が
  「枠と破片を結ぶ**視錐台**」になる
- **枠に近づくほど広く入り、離れるほど狭くなる。前後に歩くことに初めて意味が出る。**

**実装（新規は Lua 20〜30 行だけ。カメラ行列も射影も要らない）**

生成側は枠の 4 隅を渡すだけ:
```python
c = Conn(30, F, 2.4, 12.0, center, "frame",
         frame=[[x0,y0,z0],[x1,y1,z1],[x2,y2,z2],[x3,y3,z3]])  # 左下→右下→右上→左上
```

判定は「点 P が、目 E と枠の 4 隅が作る錐の内側にあるか」。
**4 つの側面の法線との内積の符号が揃うか**を見るだけ:

```lua
-- fr = 枠の 4 隅（周回順）。E = 目。P = 破片の bbox の 1 点。
local function insideFrame(fr, ex, ey, ez, px, py, pz)
    local s0 = nil
    for i = 1, 4 do
        local a, b = fr[i], fr[i % 4 + 1]
        local ax, ay, az = a[1]-ex, a[2]-ey, a[3]-ez
        local bx, by, bz = b[1]-ex, b[2]-ey, b[3]-ez
        local nx, ny, nz = ay*bz - az*by, az*bx - ax*bz, ax*by - ay*bx  -- 側面の法線
        local d = nx*(px-ex) + ny*(py-ey) + nz*(pz-ez)
        if s0 == nil then s0 = (d >= 0)
        elseif (d >= 0) ~= s0 then return false end
    end
    return true
end
```

- 破片の bbox 8 点（`sh.pts`。**既に焼いてある**）を全部通す。24 回の掛け算 × 8 点 × 破片数。
  毎フレームでも無視できる負荷
- 既存のゲートに **and** で足すだけ（`gateB = gateB and framed`）。
  `c.frame` が nil の継ぎ目には影響ゼロ ＝ **既存 24 本を 1 本も壊さない**
- 枠そのものは `box()` 4 本で作る（当たり判定なし＝ `DECOR_RE` に載せる）

**手間**: **中**（runtime 30 行 + 生成側の枠 + 机上検査 `sim_liminal.field()` に同じ式を足す）

**芯を壊すか**: 壊さない。枠は最初から部屋に立っている物。文字も光も出ない。

**落とし穴**:
- **確定域が消えやすい。** 枠の見込み角が破片の見込み角より小さいと、成立する床が 0 になる。
  生成時に「枠の見込み角 ≧ 破片の見込み角 × 1.3」を **assert する**こと
  （`sim_liminal.py` の `field()` に条件を足せば机上で測れる。目標 **1.5m² 以上**）
- 枠を通り道の真ん中に置くこと。避けて通れるが、**通ろうとして必ず一度は覗く**形にする

### 案 C ★★「押して運ぶ」— 破片の 1 枚を体で押す

**芯を壊すか**: 壊さない。掟「歩ける物は最初から全部歩ける」は守れる

## 5. 「回る」規則（継ぎ目 9・スリット付きの筒）はなぜ厳しいのか

> 「回転するオブジェクト。それさ、まじ判定厳しいから改善と、もうちょいいいやり方ないか」

### 5.1 数字で突き合わせる

読んだ場所:
`gen_liminal.py:1134`（`Conn(9, ...)` の定義）/ `liminal_runtime.lua:481`（`throughSlot()`）/
`liminal_runtime.lua:1875`（呼び出し）/ `gen_liminal.py:LOCKS` / `MARKS` / `calib_marks.py:52`

| 量 | 値 | 出どころ |
|---|---|---|
| 筒の回転速度 | **36 °/秒**（一周 **10.0 秒**） | `slot.speed=36.0` |
| 判定の窓（片側） | **±17°**（全幅 **34°**） | `slot.half=17.0` |
| **窓が開いている時間** | **34 / 36 = 0.944 秒 / 周**（時間の **9.4%**） | 上の 2 つから |
| 確定に要る連続時間 | **0.36 秒** | `DWELL` |
| 許容角 `lock` | **0.9°** | `LOCKS[9]`。**24 本中で最小**（中央値 3.4、次に厳しいのが 2.0） |
| 床の印の大きさ | **0.19 × 0.74 m = 0.141 m²** | `MARKS["C9_mark"]`。**24 本中で最小** |
| 実測の確定域 | **1.39 m²**（7.47 から締めた） | `docs/V15.md` §13 |
| 速さの上限 | 1.10 m/s | `STILL` |
| 視野 | 26° 以内 | `CONE` |

**「窓が開いている時間 < 確定に要る時間」ではない。** 0.944 > 0.36 なので、
原理的には成立する。**厳しさの正体は別のところにある。4 つある。**

---

#### 厳しさ①（本命）— hold が窓を跨げない

判定はこう書いてある（`liminal_runtime.lua:2081-2087`、規則A の既定の枝）:

```lua
if looking and gate and err < c.lock and fdmax < FOCUS_LOCK then
    c.hold = c.hold + dt
    if c.hold >= DWELL then resolve(self, c) end
else
    c.hold = 0.0          -- ★窓が閉じた瞬間にゼロへ戻る
end
```

`gate = gateB and still` で、`gateB` は `throughSlot` が false になった瞬間に false。
つまり **窓が閉じると溜めた時間が全部消える。**
0.36 秒を**一つの窓の中で連続して**成立させるしかない。

余裕は 0.944 − 0.36 = **0.584 秒**しかない。そこへさらに:

- 歩いて来て `STILL`(1.10 m/s) 以下へ落ちるまで、止まりの時定数 45ms・95% まで **136ms**
  （`liminal_runtime.lua:ACCEL_S = 22.0`）
- マウスがわずかに動いて `err` が 0.9° を跨いだら、その瞬間にゼロへ戻る

**実質の余裕は 0.4 秒前後。** 一度でも手が震えたら、次の窓（10 秒後）までやり直し。

#### 厳しさ②（一番効いている）— 探す作業に情報が来ない

これが本当の問題。**破片は筒の中に吊ってある。**
つまり**破片が見えるのも、窓が開いている 9.4% の間だけ**。

```
  0.94秒  見える → 位置を直したい
  9.06秒  コンクリの壁。何も分からない
  0.94秒  見える → 直した結果が分かる
  ...
```

**立ち位置を 10 か所試すのに 100 秒かかり、そのうち 90 秒は壁を見ている。**
`lock = 0.9°` の一点を、**1 回あたり 0.94 秒しか見られない目で探せ**、と言っている。
`lm_sweep`（機械の通し）が通るのは、**機械は最初から答えの座標に居る**から。
`docs/V15.md` §14 が自分で書いている通り、
**「仕掛けが動くこと」と「仕掛けが遊べること」は別**。

#### 厳しさ③ — 絵と判定がずれている

- モデルのスリットは **38.6°**（`docs/V15.md` §12。Blender の `band(skip=)`）
- 判定の窓は **34°**（`slot.half = 17.0`）

**4.6° 分＝ 1 周あたり 0.13 秒（窓の 13%）、「スリット越しに見えているのに判定は閉じている」帯がある。**
プレイヤーから見ると「見えてるのに繋がらない」。**これが「判定が厳しい」の体感そのもの。**

#### 厳しさ④ — 判定が見ている的が、プレイヤーが見ている物と違う

```lua
if not throughSlot(c.slot, yawNow, ex, ez, c.center[1], c.center[3]) then
```

`c.center` は **`(22.0, Y2+1.2, 151.0)` ＝ 出来上がる階段の中心**で、**筒の向こう側**にある。
一方プレイヤーが目で追っているのは**筒の中に浮いている破片**で、
`k = 0.42 / 0.58 / 0.74` から x = **11.1 / 14.1 / 17.1**（筒は x 10〜18）。

3 つの塊は方位が違うので、**「いま見ている塊が見えている時間」と「判定が開いている時間」が一致しない。**
片方だけ見えている瞬間に窓が閉じたり、逆もある。

### 5.2 直し方（質の違う 6 案）

#### 案 9-1 ★★★「窓の間だけ hold が溜まる（閉じてもリセットしない）」

**いま最初にやるべきはこれ。**

```lua
-- いま:  窓が閉じた瞬間に c.hold = 0
-- 案  :  「合っているか」と「窓が開いているか」を分けて持つ
--        ・合っていない  → c.hold = 0（今までどおり）
--        ・合っているが窓が閉じている → c.hold は【増えないが減らない】
--        ・合っていて窓も開いている   → c.hold = c.hold + dt
```

実装は `Conn` に `slot` があるときだけ枝を足す **6 行程度**:

```lua
local aligned = looking and still and err < c.lock and fdmax < FOCUS_LOCK
                and (not c.minY or ey >= c.minY) and (not c.maxY or ey <= c.maxY)
if aligned and slotOpen then c.hold = c.hold + dt
elseif not aligned      then c.hold = 0.0
end                                  -- aligned かつ窓が閉じている間は据え置き
if c.hold >= DWELL then resolve(self, c) end
```

- **長所**: 絵は 1mm も変わらない。難度の芯（正しい所に立って、スリット越しに見る）も変わらない。
  消えるのは「あと 0.05 秒で決まるところで窓が閉じた」という**理不尽だけ**。
  スリット越しに見た時間の合計は今までどおり 0.36 秒必要なので、
  「見ていない物が実体になる」という原則も守られる
- **短所**: ほぼ無い。強いて言えば「1 周で決まらなかった」という緊張が減る
- **手間**: 小

#### 案 9-2 ★★★「判定の窓を絵に合わせる」（`half` 17.0 → 19.3）

- モデルのスリットは 38.6°。判定を **±19.3°** にすれば絵と一致する
- 窓は 0.944 → **1.072 秒**（+14%）
- **長所**: 数字 1 個。「見えてるのに繋がらない」が消える
- **短所**: 無い。**これは修正であって、緩和ですらない**
- **手間**: 極小。★案 9-1 と一緒にやること

#### 案 9-3 ★★「判定の的を、破片そのものへ向ける」

`throughSlot` に渡す点を `c.center`（出来上がる階段）から
**各破片の浮遊姿勢の重心**（`sh.pts` の平均。筒の中にある）へ変える。

- **長所**: 「いま目で追っている塊が見えている時」＝「判定が開いている時」が一致する。
  「なんで今なの？」が消える
- **短所**: 3 塊のどれを基準にするかを決める必要がある。
  **全部見えている時だけ**にすると窓が狭くなる（塊の方位差ぶん）。
  **重心 1 点**にするのが素直
- **注意**: `sim_liminal.py` の机上検査にも**同じ式**を入れること（表示と判定を別の式で書かない）
- **手間**: 小（5 行 + 検査側）

#### 案 9-4 ★「回転を遅くする / 窓を広げる」

- 速度を落とすのは**駄目**。`docs/V15.md` §12 が実測で「11°/秒（一周 33 秒）にしたら
  何も起きない時間が長すぎて仕掛けだと気づけない。**周期は 10 秒が上限**」と結論を出している
- 窓だけ広げる（`half` 17 → 30、窓 1.67 秒・duty 16.7%、周期は 10 秒のまま）なら成立する。
  ただし**モデルのスリットも 60° に開き直すこと**（Blender の `band(skip=)`）。
  でないと案 9-3 と逆向きの「絵と判定のずれ」が出る
- **長所**: 確実に楽になる
- **短所**: 楽になるだけで、**面白くはならない**。厳しさ②（情報が来ない）は 9.4% → 16.7% に
  なるだけで本質は残る
- **手間**: 小（+ Blender 作業）

#### 案 9-5 ✕「回転をプレイヤーが止められるようにする」— **採らない**

- 板を踏む・スイッチを押す形は、`docs/V15.md` §9 が明示的に禁じている
  （「そこに乗らない仕掛け（床の跡を歩く・**スイッチ**・タイマー）は足してはいけない」）。
  そもそもこの作品に押すボタンは無い
- ボタン無しの変種（**近づくと筒が遅くなる**）は動くが、
  **「近づいている最中に世界が反応する」＝ 合図**になる。ユーザーの掟に真正面から反する
- **却下**

#### 案 9-6 ★★「回る筒をやめて、`osc`（揺れる破片）にする」— 時間の規則を残したいなら

`Conn.shard(k, ents, osc=(dx,dy,dz,周期))` は**既に実装済み**で、
`liminal_runtime.lua:517` の `shardOffset()` がこう書いてある:

```lua
-- 揺れる破片。★合う姿勢(o=0)で【速度も 0 になる】式にすること。
--   ここが最速だと「合う瞬間」が一瞬すぎて理不尽になる。(1-cos)/2 なら端で止まる。
```

**この作品はすでに、時間で揺れる的の正しい作り方を持っている。**
`(1-cos)/2` は**合う姿勢の付近で速度が 0 になる**ので、
「合う瞬間だけ時間がゆっくり流れる」＝ 窓が幾何的に広い。
回る筒（等速回転）は真逆で、**合う瞬間が一番速く通り過ぎる**。

- **長所**: 判定を 1 行も足さずに、待つ規則が humane になる。破片は最初から全部見えている
  （厳しさ②が丸ごと消える）
- **短所**: 巨大な筒という絵を失う。`docs/V15.md` §14 が「この回で作った中で一番良い絵」と
  書いている物なので、捨てるのは惜しい
- **手間**: 小

#### 案 9-7 ★★★「そもそも回るのをやめる」— **これを推す**

> 「そもそも『回る』という規則がこのゲームに要るのか」

**要らない、と考える。理由は 3 つ。**

1. **時間で待たせる規則は既に 2 本ある**（規則E 暗の一瞬。継ぎ目 16 と 25）。
   筒は絵が違うだけで、プレイヤーの動詞は同じ「**待つ**」。§1 で数えた
   「規則が 12 種あっても手は 1 種類」の典型例になっている
2. **この作品が強いのは空間の側**（どこに立つか）。時間の窓は、その強みに
   **情報を与えない足枷**を足しているだけ（厳しさ②）
3. **筒という絵は捨てなくていい。**

**作り替え方**: 筒は残す。回転を止める。**スリットを 1 本のまま固定する。**

- 破片は今までどおり筒の中に吊る
- **スリット越しに 3 塊が全部見える立ち位置は、床の上に 1 か所しかない**
  （筒の半径 4m・スリット 38.6°・塊の広がり x 11〜17 から、幾何で一意に決まる）
- **時間の窓は消え、空間の窓になる。** やることは「見えるまで歩く」＝ この作品の本来の動詞
- ★これは §4 の**提案 B「枠に収める」の曲がった枠**そのものである。
  判定式は `insideFrame()` を円筒版にしたもの 1 本で済み、**規則が 1 つ増えるのではなく 1 つに統合される**
- 「動いていてほしい」なら、**筒は回すが判定には使わない**（＝スリットを 2 本、180° 対称に開ける。
  どちらか一方は常にこちらを向いているので、判定は角度に依存しなくなる。絵は動いたまま）

**結果として何が良くなるか**

| | いま | 案 9-7 |
|---|---|---|
| 破片が見えている時間 | 全体の 9.4% | **常時** |
| 立ち位置を直した結果が分かるまで | 最大 10 秒 | **即座** |
| 確定に要る連続時間 | 0.36 秒（窓の中で） | 0.36 秒（いつでも） |
| 動詞 | 待つ（規則E と同じ） | **覗く**（新しい） |

### 5.3 5.1〜5.2 のまとめ — 何をどの順でやるか

1. **まず 9-2**（`half` 17.0 → 19.3）。数字 1 個。バグ修正に近い
2. **次に 9-1**（窓を跨いで hold が溜まる）。6 行。理不尽だけが消える

## 6. ヒントを与えすぎている — 印と、自由な解き方

>   自由な解き方をしてほしい」

### 6.1 いま印がどれだけ答えを言っているか

**結論: 印はヒントではない。答えそのもので、しかも機械がそれを保証している。**

`source/calib_marks.py` の冒頭:

> 「**印の上ならどこに立っても繋がる**」を**絶対の条件**にして、2 つの軸で探す

そして机上検査 [5] が**毎回それを見張っている**。
つまり印は「たぶんこの辺」ではなく、**「ここに立てば必ず解ける床」の証明済みの部分集合**。

さらに 2026-09-09 の変更（`gen_liminal.py:571 mark()` の docstring）で、
印には**破片と同じ金色（`GOLD`）の細い線**が外周に付いた。

> 「金の線がある所どうしは仲間」という読み方が世界の中で成立する

**これで「あの金の四角に立て」が一目で分かるようになった。**
残った遊びは「金の四角まで歩く → 立つ → 破片の方を向く → 0.36 秒待つ」だけ。

**印の大きさ（`MARKS` 表の 全 27 個を計算した）**

| | 値 |
|---|---|
| 最小 | **0.141 m²**（`C9_mark` 0.19 × 0.74） |
| 最大 | **0.616 m²**（`C12_mk2` 0.49 × 1.14） |
| 中央値 | 約 **0.49 m²** |
| **1.5 m² を超えるもの** | **0 個** |

★ユーザーの目標「確定域 1.5 m² 以上」に対し、**印は 1 つも届いていない**
（印 ≤ 確定域 なので確定域はもう少し広いが、継ぎ目 9 で 1.39 m²、`docs/V15.md` §13）。
**いまは「答えを教えているのに、その答えが狭い」という、一番損な状態にある。**

### 6.2 ★線引き — さまよわせることと、詰ませることの違い

先に線を引いておく。ここを外れる案は書かない。

1. **部屋に入った時点で「ここに仕掛けがある」ことは必ず分かる。**
   浮いている半透明の破片が見えていれば足りる（実装済み）。
   分からなくてよいのは「**どこに立つか**」だけ
2. **探索範囲は常に 1 部屋の中。** 答えが別の部屋にある形にしない。
   The Witness の環境パズルが理不尽になる唯一の形がこれ
3. **詰みを作らない。** 迷った時間に応じて印が**必ず**出る（案 B-1）。
   上限は 75 秒。これは「さまよう」と「投げる」の境目として妥当な長さ
4. **試行のコストをゼロに保つ。** 確定は取り消せないが、失敗しても何も失わない。
   歩いて戻れる（`docs/SCALE.md` の掟。Viewfinder が rewind でやったのと同じ役目を
   「歩いて戻れる」が果たしている）
5. ★**確定域は 1.5 〜 4.0 m² に収める。**
   - 下限 1.5 m²: 体の直径が 0.68m（`characterController radius=0.34`）＝ 0.36 m² あるので、
     0.14 m² の印は**自分の体より小さい**。その上に立てているかを自分で確かめられない
   - 上限 4.0 m²: `calib_marks.py:44` のコメント「確定域が 4m² を超えると
     『その辺に立てば解ける』＝ 歯応えが消える」
6. ★★**印を消すなら、同時に確定域を広げること。**
   案内を消して 0.14 m² の一点を探させるのは**両方悪い**。
   `soft`（破片のずらし量を弱める）を上げれば **`lock` を緩めずに確定域が広がる**
   （`calib_marks.py` の説明どおり。浮き方が控えめになるだけ）。**ここが交換条件になる。**

### 6.3 印を弱める案（4 つ）

#### 案 B-1 ★★★「印は後から出る」— 迷った時間で濃くなる

部屋に入った時点では**印は無い**。その継ぎ目の周りをうろついた時間が溜まると、
**金の線が、ゆっくりと、連続的に**濃くなってくる。

**「合図ではない」ことの根拠**（この作品の掟に触れないための条件）:
- **近づいても濃くならない。** 変数は「その部屋に居た時間」だけで、距離を一切見ない
- **点かない・鳴らない・動かない。** 30 秒かけて連続的に濃くなるだけ
- **答えに近づいても何も起きない。** 判定側は 1mm も変わらない

**実装（既存の部品だけで足りる）**
- 「迷った時間」の測り方は `tutUpdate` が既にやっている作法そのもの
  （`self.walkT` / `self.turnT` を積み、`toward(cur, target, dt, 3.6)` で連続に寄せる）。
  ここでは継ぎ目ごとに `c.wanderT` を積む:
  ```lua
  -- 未確定で、その継ぎ目の中心から R m 以内に居る間だけ溜まる
  if (not c.locked) and dist(ex,ey,ez, c.center) < 12.0 then
      c.wanderT = c.wanderT + dt
  end
  local u = clamp((c.wanderT - 45.0) / 30.0, 0, 1)   -- 45秒は無反応、以後 30秒で満ちる
  ```
- 印の金線を濃くするのは **`scene:setMeshParams(e, 1.0, 0.84, 0.52, 0.55 * u)`**。
  `mark()` が作る `<name>_e0..3` の 4 本は `ReconnectInk` シェーダーで、
  `shaderParams` の 4 番目が明るさ。**これは既に `setGlow()` が使っている API**
  （`liminal_runtime.lua:526`）
- 印の板そのものも薄く出したいなら `UNBUILT` シェーダー + `scene:setMeshEffect(e, v)`
  （幽霊の破片と同じ仕組み。`make_ghost()` 参照）
- **手間: 小**（runtime 25 行 + `mark()` に shader を足す）

★**この案があるから、以下の案を安全に入れられる。** どれだけ隠しても詰まない。

#### 案 B-2 ★★★「幕ごとに弱める」

| 幕 | 印 | 理由 |
|---|---|---|
| 第一幕（1〜4） | **今のまま**（板 + 金線） | 型を教える役。`calib_marks.py:46` も「継ぎ目1 だけは広いままにする」と書いている |
| 第二幕（5〜10） | **板だけ。金線を外す** | 2026-09-09 以前の「床の擦れ跡」へ戻す。目を凝らせば分かる |

実装は `Conn(..., mark_level=0/1/2)` を足して `mark()` が金線を出すかどうかを分けるだけ。**手間: 小**

#### 案 B-3 ★★★「環境の手がかりへ置き換える」— 部品はもう全部ある

印を消した部屋に置くもの。**どれも既に `gen_liminal.py` にある関数**:

| 手がかり | 関数 | どう効くか |
|---|---|---|
| **破片の影** | `floor_shadow(tag, F, ents, y)` | ★**これが最強**。焦点から見た破片の投影を床に黒い板で置く。**破片が自分の影にぴたりと収まる場所が焦点**。ヒントであると同時に**答えの検算**になっている。いま継ぎ目 23 でしか使っていない |
| **死んだ蛍光灯** | `troffer(..., on=False)` | 天井の管を 1 本だけ消す／点ける。**明るさの島**が焦点の上に来る。Antichamber と The Witness の「不自然に整った配置」 |

| **非常口の緑** | `exit_sign()` | 既に規則D（継ぎ目 14）で「緑が答えを兼ねている」前例がある（`docs/V15.md` §9） |

「部屋のどこか」を「この一角（半径 3m）」まで狭めるのが手がかりの仕事で、
**最後の 2m はプレイヤーが破片の重なりを見て詰める**。これが The Witness の作法。

#### 案 B-4 ★「外れの印を混ぜる」— 条件つきで可

- 部屋に印を 3 つ置き、1 つだけ本物。囮の板（`LURE` / `dud`）は既にあり、
  `add_walk_colliders` が**わざと当たり判定を付けない**ようにして
  「ぶつかるかどうかで見分けられない」を守っている（コメントに明記）
- **短所（大きい）**: 3 か所で 0.36 秒ずつ待つのは**作業であって謎ではない**。
  深くならずに長くなるだけ
- **可にする条件**: 外れの印が**外れだと読める**こと。
  例 ── 外れの印に立つと**破片が逆に散って見える**（`k` の勾配が逆向きになる位置に置く）。
  そうすれば 3 つのうちどれかは 1 秒で捨てられる
- 一番良い使い方: **外れの印を、その部屋で既に解いた別の継ぎ目の焦点にする。**
  「床は、前に自分が立った場所を覚えている」という読み方が生まれ、囮が世界の一部になる

### 6.4 自由な解き方をどう作るか

#### いまどれだけ自由でないか（`needs` を全部数えた）

| 幕 | 継ぎ目 | 連鎖 | 自由度 |
|---|---|---|---|

#### 案 S-1 ★★★「第三幕の一本鎖をやめる」— 第四幕に倣う

第四幕（大展示室）は 5 本とも `needs` を持たず、**どこから解いてもよい**。

#### 案 S-2 ★★★「1 つの継ぎ目を、複数の立ち位置から解けるようにする」

**これはほぼ実装済みで、あと 8 行で完成する。**

- `Conn.shard(k, ents, focus=...)` は**破片ごとに焦点を持てる**（docstring に明記）
- `per_shard=True`（規則C 巡る）にすると破片を 1 つずつ実体化し、
  **ランタイムは未確定の破片を毎フレーム全部見るだけで、順番を一切強制していない**
  （`liminal_runtime.lua:2021-2053`）。**継ぎ目 12 と 17 は既に「好きな順で 4 か所を回る」**

足りないのは「**同じ破片を、2 通りの立ち位置のどちらからでも決められる**」こと:

```lua
-- 案: shard に F2 を持たせ、誤差の小さい方を採る
local err = alignError(ex,ey,ez, sh.F, sh.k, sh.pts, ox,oy,oz)
if sh.F2 then
    local e2 = alignError(ex,ey,ez, sh.F2, sh.k2 or sh.k, sh.pts, ox,oy,oz)
    if e2 < err then err = e2 end
end
```

生成側は `shard_display()` を 2 回呼ぶだけ（**同じ浮遊物に別の (F, k) を与える**機能が
docstring に書いてある通り既にある）。

- **効果**: 階段が「床から」でも「バルコニーから」でも組める。
  文法は 1mm も増えず、**「正解は 1 つ」という思い込みだけが消える**
- **手間: 小**（runtime 8 行 + 検査側に同じ式）

#### 案 S-3 ★★「迂回路 — どちらを解いてもよい」

**どちらか一方を解けば渡れる**ようにする。

- 実装: 開く扉／沈む塞ぎ板を、**両方の継ぎ目の `movers` に入れるだけ**。
  **ランタイムの変更ゼロ**
- 第二幕の 7 / 8（東の橋・西の橋。どちらも `needs=(6,)`）は**すでにこの形にできる**。
  今は両方解かないと先へ進めないのか、片方でよいのかを確かめて、片方でよい形に直す
- **手間: 小**

#### 案 S-4 ★★「幕の出口を『何本解いたか』で開ける」

`GOAL.need` はいま**継ぎ目の id を 1 つ**指している（`liminal_runtime.lua:2096`
`self.lockedIds[GOAL.need]`）。これを**本数**にする。

- 「5 本のうち 4 本解けば次の幕へ行ける」。嫌いな 1 本を飛ばせる
- The Witness のレーザーと同じ仕掛け。**投げるより飛ばさせる方がいい**
- **手間: 小**（5 行）

#### 案 S-5 ★★「取り返しのつかない選択」— §4 案 F（多義 `excl`）

自由度の最後の一段。**同じ破片が 2 通りの実体になり、選んだ方しか残らない。**
「自由に解ける」を、**選択の重みで**返す。実装済み・未使用（§4 案 F）。

### 6.5 Viewfinder / Superliminal はこの自由度をどう作っているか

| | Viewfinder | Superliminal | JUNCTION に写せる形 |
|---|---|---|---|
| 解が複数 | **中盤以降、自分でカメラを持つ**ので構図は無限。攻略記事も「多くの場合 複数の解法が成立する」 | 掴んだ物をどこへでも置ける。大きさは連続量 | **案 S-2**（同じ破片に 2 つの焦点）。連続の自由は作れないが、**離散の複数解**なら作れる |
| 失敗が怖くない | **rewind**（開発者いわく「レベル全部やり直しは苦痛だった」「試行錯誤を罰するのではなく奨励する」） | 掴み直せば元に戻せる | **歩いて戻れる**（既にある）。★ただし**確定は取り消せない**ので、`excl` の選択だけは慎重に |
| 段階的な解禁 | ポラロイド → コピー機 → 自分のカメラ。Stark「カメラを最初から渡すとプレイヤーは圧倒される」 | チェス駒 1 個の部屋から | **案 B-2**（幕ごとに印を弱める）が、これの裏返し。**道具を足すのではなく、補助輪を外していく** |
| 順番の自由 | 章は一本道。**章の中は自由** | 章は一本道 | **同じでよい**。幕は一本道、**幕の中を自由に**（案 S-1） |
| 詰まった時 | rewind + 「だいたい合っていればよい」寛容な判定 | チェックポイント | **案 B-1**（迷ったら印が出る）＋ **確定域を 1.5 m² 以上へ**（6.2-5） |

★**両作の共通点**: 自由度は「**やることの数**」ではなく「**やり直しの安さ**」で作られている。
Viewfinder は rewind を入れた瞬間にプレイヤーが大胆になった、と開発者が言っている。
JUNCTION でそれに当たるのは「歩いて戻れる」と「**印は最後には必ず出る**」の 2 つ。
**この 2 つを保証したうえでなら、印はいくら隠してよい。**

### 継ぎ目 11 — 「縮む廊下」（動詞 A: くぐって縮む）

x 16〜30 / z 172〜184

**入って何が見えるか**
南の扉をくぐると、まっすぐ 12m の廊下。天井の蛍光灯が、奥へ行くほど**低く、間隔が詰まって**いる。
突き当りに扉が 1 枚。遠近で小さく見えるだけかと思うが、**歩いても大きくならない**。
廊下の中ほど、右手の壁の前に金色の縁取りの破片が 3 枚、宙に浮いている。

**何をすると解けるか**
まず何も考えず突き当りの扉をくぐる。**その瞬間、体が半分になる**（音も光も出ない）。
振り返ると、今出てきた扉が自分の背丈の 2 倍ある。廊下の入口の光がはるか遠くに見える。
戻って廊下の 3 枚の破片を見ると、**さっきは絶対に合わなかったのに、今は合う立ち位置がある**。
目の高さが 1.70 → 0.85 に下がったから。

**解けると何が起きるか**
3 枚が 1 枚の渡し板になり、廊下の途中にある床の穴（`GAP1` にあたる）を渡せるようになる。
その先が次の部屋。

**なぜこの順なのか**
Superliminal の Induction 章と同じ作法。**失敗できない形で先に結果だけ見せる**
（`docs/REDESIGN.md` D-2 の「間違えようがない状態で、先に結果だけ見せる」と同じ）。
プレイヤーは「選んだ覚えがないのに世界が変わった」→ 戻って確かめる → 気づく。

**確定域**: 廊下は幅 14m あるので、0.85 の目の高さで 3 枚を合わせる床は
**2〜3m² 取れる**（`min_y/max_y` を 0.85 ± 0.25 に切る）。

### 継ぎ目 12 — 「枠の部屋」（動詞 B: 枠に収める）

x 16〜30 / z 184〜196

**入って何が見えるか**
6×12m（0.5 の体には 12×24m）の部屋。天井の蛍光灯は 2 本だけ点いている。
部屋のちょうど真ん中に、**床から立った空の窓枠**が 1 つ。ガラスは無い。
枠は通り道を塞いでいて、左右どちらかへ避けないと進めない。
奥の壁の手前に、金色の線で縁取られた破片が 5 枚、高さを変えて散っている。

**何をすると解けるか**
床のどこに立っても、破片は重ならない。**枠越しに見た時だけ**重なりが効く。
しかも 5 枚**全部**が枠の中に収まっていないと駄目。
枠に近づけば広く入るが遠近が合わず、離れると枠が狭くて 5 枚が入りきらない。
**前後に歩いて、初めて意味のある調整をする。**

**解けると何が起きるか**
5 枚が 1 枚の階段になり、部屋の北東の高い開口（次の部屋の床の高さ）へ架かる。

**なぜここか**
避けて通れる枠を通り道の真ん中に置くので、**通ろうとして必ず一度は覗く**。
覗いた瞬間に破片が近づくのが見えるので、「この枠は何かある」と分かる。
Portal の「次の部屋の仕掛けが窓越しに見えている」と同じ作法。

**確定域**: 枠の見込み角を破片の見込み角の 1.4 倍にすれば **1.8〜2.5m²**。
組む時に `sim_liminal.field()` で必ず測ること。

### 継ぎ目 13 — 「影の部屋」（動詞 D: 自分の影を重ねる）

x 16〜30 / z 196〜206

**入って何が見えるか**
部屋が暗い。天井の蛍光灯は全部死んでいて、**南西の隅に 1 本だけ**、
斜めに垂れ下がった管が点いている。
床に、うっすらと灰色の輪郭が 1 つ描いてある。角ばった細長い帯で、
北の壁の方を向いている。破片は**天井の近く**に 3 枚浮いている。
★破片を見上げても、どこからも合わない（焦点が床の上に無い）。

**何をすると解けるか**
灯りの前に立つと、自分の影が床に伸びる。歩くと影が伸び縮みして向きが変わる。
**影の先が床の輪郭にぴったり重なる位置**に立つと、頭上の 3 枚が落ちてきて庇になる。
**照準を一度も使わない。** 上を向いても下を向いても関係ない。

**解けると何が起きるか**
庇が北の壁に架かり、その下をくぐって東の廊下へ出られる。

**なぜここか**
2 部屋続けて「目で合わせる」をやった直後に、**目が要らない部屋**を置く。
手が完全に変わるので、覚えた手が効かないことがすぐ分かる。
教える装置は 3 つ全部**最初から見えている**: 灯り・自分の影・床の輪郭。

**確定域**: 灯りを高く（天井 2.0m の 1.8m）置くほど影が短くなり、確定域が狭くなる。
**1.2m の高さ**に吊れば影の倍率が緩くなり、**2m² 以上**取れる。

### 継ぎ目 14 — 「走る床」（動詞 E: 乗って待つ）

x 30〜58 / z 200〜204（渡り廊下）

**入って何が見えるか**
幅 4m・長さ 28m の長い廊下。天井は低い。
床の真ん中を、**腰の高さの平たい台車**がゆっくり（0.5 m/s）往復している。
廊下の東の端に、次の部屋の開口が**床から 1.8m 上**にある（0.5 の体には 3.6m 相当＝届かない）。
両側の壁に、破片が 4 枚ずつ、8 枚も貼り付くように浮いている。

**何をすると解けるか**
床を歩いている限り、8 枚はどこからも合わない。台車に乗る。
**乗っている間だけ**、壁の破片が動いて見える。台車が廊下の 3 分の 2 まで来た一瞬だけ
8 枚が重なり、そこで階段が生える。降りて上る。

**解けると何が起きるか**
壁から折り返しの階段が生えて、東の高い開口へ届く。

**なぜここか**
「止まって探す」を 3 部屋やった後に、**止まれない部屋**を置く。
台車は最初からゆっくり動いていて、乗れることは見れば分かる
（掟「歩ける物は最初から全部歩ける」を守る）。

**★実装の注意**: `STILL = 1.10 m/s` のゲートに台車の速度が乗る。
台車を 0.5 m/s にするか、判定を相対速度に直すこと（§4 案 E）。

**代替**: 台車に体が運ばれないことが実測で分かったら、
**動詞 C（押して運ぶ）に差し替える**。廊下に押せる台車を置き、
その上に破片の 1 枚が乗っていて、押した位置で 8 枚が合う、という形にする。
部屋の絵はほぼそのまま使える。

### 継ぎ目 16 — 「二つの出口」（動詞 F: 選ぶ）

x 58〜72 / z 196〜214（最後の部屋）

第三幕で一番広い部屋（0.5 の体には 28×36m に見える）。
