# V15 — 解き方を増やす（2026-09-08）

指摘（そのまま）:

* エリアは大量にあるのに、**解き方が「橋」と「ドア」の二種類しかない**
* **プールを解いた以降、同じようなパズルの繰り返し**で面白味がない
* 複数の仕掛けを**組み合わせて解く巨大ギミックステージ**が欲しい
* シャッターの所、**横の棒のモデルがずっと残っていてバグっている**
* シャッターは良いが、**まっすぐ立って合わせるだけでは物足りない**。もっと良い視点が欲しい

新しいエリアは増やさない。**既存の部屋の中身だけを差し替える。**

---

## 0. 何が「同じ」だったのか（数字）

`python source/score_liminal.py` の出力（2026-09-07 時点）:

| 指標 | 値 | 意味 |
|---|---|---|
| 規則 A（相似）| **19 / 25** | ほぼ全部が同じ規則 |
| 連鎖している | **2 / 25** | ほぼ全部が一問一答 |
| 結果が橋 | 6 / 25 | v14 の 10 本からは減った |

ただし本当の問題は規則でも結果でもない。**動詞が 1 つしかない**ことだった:

> **「立ち止まる → 正しい一点を探す → そこで待つ」**

A〜F はどれもこの動詞の変奏でしかない。B は焦点を使わないだけ、D は向きを変えるだけ、
E は待つ時間が増えるだけ、F は立ち位置の条件が増えるだけ。
**25 回とも同じ事をしている。**だから 3 本目で飽きる。

→ V15 の方針は **「動詞を増やす」**。止まらない／照準を使わない／時間に追われる／
自分の後ろを解く／乗り物の上で解く。

## 1. 新しい規則（動詞が違うもの）

### G「なぞる」— 歩きながら、目で溶接する

長い物（配管の列・鉄骨・ベルトコンベア・シャッターのスラット）を **N 個の節**に割る。
節は **照準がその節を通過した瞬間**に、その節だけ実体化する。
条件は「全体のずれが緩い上限以内」＝ **大まかに合っていれば良い。代わりに端から端まで見る**。

* **初めて「止まらない」パズル**。立ち止まると 1 節も進まない
* 手触り: 溶接。左から右へ首を振ると、その軌跡どおりに物が生えてくる
* 実装: `Conn(..., sweep=N)`。shard を N 個に割り、各節に `swept` フラグ。
  DWELL は使わない（通過で決まる）
* ★使い先は §3 の巨大機械の「24m の桁」。シャッターには**入れない**（§2.2）

### ~~H「踏んでなぞる」~~ — ★却下（錯覚を使っていない）

床の埃に、薄い跡が点々とある。**その跡を順に踏むと**、跡が描いていた形の物が建つ。
視線は一切使わない。

* **照準を使わない唯一の規則**。目をつぶっても解ける ＝ 今までと真逆
* 手触り: 「見て決める」ゲームの中に**歩いて決める**が一つだけある違和感
* ★**踏み外しても戻さない**。この作品は「確定した物は絶対に元へ戻さない」で通してきたので、
  やり直しを入れると其処だけ作法が変わる。難しさは**順序と道のり**で出す
* ★**gate から `still` を外すこと**。ほかの規則は「止まっていないと確定しない」ので
  `still`（1.10m/s 以下）が入っているが、これを掛けると**歩いている間しか進まない
  この規則が 1 歩も進まない**。`gateB`（連鎖・暗・高さ窓・遮蔽）と `gate = gateB and still`
  に割った
* ★破片は**真上に浮かせて、踏むと降ろす**（`shard_free` の変位）。相似 `k` で縮めると
  焦点の方へ飛んで行くので、**どの跡がどの段なのか対応が読めない**
* 実装: `Conn(..., trail=[[x,z], ...], trail_r=0.95)`。i 番目を踏むと i 番目の破片が落ちる

### I「二度見」— 覚えていられる時間

焦点が 2 つある。A で合わせると**半分だけ**実体化し、**8 秒**で崩れる。
その間に B へ走って合わせると確定する。

* **初めて時間に追われる**。部屋の広さが初めて意味を持つ
* A と B の間に見通しが無いと理不尽なので、**A から B の印が見えている**こと
* 実装: `Conn(..., relay=秒)`。`shard(focus=...)` を 2 つ持ち、片方が決まると `relayT` が減り始める

### J「影を追う」— 自分の目が光源

プレイヤーの目の位置に光を置く。破片は正面の壁に**影**を落とす。
壁にはペンキで輪郭が描いてある。**影が輪郭に重なった時**に、
**背中側にある**破片が実体になる。

* **振り返ったら解けない**。後ろの物を、前の壁を見ながら解く
* 「見たものが、そうなる」の一番きれいな言い換え ＝ **視線が形を落とす**
* 実装の要: エンジンの点光源が影を落とすか（`dx12_set_shadow_pcss` / `contact_shadow`）を
  実機で確認する。落ちないなら **影板を Lua で毎フレーム置き直す**（破片を目から壁へ
  射影した長方形を 1 枚描く。数学は `floor_shadow()` の壁版）
* 判定は既存の相似のままで、**gate に「継ぎ目が視野外（>120°）かつ影の壁が視野内」**を足す

### K「水鏡」— 水面の中でだけ合う

第五幕の井戸に水を張る。本物は覗けない所（塞がれた区画）にあり、
**水に映った像でだけ**重ねられる。下を向いて解く。

* 実装: 水面 y=Wy に対して**鏡像の複製ジオメトリ**を沈めておく（半透明の板 1 枚 + 反射側の箱）。
  鏡像から見た重なりは、**目を水面で反転した点 E' から見た本物の重なり**と同一なので、
  数学は既存のまま。ランタイムで `ey' = 2*Wy - ey` を渡すだけ（`mirrorY`）
* SSR には頼らない（品質が出ない／実機で確認できない）

### L「動く焦点」— 走る足場の上の一点

ガントリー（門型クレーン）が 12m 走る。その上に立っている間だけ通る一点がある。
**乗り物の上で解く**。

* 実装: 焦点をエンティティ相対で持つ（`focus_of="G6_car", focus_off=[0,1.7,0]`）。
  足場は KINEMATIC で transform を書き、**乗っている体には毎フレーム同じ差分を足す**
  （CharacterController は勝手には運ばれない）

### M「見つめると溶ける」— 負の継ぎ目の発展

見つめ続けると実体が**消える**（継ぎ目14 の逆）。床を見つめると床が抜ける。
「見るな」を体で覚えさせる。**通り道を作るために、わざと壊す**のが正解の場所を 1 つ作る。

### N「見張りの目」— 自分では見えない重なり

部屋にある「目」（常にプレイヤーを向く円盤）。**その目から見て**重なった時に成立。
自分の画面では一度も重なって見えない。目の位置から逆算して立つ。

* 難しすぎるので**最後の一本**か、**影（規則J）と併用**して読ませる

## 2. シャッター（継ぎ目5）をどう良くするか

### 2.1 バグ（直した）

**症状**: シャッターが巻き上がった後、**横の棒が 12 本、開口に宙吊りで残る。**

**原因**: 実在する 3 枚の板（`C5_ll` / `C5_lr` / `C5_ur`）に貼った**リブ 12 本**
（`C5_*_r0..3`）が、**巻き上げの mover 一覧に入っていなかった**。
板だけが上がり、リブはその場に残る。生成コードでリブを変数に受けずに捨てていた。

**直し**: `pribs` に受けて `mover_by` の一覧へ入れた（`source/gen_liminal.py`）。

**再発防止**: 机上検査に **[9]「置き去りの飾り」** を足した。
「動く板に**くっついている**物（名前が `<動く板>_…` か、その箱にほぼ収まっている物）が、
一緒に動くか」を全継ぎ目について機械で見る。
★破片の一員（`shards` に載っている物）は対象外にする ── 扉枠の実在する側は
塞ぎ板の隣にあるだけで「くっついている」わけではないので、これを外さないと誤検出になる。
わざとリブを外すと **12 件を正しく捕まえ、それ以外は 0 件**であることを確認済み。

### 2.2 視点 ── **触らない**（2026-09-08 決定）

一度「規則G なぞる」（上半分を 5 本の縦帯にして、左から右へ首を振り切ると
鼻先の 18cm から壁際の 93cm まで順に溶接される）に作り替えたが、
**ユーザー判断で却下 ──「シャッターは前回のまんまでよかった」。**

→ **継ぎ目5 は HEAD の姿（4 分割・左上 1 枚が k=0.16 の巨大×極小）へ完全に戻した。**
残したのは §2.1 のリブのバグ修正だけ。焦点 (6.6, 5.1, 92.0) / lock 4.6 /
確定域 3.28m² も元の値。

**教訓**: 「もっと良い視点があれば」は**作り直してよいという意味ではない**。
既に効いている絵（巨大×極小の驚き）は、動詞を変えると一緒に壊れる。
新しい動詞は**まだ何も効いていない場所**へ入れる。

規則G の実装（`sweep=True` / `SWEEP_CONE`）はランタイムに残してある。
使い先は §3 の巨大機械（24m の桁を溶接する）。

## 5. 立坑を組んで分かったこと（2026-09-08 / 机上検査を通す過程）

第三幕の小部屋 6 個を消して **58 x 42m・高さ 28m の立坑 1 本**に置き換えた。
継ぎ目 11(巻き段) / 12(水鏡の柱) / 13(折り返し段) / 14(庇の道) までは机上検査を通った。
16(出口の床)が未接続。**通しではまだクリアできない。**

### ★★このゲームの幾何が課す制約（設計の前提。破ると必ず詰む）

1. **歩ける面は必ず水平**。机上シミュレータの Body は `rotation[1]`(yaw)しか見ない。
   傾けた斜路は当たり判定が嘘になる → 縦移動は**全部 0.32m 以下の段**でやる。
2. **跳躍が無い**。柱の頭は必ず接するまで寄せる。4m 空けたら渡れない。
3. **★★螺旋を一周(360度)させてはいけない。** 降りきった段の真上に一周前の段が来て、
   頭上が 1.17m しか空かない ＝ 乗れても出られない檻になる。**270 度で止める**。
4. **★★回廊を段の真上に張り出させない。** 同じ理由で、上り切る手前で通れなくなる。
   逃がすなら**平面で**逃がす(高さでは逃げられない)。
5. **★★焦点は「道の軸の上・手前の端」に置く。** 横に置くと、
   **歩ける = 接している = 縮めても接している**ので、破片どうしが必ず重なる。
   軸の上に置くと `f_i = F + k_i·d_i·u` になり、k と d が同時に増えるぶん
   破片が軸に沿って一列に開く。継ぎ目3(プールの階段)が通っているのはこの形だから。
6. **★多義(継ぎ目7/8 の数学)は「どちらを選んでも同じ出口」に使えない。**
   `(1-k)(F14-F15) = k(B-A)` は二つの実体が**平行移動だけ違う**ことを要求するので、
   片方は必ず出口から離れる ＝ 詰む。多義は**行き先が二つあってよい所**でだけ使う。
7. **深さは歩く所ではない。** 5.80 → 0.60 → 7.60 と歩かせると登りが 7m になり、
   0.283 刻みで 25 段要る ＝ 破片が団子になって読めない。
   **歩くのは上の 5m、下の 17m は「ずっと足の下にある空虚」として見せる。**

### 直し方の手順（次に触る時）

不通の原因はいつも「どの升が、どの高さで、何に塞がれているか」。当てずっぽうで座標を
動かすより、**`sim_liminal.World` と `walk` を直接叩いて `flat` を覗く**のが速い:

```python
r, seen, flat = S.walk(w, start, {"t": (x, z, y)}, B)
print(flat.get((round(x/S.CELL), round(z/S.CELL))))   # その升の到達高さ
for b in w.near(x, z): print(b.name, b.aab)           # 何が居るか
```
これで「巻き段が柱の上に乗っていた」「回廊が段の上に庇を出していた」の 2 件とも
一発で分かった。

### ★★実機で踏んだ罠 — 到達点(CHECKS)は「降りる途中」にも要る

立坑を建てて実機で通したら、**巻き段を普通に降りただけで上へ引き戻された**。
落下復帰の条件は `p.y < CHECKS[cp].y - 2.0`。到達点どうしの高さが 2.0m 以上
離れていると、正しく歩いているのに「落ちた」と誤判定される。
巻き段は 2.8m 下るので、**途中に 2 つ**(西・東)到達点を置いて刻む必要があった。

症状は「warp しても一瞬で元の場所に戻る / 継ぎ目の誤差が 999 のまま」。
机上シミュレータは到達点を見ないので、**これは実機で通さないと絶対に出ない**。

### 立坑の通し（実機・2026-09-08）

`lm_tp` で各到達点へ跳び、印に立って視点を合わせる方式で
**継ぎ目 11 → 12 → 13 → 14 → 16 の 5 本すべてが確定**（`lm_locked = 5`）。
scriptErrors 0 / 机上検査 **PASS**（破片の干渉・順路・確定域・足場・同一平面・
照明・貫通・置き去りの飾り、全 9 項目）。

| # | 規則 | 出来る物 | 確定域 |
|---|---|---|---|
