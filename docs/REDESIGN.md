# JUNCTION 作り直し契約書（2026-09-01(4)）

前回の作り直し（文字を消してカメラと色で教える）は**失敗している**。
プレイヤーの指摘：

> 操作は分かるが**条件が全く分からない**。今何が起きているのか情報が入ってこない。
> 角度で行き先が変わるという話も**説明が一切ない**。
> ステージはどれも開幕のカメラワークもレベルデザインも同じ。
> カメラが建物に遮られて見えないことがある。

## 何が悪かったのかの診断（ここを外すとまた同じ物を作る）

1. **これはグラフパズルなのに、グラフが一度も見えない。**
   部屋は 52m 離れた閉じた箱で、外からは何も見えない。どの部屋とどの部屋が繋がったのか、
   自分が今どこにいるのか、出口がどっちなのかを**知る手段が存在しない**。
   開幕に出口を 2 秒映すだけでは、3 部屋目に着いた時点でもう分からない。
2. **予算・制限時間・詰みという「条件」が、画面の隅の無地の図形でしか表現されていない。**
   右上の錠剤が何なのか、減ると何が起きるのかは、どこにも書かれていないし、
   どこにも**演じられていない**。
3. **角度の授業がカメラの見物で終わっている。**
   扇を上から眺めさせても「自分の入り方で行き先が変わる」体験にはならない。
   決定的に欠けているのは **「今の自分の入射角がどの出口を指しているか」の実時間表示**。
   撃つ前に照準が見えないのに「精密射撃」を要求していた。
4. **8 面すべて 12m 角の同じ箱・同じ湧き位置・同じ北壁のドア・同じ開幕カメラ。**
   新しい事を 1 つ足しているつもりでも、**画面が同じなので新しく見えない**。
5. カメラ位置が式（湧き位置 ±4m）で決め打ちなので、柱・壁・什器に刺さる。

## A. 結線ビュー（Constellation）

`TAB` 押しっぱなしで画面中央に浮かぶ、**文字のないノードグラフ**。

- 部屋 = 角丸の四角。**今いる部屋だけ白く塗り、他は輪郭だけ。**
- 部屋の縁に、その部屋が持つドアを**ドア固有色の点**で置く。
- 接続済みのドア同士を**そのドアの色の点線**で結ぶ。点は流れる（生きている感じ）。
- 出口の部屋は緑の枠＋中に緑の点。
- 未使用の接続予算は、グラフの下に**ピンの形**で並ぶ（HUD の錠剤は廃止）。
- **文字・数字は 1 つも置かない。**

実装：`ui:rect` の immediate モードのみ。斜め線は**小さい四角の連なり**で描く
（点線に見えるのは狙い通り）。座標は部屋のワールド座標を XZ 平面ごと
画面へ正規化して置く（グラフのレイアウトを別に持たない＝生成側と二重管理しない）。

`TAB` のキーキャップは、**第1面で初めて接続が成立した瞬間に 1 回だけ**出す（`learn("map")`）。

## B. 羅針（Compass）— 角度ルールの本体

合流点（2 枚以上）のドアに **7m 以内** で近づくと、床にこれが出る：

1. **扇の塗り**。出口ごとのスライスを**面で**塗る。今までの細い線ではなく板。
   `models/wedge<角度>.gltf`（120/60/40/30 の 4 種）を `scene:spawn` で出す。
   色は行き先のドア色、彩度は `vivid()` を通す。
2. **針（Needle）**。ドアの足元を支点に、**今の WASD の押し方向**に実時間で回る矢印。
   歩いていない時は最後の向きで止まる。`models/needle.gltf`。
3. **狙っているスライスだけ明るくなる**（他は 0.35 倍に落ちる）。
4. ★**ドアの中の虚無が、行き先のドアの色に染まる。**
   これが決定打。ストレイフすると**目の前のドアの色が変わる**ので、
   「入り方で行き先が変わる」を、通る前に、文字なしで理解できる。
   `Void_<id>` を `scene:setColor` で染め、`VoidLight_<id>` の色も合わせる。
5. **スライスの境界をまたいだ瞬間に「カチッ」と鳴る**（`ui/detent.wav`）。
   ダイヤルの手応え。これが無いと境界がどこか分からない。

## C. 物としての予算（接続ピン）

- 未使用ピンは**結線ビューの下**に並ぶ（A に統合。常時 HUD の錠剤は消す）。
- **接続した瞬間、ピンが 1 本ドアへ飛んで刺さり、以後そこに残る**
  （`models/pin.gltf` を `Pin_<n>` として世界に置く）。
  予算を使ったことが、画面の隅の消灯ではなく**世界の変化**として残る。
- 予算 0 で `E` を撃つと、ピン置き場が赤く弾けて `ui/deny.wav`。

## D. レベルデザイン

### D-1. 部屋の形を増やす

`blender_kit.py` を**寸法パラメータ化**し、以下のフットプリントを出す。
`gen_stages.py` は部屋ごとに形を選べるようにする。

| 形 | 内寸 | 天井 | 用途 |
|---|---|---|---|
| `box12` | 12 x 12 | 4.0 | 既存。標準の部屋 |
| `hall20` | 20 x 20 | 7.0 | 吹き抜け。開幕カメラが引ける。合流点を置く主室 |
| `corr18` | 18 x 8 | 3.2 | 廊下。助走が一直線に強制される |
| `cell8` | 8 x 8 | 3.0 | 小部屋。行き止まり／罠に使う |

### D-2. 角度ルールは【幾何で先に教える】

カメラの授業は廃止。代わりに：

- **第2面**：ドアの手前に**腰高の仕切り（`models/divider.gltf`）が 1 枚**立っていて、
  ドアへは**左からか右からしか入れない**。左から入ると青い部屋、右から入ると黄の部屋。
  プレイヤーは「選んだ覚えがないのに違う所へ出た」→ 2 回目で気づく。
  **間違えようがない状態で、先に結果だけ見せる。**
- **第3面**：同じ形の部屋から仕切りが消える。今度は自分で助走を決める。
  床に助走レーンの塗りだけが残っている。
- **第4面**以降で 3 枚合流・4 枚合流と枚数が増える。

### D-3. 8 面の作り直し

| 面 | 部屋の形 | 教える事 | 見た目の差 |
|---|---|---|---|
| 1 | corr18 → box12 | 触れる・繋ぐ・通る。**出口の部屋がガラス越しに見えているが歩いては行けない** | 白基調・明るい |
| 2 | box12（仕切りあり）| 入る側で行き先が変わる（幾何で強制） | 仕切りと 2 色の床 |
| 3 | hall20 | 仕切り無しで自分で助走を決める。制限時間の導入 | 吹き抜け・高い天井 |
| 4 | box12 + cell8 | GDD 第4面。予算 2・ドア 4。触ると詰むドア | 電球色・暗め |
| 5 | corr18 中心 | 遠近の錯覚 | 長い廊下 |
| 6 | hall20 | 四枚合流 40° | 柱林・影が強い |
| 7 | 混成 | 五枚合流 30° | 蛍光灯が半分死んでいる |
| 8 | 全部 | 一棟。合流点の崩壊 | 非常灯だけの赤い照明 |

**湧き位置とドアの壁は面ごとに変える**（今は全部 (0,-3.5) の北壁）。

### D-4. カメラワーク

- **式で決めるのをやめる。** `gen_stages.py` の各ステージに `cine` を**手で書く**。
  座標は**部屋ローカル**で書き、生成側がワールドへ直す（絶対座標を手書きしない）。

```python
cine=[  # (部屋, 目のローカル位置, 見る部屋, 見る点のローカル位置, 秒)
    ("G", (0, 3.0, -7.0), "G", (0, 1.2, 2.6), 2.2),
    ("S", (-5, 2.4, -5.0), "S", (0, 1.5,  6.0), 2.6),
]
```
- 生成側で **「目の位置が部屋の内側に 1.2m 以上余裕があるか」を assert** する。
  刺さるカメラをコミットできないようにする。
- Lua 側は**毎フレーム `physics:raycast` で目→注視点を確認**し、
  遮られていたら目を上へ最大 +2.5m 逃がす（それでも駄目なら注視点へ寄る）。
- **面ごとに絵の作りを変える**（第1面は横移動のドリー、第3面は吹き抜けの俯瞰から降りる、
  第5面は廊下の奥行きを使ったトラック、…）。全部同じ「出口→ドア」をやめる。

## 分担と、絶対に守る境界

**同じファイルを 2 人で触らない。** 触っていいファイルを固定する：

| 担当 | 触ってよいファイル | 触ってはいけない |
|---|---|---|
| **音** | `source/gen_sfx.py`, `assets/audio/**` | それ以外すべて |
| **モデル** | `source/blender_kit.py`, `source/gen_textures.py`, `assets/models/**` | `gen_stages.py`, `*.lua` |
| **Lua** | `assets/components/Junction.lua`, `FreeLook.lua` | `source/**`, `assets/scenes/**` |
| **レベル** | `source/gen_stages.py`, `assets/scenes/**` | `assets/components/**` |

★ただし `gen_stages.py` は最後に `Junction.lua` の `>>>STAGES` 〜 `<<<STAGES` を
書き換える。**Lua 担当はこの範囲を手で編集しない**（生成物）。
レベル担当が `gen_stages.py` を回すのは、Lua 担当の作業が終わってから。

## 名前の契約（変えるなら両方同時に）

生成側が置き、Lua が名前で引く物：

```
Door_<id>            ドアの基準（transform だけ。forward = 部屋の内側）
Void_<id>            ドアを塞ぐ白板。接続モードで奥へ飛ばす／行き先の色に染める
VoidLight_<id>       白板を白飛びさせる点光源
Frame_<id>_-1/1/top  ドア固有色の枠
Proxy_1..8           虚無に浮かぶ候補（全ドアで使い回す）
Goal / GoalBase / GoalLight / GoalFx
MainCamera / Logic_Stage_<n>
<部屋>_Light_1..4    蛍光灯（明滅に使う）
```

**Lua が実行時に `scene:spawn` する物（生成側は置かない）**：

```
W_<id>_<k>     扇のスライス板   models/wedge120|60|40|30.gltf
Needle         入射角の針       models/needle.gltf   （シーンに 1 本だけ）
Pin_<n>        刺さった接続ピン models/pin.gltf
```

★`Mark_` / `Slice_` / `Lane_` / `Post_` は**廃止**（扇の塗りと針に置き換える）。
生成側は出力をやめ、Lua は参照をやめる。

## 検証の掟

- **HUD は `dx12_screenshot*` に写らない**（ImGui）。HUD を見たいなら
  `Start-Process` + `GetClientRect`/`ClientToScreen`/`CopyFromScreen` で
  ゲーム窓を直接撮る（`docs/shot.ps1`）。
- Lua を書いたら `dx12_play` → `dx12_get_script_errors` を必ず見る。
- 「たぶん動く」でコミットしない。**自分の目で見てからコミットする。**
