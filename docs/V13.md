# v13「観測が世界を確定させる」— 一本道の解放と、網膜に描く回路図

v12 への指摘:

> 最初は一個の扉しか入れなくて、一個一個ステージを解放していって最後通電させてゴールまでいく
> 部屋が傾く部屋なんだけど、なんもトリックじゃないし、意味が分からない
> もっと目の錯覚、認知の歪みをついた、まだ見かけない脳ハックのマップを
> ドアのつながりの中心メーターの UI いらない
> ボールのめり込みがすごい

## 0. 診断 ── なぜ傾く床だけが浮いたのか

既存 4 つを並べると、実は全部**同じ一本の軸**の変奏だった。

| 既存の仕掛け | 実は何をしているか |
|---|---|
| アナモルフォーシス(B) | **視点**が形を確定させる |
| 見ると沈む段板(H) | **注視**が存在を崩す |
| 枠の継ぎ手 / 回転台(D) | **視野の枠**が接続を確定させる |
| 膜の向こうの写し(M) | 観測面の向こうに**確定していない写し**がある |
| 傾く床(G) | ← **入力(歩行方向)が物理を動かす**。観測ではない。しかも錯覚ですらない |

**Junction のテーマは既に「観測が世界を確定させる」だった。** 傾く床だけが
「入力 → 物理」という別ジャンルの機構だったので、浮いて当然だった。

### v13 の軸

> **見たものが、そうなる。だから「見ないこと」も道具になる。**

視線をゲームの通貨にする。全ての仕掛けを 5 つの動詞に整理する。

| 動詞 | 部屋 |
|---|---|
| 見る向きで世界が変わる | D 継の間(回転台) |
| 観測面の向こうを動かす | M 膜の間 |
| **凝視して確定させる** | B 画角の間(アナモルフォーシス) |
| **凝視して崩す** | H 見の間(段板) |
| **凝視して溜める** | **G 滝の間(運動残効)** ← 新規。傾く床を置換 |
| **自分から目を焼く** | **A 母屋のフィナーレ(補色残像)** ← 新規 |

技術的な追い風: 本作は HMD ではなくモニタ + マウスルック。**両眼視差が存在しない**ので
単眼手がかりの嘘がタダで通る。前庭感覚との矛盾も起きないので閾値が事実上無限大。

## 1. 一本道の解放(リング)

v12 は A を中心としたハブで、**5 部屋が最初から全部開いていた**。
v13 は**環**にする。物理的な 3 × 2 の升目がそのまま順路になる。

```
        D 継の間 ────── A 受入ホール ────── G 滝の間
       (-37,-12)   6      (0,0)      1     (36,-12)
           │                                   │
         5 │                                 2 │
           │                                   │
        M 膜の間 ────── B 画角の間 ────── H 見の間
       (-37,-42)   4     (0,-36)     3    (40,-37)
```

**順路は A → G → H → B → M → D → A。** 教える順に登っていく:

| 順 | 部屋 | 動詞 | 継電器 | この扉を開ける鍵 |
|---|---|---|---|---|
| 1 | **G 滝の間** | 凝視して溜める | k1 | ─(最初から開いている唯一の扉) |
| 2 | **H 見の間** | 凝視して崩す | k2 | k1 |
| 3 | **B 画角の間** | 凝視して確定させる | k3 | k2 |
| 4 | **M 膜の間** | 観測面の向こう | k4 | k3 |
| 5 | **D 継の間** | 見る向きで変わる | k5 | k4 |
| ─ | A へ戻る | ─ | ─ | k5 |
| 終 | **谷を渡る** | 目を焼いて回路図を読む | ─ | 5/5 + フィナーレ |

- **開幕、A から出られる扉は G 行きの 1 枚だけ。** 他の 4 枚は錠(`lockplate`)が
  被さっていて、枠を重ねても繋がらない。
- 継電器が入ると、**その場で次の錠が落ちる音がする**(`ui/open.wav` + 錠が床へ落ちる)。
  文字は 1 文字も出さない。
- 一度開いた錠は戻らない。環なので**どちらの向きにも歩いて帰れる**。

### 実装(既存機構の拡張だけで足りる)

`PAIR(a, b, needs=...)` の `needs` は今 `plateDone`(重量板)しか見ていない。
これを**継電器 `k1..k5` も受け付ける**ように広げる。それだけで順序解放になる。

```
Junction.lua: local live = (g.needs == "") or self.plateDone[g.needs]
           →  local live = gateLive(self, g.needs)   -- plate / breaker / "pw" を解決
```

## 2. G 滝の間 ── 運動残効(Motion Aftereffect / 滝の錯覚)

**傾く床・鋼球・受け皿・畝は全部廃止する。** めり込み問題も一緒に消える。

### 何が起きるか

部屋の南壁いっぱいに、**下へ流れ続ける縞**(滝)がある。
その前に立って **一定時間じっと見つめる**と、目を離した先の壁が**逆向き(上へ)に流れて見える**。

**その残効が続いている間だけ、谷に架かる板が本当に迫り上がっている。**
残効が切れると板は落ちる。

### なぜこれか

- 錐体ではなく**方向選択性ニューロンの選択的順応**。プレイヤーの網膜と視覚野で
  **本当に錯覚が起きる**。スクリーンショットには写らない
- 残効の持続時間は**適応時間の平方根**で伸びる(Anstis, Verstraten & Mather 1998)。
  つまり「もっと長く見つめれば、より遠くまで行ける」という難度曲線が
  **物理法則の側から出てくる**。設計者が数字をでっち上げなくていい
- H 見の間「凝視すると崩れる」の**完全な裏返し**。ゲーム全体の文法として対になる

### 仕様

| 記号 | 値 | 根拠 |
|---|---|---|
| 適応の判定 | 滝の中心が視界の **26 度以内**、距離 14m 以内 | H の 34 度より狭い = 「ちゃんと見る」を要求 |
| 溜まる速さ | 1.0 / 秒(上限 `cap = 6.0` 秒) | 6 秒凝視で満タン |
| 残効の長さ | `hold = 2.6 * sqrt(charge / cap)` 秒 | 平方根則。満タンで 2.6 秒 |
| 減衰 | 見るのをやめると 0.5 / 秒で溜めが抜ける | 溜めっぱなしにできない |
| 板 | 7 枚。残効が生きている間だけ y=0 へ迫り上がる | H の段板と同じ機構を流用 |
| 板の落下 | 残効が切れると 0.8 秒かけて落ちる | 踏み外しても即死にしない |

**残効が生きている合図は文字でも UI でもない**: 壁のテクスチャが**逆向きにドリフトする**
(`scene:setMeshUvScroll` を負にする)。プレイヤーの脳内で起きているのと同じ事を
世界の側でも起こす。これで「今それだ」が伝わる。

**罠を先に潰しておく**: 滝を見ながら後ろ歩きで渡ろうとすると簡単すぎる。
滝は**谷の手前側の壁**に付け、渡る方向を向くと**滝が背中側になる**配置にする。
つまり「溜めてから、振り向いて、走る」。

## 3. A 母屋のフィナーレ ── 補色残像(Negative Afterimage)

5 つ点いた瞬間に扉が開くのではない。**配電盤が回路図を要求する。**

1. 5/5 になると、母屋の照明が落ち、**真っ赤な大面**が正面に灯る(20 秒)
2. 赤の中には**黒く抜かれた 3 つの印**がある(左 / 中 / 右のどれか 3 つのうち 1 つが違う形)
3. 20 秒後、赤が消えて**白い壁**になる。プレイヤーの網膜に**緑の残像**で印が浮かぶ
4. その形と同じ差込口へプラグを挿す = 通電

**ゲームは白い壁しか描いていない。** 回路図はプレイヤーの網膜が生成する。
攻略サイトのスクリーンショットには**絶対に写らない**。

### 事故らないための設計

- **間違えても失敗しない。** 違う差込口に挿すと `ui/deny.wav` が鳴って赤面がもう一度出る
- 残像が見えなくても、**赤面が出ている間に印の位置を覚えていれば解ける**
  (残像は「楽しい近道」であって必須ではない)。ここを守らないと理不尽になる
- 赤面の色は `(0.86, 0.05, 0.05)`。緑残像が最も強く出る波長域

## 7. 実装の契約(エージェント間で共有する語彙)

### gen_stages.py に足す DSL

```python
FALLS(fid, room, at, facing="S", w=12.0, h=6.0,      # 滝の面
      cone=26.0, rng=14.0, rate=1.0, cap=6.0,
      hold=2.6, decay=0.5, steps=[(x,z), ...])        # 残効中だけ迫り上がる板
FINALE(room, at, yaw=180.0, wall=(w,h),               # 補色残像のフィナーレ
       marks=("circle","triangle","cross"), answer=1,
       redsec=20.0, sockets=[(x,z), ...])
```

`PAIR(a, b, needs="k1")` ── `needs` に継電器 id を受け付ける(既存の plate id / "pw" と共存)。

### シーン JSON に載る cfg キー(Junction.lua が読む)

```
falls   = { {id=, x=, z=, nx=, nz=, cone=, rng=, rate=, cap=, hold=, decay=,
             face="Falls_<id>", steps={ {ent=, x=, z=, y0=, y1=}, ... } }, ... }
finale  = { x=, z=, redsec=, answer=, panel="Fin_Panel", white="Fin_White",
            marks={ "Fin_M0", "Fin_M1", "Fin_M2" },
            sockets={ {ent=, x=, z=}, ... } }
locks   = { {gate="g1", ent="Lock_g1", needs="k1"}, ... }
```

### エンティティ命名規則

| 接頭辞 | 物 |
|---|---|
| `Lock_<gateId>` | 錠(未解放の枠に被さる) |
| `Falls_<id>` | 滝の面(UV スクロールする) |
| `FallsStep_<id>_<n>` | 残効中だけ迫り上がる板 |
| `Fin_Panel` / `Fin_White` / `Fin_M<n>` / `Fin_Sock<n>` | フィナーレ一式 |

### 守る事(過去に踏んだ罠)

- `math.atan2` は無い。`Junction.lua` 冒頭の `local atan2` を使う。間違えると
  **その回以降 OnUpdate 全体が死ぬ**
- `halfExtents` には `Transform.scale` が掛かる。スケールで伸ばすモデルの
  half は**モデルのままの寸法**で書く
- KINEMATIC は `transform` を書くのが正しい道。`physics:setPosition` は効かない
- HUD の文字は**かなと常用漢字だけ**(→ ★ ▸ は豆腐になる)。そもそも v13 も文字は出さない
- `dx12_screenshot_game_view` は **UI 層を撮らない**。HUD の確認は別経路
- ヘッダ相当(= `gen_stages.py` の共通部)を触った回は**必ず通しで再生成**して検査器を通す

### 8-2. 湧き位置がフィナーレの差込口の真正面だった

### 8-3. 赤面と印が開幕から母屋に立っていた(答えが最初から見えていた)

`resetRun` で 1 回 `hide()` しても、**Play 直後のシーン復元が transform を書き戻す**
(README の既知の罠)。→ フィナーレが始まるまで毎フレーム隠し続ける。

### 8-4. 印の高さが失われて「印の無い赤い板」になる

`resetRun` が `self.finMY[j]` に現在の y を控えるが、**ホットリロードや R でもう一度走ると
印はすでに HIDE_Y(-200) にいる**。それを控えると赤面に印が出なくなる。
→ `y > HIDE_Y * 0.5` の時だけ控える。

### 8-5. 赤が飽和していなかった

赤面 (0.86,0.05,0.05) × 赤灯 (1.0,0.16,0.13) 強度 9.0 は**白へクリップして salmon** に見え、
錐体の順応が分散して緑の残像が弱くなる。→ 赤面 (1.00,0.03,0.03) / 赤灯 (1.0,0.05,0.03) 強度 6.5。

### 8-7. MCP から実機を測る時の手順(次に触る人向け)

- **プレイヤーは `physics:setPosition` だけでは動かない**。`e.transform.position` と両方書く。
  それでも `useBody` のような押し込み(`placeT`)が無いと 1 フレームで戻ることがある。
- **視点は `saveNum("tpYaw", deg)` + `saveNum("tpSeq", 前+1)`** で FreeLook に飲ませる
  (マウスは注入できない)。方向キー `LEFT/RIGHT` でも回る。
- **`dx12_step_frames` の 1 フレームは実時間**。エディタが非フォーカスだと 10fps 台まで落ちるので、
  「30 フレーム進めた」が数秒になる。**2.6 秒の残効は 30 フレームで消える**。
  短い現象を捕まえるなら 4〜5 フレームずつ刻むこと。
- **`saveNum("dbg_pw", 1)` で継電器 5 台を全部入った事にできる**(v13 で追加した検証フック)。
  錠の連鎖とフィナーレを、5 部屋解かずに実機で確認するためのもの。`dbg_size` / `dbg_lockYaw` と同じ流儀。
- `dx12_screenshot_game_view` は **UI 層を撮らない**。HUD の確認には使えない。

### 9-1. クリアチェックで見つけて直した実バグ 2 件

**① 滝の間の入口の枠が「谷を渡る線」の上に立っていた(致命)**

`滝(x=24.3) -> 入口の枠 g1(x=28) -> 谷(x=33..41)` が一直線に並んでいた。
溜めて振り向いて東へ走ると、**必ず g1 をくぐって母屋へ飛ばされる**。
しかも一度くぐった組は `bound` で恒久的に繋がるので、以後何度やっても飛ばされる。
→ `GATE("g1", "G", (-8.0, 7.0), "W")` へ移動(滝の軸から 7m 外す)。

**② 部屋 H のベンチが出口の枠 h2 を塞いでいた(致命)**

`H_bench_7 (24, -44)` が `Gate_h2 (23, -43.5)` の **1.12m 手前**に立っていて、
**部屋 B へ物理的に行けなかった**。`check_props` は什器同士と壁しか見ていないので通り抜けていた。
→ ベンチを移動し、**`check_gateclear()` を新設**(枠の中心から `什器半径 + 1.6m` 以内に
什器があると `SystemExit`)。バグを戻して検査器が実際に落ちることも確認済み。

### 9-2. 滝の間の時間予算(実測)

走る速さは `SPEED 3.4 × FAST 1.3 = 4.42 m/s`(`FreeLook.lua:19-20`)。谷は **8m**。

| | 値 |
|---|---|
| 谷の横断に要る時間 | 8m ÷ 4.42 = **1.81 秒** |
| 板が完全に上がっている時間 | 振り向いてから **2.4 秒**(実測: t=0.30/1.00/1.81/2.40 で y=-0.56) |
| 板が落ち切る時間 | 約 3.6 秒(t=3.01 で y=-2.67、t=3.61 で y=-4.76) |

**余裕は約 0.6 秒。** ただし *谷の縁で溜める* ことが前提。滝の壁際(x=24.4)から走ると
16.6m = 3.76 秒かかって**間に合わない**。そこで視線判定を **面の最近点**に変えた(§8 と対):
これで谷の縁 x=31.5 に立っても満タンまで溜まる(実測 charge 7.60)。

### 9-3. MCP から通しを取る時の限界(次に触る人向け)

**MCP の 1 往復が 1〜2 秒あるので、反応時間を要求する部屋は手で遊べない。**
滝の間(残効 2.6 秒)と段板の間(道が曲がっている)は、キー入力での実走では毎回落ちた。
- 滝の間は **時間予算を実測して計算で確かめた**(9-2)
- 段板の間は **7 枚を 1 枚ずつ踏んで `route PASSABLE` を確認**した
  (視線を 90 度外すと 7 枚とも y=-0.56 へ迫り上がる = 機構は正しい)
- 枠の通過は **正しい立ち位置に 1.2 秒立ってから向こう側へ出る**と確実に決まる。
  立ち位置は `seeThrough()` を Python で再実装して 0.25m 格子で総当たりすれば出る
  (成立は **立ち位置だけ**で決まり、カメラの向きは効かない。**回転台 t2→t1 だけは例外**で
  `camYaw ∈ 42..222 度` が要る)
