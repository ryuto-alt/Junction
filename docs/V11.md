## 2. ★v11 の原理 —【手前の枠の中に、向こうの枠が見えている時だけ繋がる】

```
        ┌─ 手前の枠(gate) ─┐
  目 ●──┤                 ├───→  向こうの枠が【この開口の中に見えている】
        └─────────────────┘       ⇒ 二枚は繋がる。くぐると向こうの枠の裏に出る
```

- 判定は「向こうの枠の中心へ引いた線が、手前の枠の開口を通るか」。高さ違いで 3 本引く
- 向こうの枠は**正面をこちらへ向けて**いること(裏からは繋がらない)
- 自分は手前の枠の**正面側**に居ること。手前が近く、向こうが遠いこと
- 組は**手で書いた対だけ**(`PAIR`)。壁越しに偶然繋がることはない

**これで転送の理由がプレイヤーの目に返る。**どこへ出るかは通る前に見えている。

★**重ねた事は 1.2 秒覚えておく。** 枠に体を寄せると自分が枠の正面から外れるので、
その瞬間だけ判定が切れて**くぐる直前に必ず繋がりが消えていた**(実測)。
「合わせてから入る」を成立させるための記憶。

### 施設そのものが視線のパズルになった

受入ホール(40m 四方)を中心に、四方の部屋が **4m の隙間を挟んで**並ぶ。
その隙間を**窓**が貫いているので、隣の部屋は**見えるが入口が無い**。
窓ごしに向こうの部屋の枠を見つけ、手前の枠と重ねる ── それだけが道になる。

| | 部屋 | 役 |
|---|---|---|
| A | 受入ホール 40x40x14 | 柵(z=-13)と谷(z=0,幅14m)で三本の帯に割れている。中心 |
| B | 仕分け廊 36x9x5 | ★画角の嘘。歩いても奥が近づかない + 視界が 8 度傾く |
| G | 傾く部屋 16x16x6 | ★見た方へ床が下がる。鋼球を重量板へ転がす物理パズル |
| D | 機械室 26x26x9 | エイムズの部屋(別棟)/ 偽の廊下 / ドラム缶と重量板 |
| H | 保管庫 22x16x5.5 | 見張り(視界に入っている間は動かない人型) |

解き筋: 柵越しに重ねて中の帯 → 東の窓ごしに機械室 → ドラム缶を板へ(p0)
→ 南の窓ごしに仕分け廊 → 廊を東へ(画角の嘘)→ 南の窓ごしに傾く部屋
→ 鋼球を板へ(p1)→ 中の帯へ戻り、谷の向こうの枠と重ねて出口。

## 3. ★物理 — 什器に当たり判定と剛体を入れた

v10 まで什器は**全部すり抜ける飾り**だった。

| | 例 | 設定 |
|---|---|---|
| `phys="fix"` | 棚 / ロッカー / ベンチ / 柱 | motionType 0。押しても動かない壁と同じ |
| `phys="dyn"` | ドラム缶 26kg / 木箱 17kg / 鋼球 48kg | motionType 2。歩いてぶつかると転がる |

★**がくがくさせない数字**(指摘「しっかり現実っぽく」):
`restitution` を 0.2 以下(跳ね返りが小さいほど落ち着く)、`linearDamping`/`angularDamping`
を入れて微振動を殺す、**mass は現実の値**にする。軽すぎると人にぶつかった瞬間に
吹き飛んで嘘に見える。★CharacterVirtual は接触した動的剛体を押すので、
「歩いてぶつかると転がる」は Lua を 1 行も書かずに成立する。

★やり直し(R)では**位置と速度の両方を戻す**。速度を残すと落ちた勢いが持ち越される。

## 4. ★傾く部屋 — 見た方へ床が下がる

床は**1 枚の動く板(KINEMATIC)**。プレイヤーの視線の向きへ、床がその方向へ下がる。

```
sin(roll)  = -視線x * sin(θ)
sin(pitch) =  視線z * sin(θ)
```

★**符号に注意。** 平面 `y = -(nz/ny)z` は【法線の水平成分の向きが下り坂】になる。
逆に取ると玉が「見た方と反対」へ転がってパズルが成立しない(実測で 1 度踏んだ)。

- 重力はワールドの真下のまま。だから**純粋に物理で解ける**
- ★どちらを向いても手前が下り坂 = 現実にはあり得ない床。振り返っても下っている
- 床は部屋より 5m 大きく作って端を壁の中へ埋める。さらに壁の下へ**腰板**を垂らす。
  ★腰板に**当たり判定が要る**。無いと下がった側で玉が壁の下から逃げる(実測: 鋼球が
  部屋を脱出して 400m 落下した)
- 板と一緒に傾ける物(重量板など)は Lua が同じ回転で置き直す

**パズル**: 低い壁で区切った囲いの中の重量板へ鋼球を入れる。囲いは北にしか開いていない
ので、玉を一度北へ回してから南へ落とす。**見る方向が唯一の操作**。

## 5. ★視野角のトリック(fovramp)

仕分け廊(36m)を東へ歩くと画角が **74 度 → 46 度**へ連続的に絞れる。
絞ると**近づいても大きくならない**ので、奥の壁がいつまでも同じ大きさのまま =
歩いても終わらない廊下になる。同時に視界が 8 度傾く(`rolls`)ので、
**奥へ行くほど廊下が傾いて見え、振り返ると水平に戻る**。

`anchors`(1 個の物だけ角度を固定する)との違いは、**画面全体に効く**こと。

## 6. ★HLSL — `Membrane.hlsl`(つなぐのトリックアート)

枠の中に張ってある膜。**左半分と右半分が別々の場所の表面**で、互いに逆へ流れている。
真ん中の縫い目(ファスナーの歯)だけが、その二枚を留めている。

| 状態 | 見え方 |
|---|---|
| 繋がっていない | 歯が固く噛み合った 1 本の細い線。膜は不透明で、向こうは見えない |
| 繋がった | 歯が左右へ開き、間に**向こうへ抜けた裂け目**が空く。★裂け目ごしに行き先が見える |
| くぐる瞬間 | 裂け目から衝撃波 |

`effectValue` に繋がり具合を毎フレーム送る(`scene:setMeshEffect`)。
★**明るさは控えめに。** 加算を強くするとブルームで一瞬で白飛びして何も読めない(実測)。

## 7. ★くぐる瞬間の演出(暗転しない)

指摘「フェードアウトだと味気ない」。

**膜そのものがカメラの前を通り過ぎる。** くぐった瞬間は膜が**閉じたまま顔の前を覆い**、
そこから縫い目が左右へ裂けて向こう側の部屋が現れる。同時に画角が 30 度伸び縮みし、
視界が 12 度ねじれる。継ぎ目を通ったのだから膜が顔の上を通る ── 理屈が絵と一致している。

★**実測: engine v1.12.9 の post は `wave` / `radial` / `chromatic` / `invert` /
`pixelize` が【値は入るのに描画へ出ない】。** 効くのは
`bloom` / `vignette` / `grain` / `exposure` / `tonemapper` / `fxaa` / `deband` だけ。
画面歪みはこの膜(メッシュ + カスタムシェーダー)で作るしかない。
`post.set("ca", …)` は名前が違う(正しくは `chromatic`)。名前は `post.names()` で引ける。

## 7.5 ★v11.1 — 「解き方がぜんぜん分からない」への答え(教える層)

指摘:

> 各部屋パズルの解き方がぜんっぜんわからない。
> 後ろ見るとなんか立ち絵がいるけどそれだけじゃなんも意味わからない。

**正しい指摘。仕掛けだけ作って、遊び方を一切教えていなかった。**
ルールが特殊(枠に枠を重ねる)なので、放っておいて発見できるものではない。
次の 6 つを足した。

### (1) 対の色

**同じ色の枠どうしだけが繋がる。** 枠の灯りと膜の色相が対の色になる。
どれとどれが組なのかが、文字なしで一目で分かる。色は 6 種
(amber / cyan / green / violet / red / blue)。中の帯に並ぶ 4 枚は全部違う色にしてある。

### (2) ★重なり具合のバー(これが一番効く)

枠の正面に立つと、画面の中央下に**重なり具合のバー**が出る。
動くと伸び縮みするので、**手探りで正解の立ち位置を探せる**。
ルールを知らなくても「動いたらバーが伸びた」で気づける。満ちると「つながった」。

### (3) 立ち位置の印

最初の 2 組だけ、床に**対の色のレーン**を描いてある。そこに立てば必ず重なる。
1 組目で「ここに立つ → 膜が裂ける → くぐれる」を体験させ、2 組目で反復する。
3 組目以降は印を出さない(そこからが本番)。

### (4) 電源の無い枠は消灯する

`needs` の付いた組は、重量板が押されるまで**灯りが消えていて膜も灰色**。
見れば「まだ使えない」と分かる。板を押した瞬間、板からその枠へ**光の帯が飛ぶ** =
どれが開いたかが分かる。板の色 = 開く枠の色。

### (5) 繋がっている間は枠と枠の間に光の帯

壁も窓も突き抜けて見えるので、遠目にも「今この二枚が一枚になっている」が分かる。

### (6) ★傾く床は【押している間だけ】

**常に傾いていると玉が止められず、パズルとして成立しない。**
右クリック(または SHIFT)を押している間だけ、見ている方へ床が下がる。
離せば水平に戻って玉が止まる。**体で狙って、離して止める。**

### 見張りに意味を持たせた

指摘「立ち絵がいるだけで意味が分からない」。**視線をふさぐ物**にした。
枠と枠を結ぶ線の上に立たれると繋がらない(HUD が「何かが 線をふさいでいる」と言う)。
当たり判定を持つ 34kg の剛体なので、**押しのければいい**。
目を離した隙に線の上へ移動してくるので、放っておくと何度でも塞がれる。

★HUD の文字は **かなと常用漢字だけ**。矢印(→)や記号(★ ▸)は ImGui の日本語範囲に
入っていないので豆腐になる。`python source/check_glyphs.py` が照合する。

★**`dx12_screenshot_game_view` は UI 層を撮らない。** HUD の確認は `dx12_ui_screenshot`
(エディタ全体)を使う。これを知らないと「HUD が出ていない」と誤診する(実際にやった)。

★**Lua のテーブルは後勝ち。** 対の色を `r/g/b` で書いたら、**枠の番号 `b` を青成分 `b` が
上書き**して `seeThrough` に nil が渡り落ちた。色は `cr/cg/cb` にしてある。

## 7.6 ★v11.2 — 「クリアできる? シミュレーションした?」への答え

**していなかった。** 部品ごとの確認だけで、通しで遊んでいなかった。実際に通したら
**クリア不能の穴が 3 つ**見つかったので直した。

### 見つかった穴

1. ★★**継ぎ手が片道だった。** 判定が「正面から入って裏へ出る」だけだったので、
   向こうの部屋に着いた時点で自分は【出口の枠の裏】に立つ。帰るには正面へ回り込む必要があるが、
   部屋の壁との隙間しか無い置き方があり、事実上【行きっぱなし】だった。
   → **一度繋いだ組は繋がったまま(機械が覚える)**。繋がっている枠は裏からも通れる
2. ★**鋼球の転がり抵抗が低すぎた**(linearDamping 0.10)。床を水平に戻しても止まらず、
   狙った所へ置けない = パズルにならない。→ **0.62**。「傾けている間だけ転がり、離すと止まる」
3. ★**重量板が囲いの中央にあった。** 玉は板を通り過ぎて南壁で止まるので、
   1.7m 手前で止まって永久に押せない。→ **板は【玉が自然に止まる所】=囲いの突き当り**へ

### 道筋を削った

v11.1 は往復 3 回・板 2 枚・分岐 5 本で、道筋そのものが読めなかった
(指摘「その部屋でなにすればいいか分からん」)。必須を **4 回くぐって 1 つ解く**まで削った。

```
始まりの帯 --琥珀--> 中の帯 --水色--> 傾く部屋(玉を板へ) --水色--> 中の帯 --青--> 出口
```

★**中の帯に立つと、谷の向こうの出口と、消えている青い枠と、
東の窓の向こうの青い板が全部同時に見える。** やる事は見れば分かる。
機械室(エイムズ)/ 仕分け廊(画角) / 保管庫(人型)は**寄り道**にした。

### 文字をやめた

指摘「文字出してくれたけどいらなすぎる。邪魔」。文字の帯は全部削除。残したのは:

- 照準の真下の**細い線 1 本**(重なり具合。対の色で光る。文字なし)

## 7.7 ★v11.3 — 玉が地面へ埋まる / 傾けるのにボタンが要る / 什器が取り残される

### ★★`physics:setPosition` は【コライダーの中心】を指す

玉が地面へ埋まっていた真因。原点(足元)の座標をそのまま渡していたので、
**半径 0.36m ぶん沈んだ位置に置かれていた**。ドラム缶(箱)でも同じ理屈で高さの半分沈む。

エンジン側は生成時に offset を足し、書き戻し時に引く(`PhysicsSystem.cpp`)ので対称に正しい。
狂うのは **Lua から setPosition を呼ぶ時だけ**。`dynprops` に
「原点からコライダー中心までの高さ」を持たせ、必ず足してから渡すこと。

```lua
physics:setPosition(e, Vec3.new(x, y + dp.off, z))   -- dp.off = 球なら半径 / 箱なら高さ/2
```

### ★傾けるのにボタンは要らない

右クリック方式をやめ、**歩いている間だけ、進む向きへ床が下がる**ようにした。
止まれば水平へ戻って玉も止まる。向きは「移動方向 0.72 + 視線 0.28」の混合なので、
歩きながら首を振ると少しずつ狙いが変わる。

**歩いて玉を追うと床が前へ傾いて玉が逃げる** = 玉を追い立てる感覚になり、説明が要らない。

### ★什器も床にくっつけた

傾く部屋の什器は **KINEMATIC** にして、床と同じ回転で置き直す。
静止体(motionType 0)のままだと **transform を書いても当たり判定が動かない**ので、
ロッカーだけ空中に取り残される。

### ★編集スクリプトの誤爆で Junction.lua を壊した(記録)

`s.index('for _, tl in ipairs(self.cfg.tilts...')` で置換範囲を取ったら、
**resetRun の中にある同じ行**を掴んで、そこから OnUpdate 途中までを丸ごと消した。
症状は「Logic の OnStart が走らない = bodyIdx が -1 のまま / 何も動かない」。

復旧は `git show HEAD:assets/components/Junction.lua` を土台に v11 の実行時コードを
入れ直した(v10 の使っていない仕掛け = 暗い筒 port/link, creep は入れ直さず捨てた)。
**置換の目印は必ず一意になる長さで取ること。**
