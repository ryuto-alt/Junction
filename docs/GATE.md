# 選択装置を「向き」から「場所」へ — 2026-09-01(5)

## なぜ変えるのか

作り直し(4)で、床の扇・入射角の針・ドアの色染めまで作った。**それでも伝わらなかった。**

> 矢印の位置が意味わからない。ADWS押すたびに変わる。矢印の意味が伝わらない。
> 入射角の概念が意味わからん。全然伝わらないです。何をしようとしてるのか。

診断:

1. **矢印が指していたのは「WASD の押し方向」＝入力そのものであって、行き先ではない。**
   一人称のプレイヤーは「ドアの方へ歩く」としか思っていない。その歩きの**微妙な角度**を
   選択装置にしたので、A を押すたびに矢印が飛ぶのが**情報ではなくノイズ**に見える。
2. **一人称では「自分が今どの向きに動いているか」は見えない量。**
   見えないものを選択装置にした以上、どれだけ丁寧に表示しても
   「表示を読んで理解する」作業にしかならず、体で分かる瞬間が来ない。
3. **現実にも比喩が無い。** ドアに入る角度で行き先が変わる物は世の中に存在しない。
   一方で「**どのゲートを通ったかで行き先が決まる**」は、改札・料金所・分岐器で誰でも知っている。

★GDD の主張「同じドアでも入り方で出る場所が変わる」「合流するほど的が狭くなる」は**保つ**。
変えるのは**入り方を何で測るか**だけ。角度 → **開口のどこを通ったか**。

## 新しい機構

**ドアの開口が、行き先の数だけ縦の色帯(band)に割れる。通った帯の色のドアから出る。**

```
      【今】角度で選ぶ                    【新】通る場所で選ぶ
                                          ┌────┬────┬────┐
        ┌──────────┐                      │ 青 │ 黄 │ 緑 │  ← 開口が帯に割れる
        │   ドア   │                      └────┴────┴────┘
        └────┬─────┘                        │    │    │
         ╱   │   ╲                        ┌─┘    │    └─┐
      青 ╱   │黄  ╲ 緑                    │      │      │  ← 床のレーンが
       ╱     │     ╲                      │      │      │     そのまま帯へ続く
   自分の角度は矢印を                     歩いて入った帯の色の
   見るしかなかった                       ドアから出る
```

- 帯は**開口の高さいっぱい**。遠くからでも「あの扉は3つに割れている」と分かる
- 床のレーンは帯と**同じ幅・同じ色**で、開口からまっすぐ手前へ伸びる。
  **レーンと帯が地続きに見えること**が全て。扇のように角度で開かない
- 近づくと、**今そのまま歩けばどの帯を通るか**が明るくなり、
  **ドアの中の虚無がその色に染まる**（この仕掛けは(4)で効いていたので残す）
- 通った瞬間、その色のドアから出る

### 「合流するほど的が狭くなる」は保たれる

| 合流枚数 | 出口 | 帯の幅 |
|---|---|---|
| 2 枚 | 1 | 2.00m（帯は割れない） |
| 3 枚 | 2 | 1.00m |
| 4 枚 | 3 | 0.67m |
| 5 枚 | 4 | 0.50m |

★**ドアの開口を `DOORW = 1.5 → 2.0` に広げる。** 1.5m のままだと 4 出口で 0.375m になり、
プレイヤーの直径 0.7m に対して狙いが厳しすぎる。2.0m なら最小 0.5m。
**帯に体が収まる必要はない**（判定は体の中心が横切った位置）ので 0.5m でも通せるが、
2.0m にすると「人が通る扉」ではなく「**門・ゲート**」に見えるのも狙い
（帯で割れている物としての説得力が上がる）。

### 判定（表示と判定は必ず 1 箇所に集約する）

```
lat  = ドア平面を横切る瞬間の、ドア中心からの横ずれ
       （プレイヤーから見た左右。ドア自身の right ではないので符号に注意）
band = clamp(floor((lat + DOORW/2) / (DOORW/n)) + 1, 1, n)
```
- **角度の条件は無くす。** 「ドアへ向かって歩いている」(`dot(move, outward) > 0.3`) だけ残す。
  横から壁ズリしながら滑り込んでも、**通った場所が正**
- `|lat| > DOORW/2` なら壁。そもそも通れない

- `models/needle.gltf` と `Needle` / `NeedleEdge`（入射角の針）

## 「繋がった」瞬間の演出（3つ全部やる）

今はピンが刺さって光るだけで、**「部屋を選んで終わり」**に見えている。
繋ぐという行為が**世界に何をしたのか**を、その場で見せる。

順番（合計 2.2 秒。**どれも任意のキーで飛ばせる**こと）:

1. **光の糸**（0.4秒）… 白い虚無の中を、繋いだ先のドアへ向かって `fx:beam` が伸びる。
   距離があること・物理的に結ばれたことを画で見せる
2. **繋いだ先の部屋を一瞬見せる**（0.8秒）… カメラが向こうの部屋へ飛んで戻る。
   ★**同じ部屋へは 1 回だけ**。毎回やるとテンポが死ぬ
3. **結線ビューが自動で開く**（1.0秒）… TAB のグラフが勝手に開き、
   **新しい線が引かれるアニメーション**を見せて閉じる。
   「今わたしは何をしたのか」を、その場で図にして返す

★3 は特に効くはず。**接続＝グラフに辺が 1 本増えること**を、
プレイヤーが自分で TAB を押す前に、勝手に見せてしまう。

## レベル側で直すこと

### ★第2面の仕切りが致命的に間違っていた（動けない原因）

`Door_d` は x=0。仕切りも x=0 の z=47〜53。**ドアの真正面・中心線上に立っていた。**
その結果:
- ドアの手前 1.15m だけが袋小路になり、そこへは仕切りの端を回り込んで**横歩きでしか入れない**
- 入れたとしても**正面（角度 0°）＝ 2 つのスライスのちょうど境界**にしかならない

「左右どちらかからしか入れなくする」つもりが、**真ん中しか通れない形**になっていた。
**塞ぐべきは中央、開けておくべきは左右。**

新機構に合わせた正しい形:
```
        ┌──────────────┐
        │   ┌──┬──┐    │   ← ドア(2つの帯)
        │   │青│黄│    │
        │   └──┴──┘    │
        │    ██████     │   ← 衝立。ドアの正面を塞ぐ(幅1.2 / 手前2.0m)
        │   ↙      ↘    │      真っ直ぐ入れないので、左右どちらかへ回る
        │  青の帯   黄の帯      = どちらの帯を通るかを必ず【選ぶ】ことになる
        └──────────────┘
```

### その他

- `DOORW` 1.5 → 2.0 に伴い、開口の当たり判定（壁のセグメント幅）も追従させる
- 全面で、**ドアの手前 4m に助走を邪魔する物を置かない**（レーンが読めなくなる）
- 8 面すべて、レーンと帯が地続きに見えるかを目で確認する

## 名前の契約（追加・削除）

Lua が実行時に `scene:spawn` する物:
```
Band_<id>_<k>   開口の色帯    models/game/band.gltf   （原点=底面中心、+Y へ立つ板、幅1/高さ1で作り scale で伸ばす）
Lane_<id>_<k>   床のレーン    models/game/lane.gltf   （原点=手前端の中心、+Z へ伸びる平板、幅1/長さ1）
Pin_<n>         接続ピン      models/game/pin.gltf    （据え置き）
```
削除: `W_<id>_<k>` / `Needle` / `NeedleEdge` / `models/wedge*.gltf` / `models/needle.gltf`

★**シーン読み込み時に参照されていないモデルは `scene:spawn` しても描画されない。**
`[System]/Preload` のダミーを `band` / `lane` / `pin` に**差し替えること**（wedge/needle は削除）。
これを忘れると帯もレーンも無言で出ない。
