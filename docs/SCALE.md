# JUNCTION — 機構を「大きさ」へ作り直す(2026-09-02) v3

`docs/GATE.md`(帯・通った場所)の後継。**GATE の帯機構は全廃する。**

## なぜ変えるのか

帯は「狙う精度」を足しただけで、**「考える深さ」を一切足していなかった。**
繋いでも世界が何も変わらないので、プレイヤーの判断は最初から
「出口に一番近いドアを選ぶ」の一択。ルールが増えるほど**単調さが濃くなる**構造だった。

直すのは表示でも面の数でもなく、**「繋ぐ」という動詞の意味**。

> **繋ぐことは、道を敷くことではない。自分の大きさを変えることだ。**

## 機構(ルールは 7 行)

1. 建物の開口には **4 つの大きさ**がある。
2. **自分にも大きさがある。** 始まりは 1(＝扉にちょうどの体)。
3. **自分の大きさ以下の開口にしか入れない。**
4. 繋いだ開口を通ると、**(出た開口 ÷ 入った開口)** 倍に自分の大きさが変わる。
5. **高い所にある開口は、大きくないと届かない。**
6. 接続は **1 対 1**。同時に張れる本数がピン(予算)。
7. 緑の柱に触ればクリア。

### 大きさの梯子(全部 2 倍刻み。★この表が唯一の正)

| 開口 | size | 開口の実寸 (幅 × 高さ) | その大きさの体の高さ |
|---|---|---|---|
| 通気口 `vent` | **0.25** | 0.50 × 0.65 | 0.45 m |
| 小口 `hatch` | **0.5** | 1.00 × 1.30 | 0.90 m |
| 扉 `door` | **1.0** | 2.00 × 2.60 | 1.80 m |
| 門 `gate` | **2.0** | 4.00 × 5.20 | 3.60 m |

体の高さ = `1.8 × scale`、目の高さ = `1.7 × scale`。
開口は**全部相似形**(幅:高さ = 2:2.6)なので、**「体が開口をどれだけ埋めているか」が
どの大きさでも同じに見える**。これが機構全体の説得力の土台。

- **入れる条件**: `scale <= size`(自分の数と開口の数を比べるだけ)
- **通った後**: `scale ← scale × (exitSize / entrySize)`
- **届く条件**: `sill <= 1.4 × scale`(＝手の届く高さ)。実際に使う敷居は **0(床) か 0.9m** の 2 択。
  0.9m は `scale >= 0.643` ＝ **0.5 以下では届かない**。
  ★これが「小さいほど得」を壊す唯一の装置。無いとゲームが一方通行になる。

### なぜこれが良いのか(前回の失敗の裏返し)

GATE.md の教訓は「**一人称で、画面に存在しない量を選択装置にしてはいけない**」だった。
入射角も、歩いている向きも、画面に無い。

**自分の大きさは画面そのもの。** 目の高さ・歩く速さ・見慣れた物(長椅子・ロッカー・箱)との
対比で、0.1 秒で分かる。**読んで理解する量ではなく、見た瞬間に体で分かる量**になっている。
比喩も現実にある(不思議の国のアリス / ガリバー / ミニチュア)。

## 見せ方(ここが今回の本体)

### A. 虚無の中の「比べる絵」(接続プレビュー)

候補を狙っている間、虚無に **2 つの開口の実物大の枠**を並べ、**それぞれに人型を入れる**。

```
   入口(今いる扉)          出口(候補の門)
   ┌──────┐              ┌──────────────┐
   │  ▮   │              │              │
   │ ▮▮▮  │   ──▶        │      ▮       │   ← 同じ「埋まり方」になるので
   │  ▮   │              │     ▮▮▮      │      人型が【大きくなる】
   └──────┘              └──────────────┘
```

**同じ割合で埋まる** = ルール 4 そのもの。文字は 1 行も要らない。
人型は `models/game/figure.gltf`(原点=足元・高さ 1.0 で作り、scale で伸ばす)。

### B. 通った瞬間

白フェード + FOV の突き上げ(既存)に加えて、
**大きくなる時は視点が持ち上がりながら FOV が広がり、小さくなる時は沈みながら狭まる**
(0.45 秒)。音は既存の `pass.wav` をピッチで変える(`setVoicePitch`)。

### C. 常設の「今の自分の大きさ」

HUD に数字は出さない。代わりに **開口に近づくと、その開口の枠に自分の人型の影が立つ**
(入れる = 白、入れない = 赤で、体が枠からはみ出しているのが見える)。
**通る前に、通れるかが分かる**。(4) で唯一効いた「説明ではなく結果のプレビュー」の再利用。

### D. 部屋そのものが物差し

長椅子(0.95m) / ロッカー(1.95m) / 箱(0.75m) / 手すり(1.10m) は**寸法を変えない**。
大きさが変わったことは、**見慣れた物との対比**で分かる。什器は今後 **必ず各部屋に置く**。

# 実装したあとの追記(2026-09-02 実装完了時)

設計から変えたところと、実装中に分かったこと。**次に触る人はここだけ読めば足りる。**

## 設計から変えた 3 点

1. **敷居は 1.6m ではなく 0.9m。** 1.6m だと「大きさ 2 でないと届かない」になり、
   大きくなる理由にしかならない。0.9m にすると **「小さくなりすぎると届かない」** になり、
   縮小に代償が生まれる。ゲームが一方通行にならないのはこれのおかげ。

2. **大きさの梯子に 0.125 を足した。** 倍率は掛け算なので、変な繋ぎ方をすると梯子から
   落ちる(0.25 の体で 小口 0.5 に入って 通気口 0.25 から出ると 0.125)。
   一番下に受け皿を 1 段だけ置き、それより下は clamp する。
   **上の clamp は要らない**: 入る条件 `scale <= 入口` から `newScale <= 出口 <= 2` が必ず成り立つ。

3. **虚無の「比べる絵」は実寸ではなく【共通の縮尺 k を掛けて】並べる。**
   実寸のまま置くと門(高さ 5.2m)が開口の上縁に隠れて、**どれだけ大きいのかが見えない**
   (撮って初めて分かった)。**比だけ保てば意味は完全に伝わる。**
   入口の板は `Proxy_8`、候補は `Proxy_1..7`(開口は最大 8 なので候補は最大 7 = ちょうど足りる)。

## エンジン側で踏んだ地雷(README にも書いた)

- **シーンを開いた時点で存在しなかった entity は `scene:spawn` しても描画されない。**
  → 実行時に出す物は全部シーン JSON に置き、床下 y=-200 へ隠す。
- **CharacterController の寸法は実行時に変えられない。**
  → 大きさごとに `Body_0..4` を置き、使う 1 体だけ地上へ出す。
  `MainCamera` は Camera だけの別実体にした(こうすると transform を書けばそのまま効く)。
- **Play 直後は CC が物理世界に未登録で `physics:setPosition` が黙って効かない。**
  → 1 秒間押し込み直す + `y < -50` で置き直す保険。

## 検証で分かったこと

- 第1面の全経路(歩く → 扉 a → 門 b で 2 倍 → 柵を跨ぐ → 柱)は**実機で通し確認済み**。
- MCP の `dx12_key_press` / `key_down` は **`keyPressed`(エッジ)に効かない**。
  `isKeyDown`(W 移動)は効く。→ `saveNum("dbg_cmd",1)` / `saveNum("dbg_throw",1)` の
  フックを Junction.lua に残してある。人が遊ぶぶんには一切影響しない。

## まだやっていない

- **人に第1面と第2面を触らせる。** 合否は 1 つだけ:
  **部屋 G に出た瞬間に「自分が大きくなった」と口に出すか。**
  出なければ、そこで作り直す(調査: 「プレイヤーが理解しなかったら、それはあなたのせい」)。

# v4 (2026-09-02 夕) 【E を捨てて、歩いて解くゲームにした】

v3 は「E で虚無の候補を狙って繋ぐ」だった。**メニュー操作で、体で解く感じが無かった。**
操作を **WASD と SPACE だけ**にし、開口をくぐる・箱に跳び乗る・柵を跳び越える・
庇をくぐる、で進むゲームにした。

## 変えた 6 点

1. **接続はレベルが持つ。E は無い。** 開口は最初から繋がっている。
2. **大きさ = 出た開口ぴったり。倍率の掛け算は廃止。**
   ★v3 は同じ扉を往復するだけで 1 → 0.5 → 0.25 と縮み続け、**バグに見えた**(指摘された)。
   出た口ぴったりなら **往復すると必ず元に戻る**。ここが一番大事な修正。
3. **SPACE でジャンプ。跳べる高さ = 0.9 × 大きさ^0.7 [m]。**
   柵 1.15m は大きさ 2 でしか越えられず、木箱 0.70m は 1 で乗れて 0.5 では乗れない。
   小さいほど「体の何倍跳べるか」は増える(虫のように軽い)。
4. **手のモデルは廃止**(視界を塞ぐだけだった)。
5. **出口を作り直した。** 緑の細い柱 → **壁から独立して立つ扉**。
   中に枠が入れ子で 5 枚、奥へ後退していて、一番奥だけが緑に光る
   ＝ 外から見た奥行きより中の方が深い。**直接触れないとクリアにならない**(半径を絞った)。
6. **覗き箱(PeekBox)。** 開口に近づくと白い虚無の板が退き、**向こうの部屋が見える**。
   実体は開口の裏に作った浅い箱で、中に【行き先の開口が実寸で】立ち、行き先の什器と
   天井高が入っている。★**通る前に「自分がどの大きさで出るか」が分かる。**
   横から覗くと箱の壁が見えて嘘だと分かる。それでいい(リミナルの不安はそこから出る)。

## 「つなぐ」というテーマの答え = **継ぎ目(seam)**

WASD だけのゲームでは、ボタンで「繋ぐ」ことができない。
だから **繋ぐことを、移動の結果ではなく【体当たり】という動作にした。**

> **床に立った未完成の枠が 2 つある。体当たりすると、2 つが同時に
> 【その時の自分の大きさ】の口になって開く。**

- 開いた継ぎ目は普通の開口と同じ。くぐると**刻んだ大きさ**で向こうに出る。
- **何度でも刻み直せる**(自分が今いる側からなら必ず届く) = 詰みが無い。
- ★これが**新しい能力**になるのが肝: 部屋 A では絶対になれない大きさを、
  なれる部屋 S で刻んで **A へ持ち込める**。第4面以降のパズルは全部これ。

つまり **「つなぐ」= 自分の大きさを、行けなかった場所へ運ぶこと。**
タイトルの「継ぎ目」がそのままプレイヤーの動詞になった。

## 8 面

| 面 | 教えること |
|---|---|
| 1 | くぐると大きくなる／柵を跳び越える(接続は最初から張ってある) |
| 2 | 跳ぶ／小さくなると庇をくぐれる |
| 3 | 大きくなって柵を跳び越える(往復して元の大きさに戻れることも分かる) |
| 4 | **継ぎ目**。A では 2 になれないので、S で 2 を刻んで持ち込む |
| 5 | 今度は 0.5 を刻む(庇の向こうが出口) |
| 6 | **刻み直す**。柵と庇が両方ある |
| 7 | 大広間 |
| 8 | 総合。第1面の部屋と柵が戻ってくる |

## 実装で踏んだこと(追加)

- 継ぎ目の板は**当たり判定を持たせる**。持たせないと、刻んだ直後にそのまま
  歩き抜けてしまってテレポートが起きない(実際にそうなった)。
- 刻まれていない継ぎ目も**はっきり見える大きさで置く**。小さく置くと壁の染みにしか
  見えず、そこへ行く理由が生まれない。
- ジャンプは `keyPressed` ではなく `keyDown`(押しっぱなしで連続ジャンプ)。
  やり直しが軽い方がプラットフォーマーとして素直。

   押しても何も起きないボタンは、チュートリアルの邪魔にしかならない。

   **気づいたら部屋が違う**(Layers of Fear)。だから境目を一切作らない。
   ★あわせて**覗き箱を「行き先の部屋の実寸そのまま」**にした。
   7m の浅い箱だと、くぐった瞬間に壁の位置が変わって切り替わりがバレる。

   `(部屋, 区画, 大きさ, 継ぎ目の刻み)` を状態にして幅優先探索する。
   「開口を 1 つもくぐらずに出口へ着ける」面が**実際に 2 面あった**(第6・第7面)。
   最短手順を印字するので、意図した解き方になっているかも一目で分かる。
4. **チュートリアルを厚くした。** 案内の光(Pilot)を復活させ、
   序盤は常に、それ以降も**15 秒何もしていない人**には出す。
   刻まれていない継ぎ目があれば最優先で指す(それが動詞だから)。

     刺さらない構図は `check_cine` が生成時に保証しているので、実行時の小細工は廃止。
   - **演出の終点と実際の視点がずれていた** → 最後の 1 手を必ず

# v4.2 — 「気づいたら大きくなってる」が成立するまで

前回「演出を消した」だけでは全く足りなかった。**指摘は正しかった。** 原因は 4 つ重なっていた。

## 1. 立ち位置と向きが飛んでいた

出口の **2.3m 手前に、開口の正面を向いて**置き直していた。
＝ くぐった瞬間に立ち位置も向きも別物になる。これが「かくっ」の一番大きな成分。

→ **ポータルと同じ姿勢の引き継ぎ**にした。
「入口の外向き」を「出口の内向き」へ重ねる回転で、位置・向き・**上下の向き**を全部写す。
離れ方は大きさの比 `ns/old` を掛ける。開口の面に居たまま向こう側へ出るので絵が繋がる。

## 2. 向こうの部屋を 1:1 で描いていた ← ★本命

**向こうの部屋は「自分がそこで何倍になるか」の比で描かなければならない。**
扉(1) から 門(2) へ行くと自分は 2 倍になるので、向こうの部屋は **半分**で描く。

これは目を中心とした相似変換なので、**くぐる前の絵とくぐった後の絵は数学的に完全に一致する**。
1:1 で描いていた頃は、くぐった瞬間に部屋が半分になって「切り替わった」と分かってしまっていた。

覗き箱の縮尺 `k = 今の自分の大きさ / 出口の開口の大きさ` を **Lua が毎フレーム**掛ける。

## 3. 目の高さを 0.35 秒かけて補間していた

2 の通り、前と後の絵は同じ。**同じ絵の間をわざわざ揺れていた**のが「かくっ」の残り。
→ 補間をやめ、そのまま切り替える。

## 4. 覗き箱が空っぽだった

# v4.2 — 跳び越えられてしまう問題

**「跳べる高さ」だけで設計していたのが間違い。**
CharacterController は着地寸前に `stepHeight` ぶん自動で乗り上がるので、
実際に登れる高さは **跳べる高さ + 段差**。大きさ 1 でも 0.9 + 0.6 = 1.5m 登れていて、
1.15m の柵を素通りできた(＝「扉を使わなくても行けちゃう」)。

```
climb(s) = 0.9 * s^0.7 + 0.25 * s     0.25 -> 0.39 / 0.5 -> 0.65 / 1 -> 1.15 / 2 -> 1.96
柵 1.35m      : 大きさ 2 だけ越えられる
木箱 0.70m    : 大きさ 1 で乗れて 0.5 では乗れない
庇の隙間 1.0m : 体高 1.8*s < 1.0 = 大きさ 0.5 以下だけ
```

- **段差を 0.6*s -> 0.25*s**、**柵を 1.15 -> 1.35m** にした。
- **庇を「下だけ 1.0m 空いた壁」に作り直した。** 以前はスラブと脚だけで、
  大きさ 2 なら上に跳び乗って越えられた。
- **シミュレーションを実際の式(climb)に合わせた。** 以前は跳躍力だけで判定していたので、
  この抜け道を検出できていなかった。
- **踏み台チェックを足した。** 長椅子(0.95m)の上からだと 大きさ 1 でも 2.1m まで届くので、
  柵の近く 3m に踏める什器を置けないようにした(★柵だけ。庇には効かない)。

### 設計の柱: 部屋を増やさず【同じ部屋を何度も違う大きさで通る】
