## 仕掛け（1 つだけ）

焦点 **F**（目の高さ 1.70m の 1 点）から見たとき、破片は本物と**完全に同じ形に重なる**ように置いてある。
置き方は F 中心の相似変換 1 本:

```
P' = F + k (P - F) ,  scale' = k · scale        (0 < k ≤ 1)
```

ずれの尺度は「対応点への視線の角度差の最大値（度）」。F に立つと 0 になり、離れるほど増える。

* `lock` 度未満を **0.28 秒** 保ち、かつ継ぎ目の中心が視野 26° 以内にあれば確定
* 確定すると破片は k → 1 へ **一瞬で**飛ぶ。**そこで初めて当たり判定が付く**
  （未確定の破片は素通りできる ＝「まだ実体ではない」が触っても分かる）

## しれっとつながる（2026-09-06 の作り直し）

**つながる演出は全部やめた。** 環（合い具合の HUD）・近づく合図の音・確定音・粒子・
継ぎ目の光の増減・ドローンの音程 — 一つも残っていない。
合っているかどうかを伝えるのは **破片そのものの重なり** だけ。画面の中央は最後まで空。

仕掛けの肝は、**確定の瞬間に画面が 1 ピクセルも変わらない**こと。
焦点から見た k 倍の破片と本物は投影が完全に一致しているので、k を 1 へ飛ばしても見えない。
だから「合った瞬間」は無い。歩き出して初めて、床があることに気づく。

目に見える変化（扉が開く・塞ぎ板が消える・標識が点く）は 2 通りに分ける:

* **その継ぎ目が視界の外（`AWAY=60°` を `AWAY_T=0.12s`）** … 一度に置く。どうせ見えないので
  一番きれい。振り返るともう開いている ＝ 変化の見落とし（change blindness）
* **見られている** … `FORCE_T=0.5s` 後からイージングで動かす。音も光も粒子も足さない。
  扉は扉の速さで、静かに開くだけ

### ★★ここを間違えた（2026-09-06 に 2 つ同時にやらかした）

最初は「視界の外に出るまで待つ・出たら**瞬間移動**」だけにして、保険を **6 秒** にしていた。
これが両方とも致命的だった:

1. **「解いたのに扉が開かない」** — 扉へ向かって歩く間、プレイヤーはずっと扉を見ている。
   だから `away` が一生溜まらず、**6 秒間ドアが閉じたまま**になる。実測で確認:
   焦点（z=6.4）で継ぎ目1 を確定 → 扉（z=14）まで歩ききっても `C1_Panel` は閉位置 1.10 のまま
2. **「急にカクッとなってはまる」** — 待たされた末に塞ぎ板が瞬間移動して消えるので、
   **板に体を押しつけた状態でいきなり支えが無くなり、前へつんのめる**

直し方は「**待たせない・カクッとさせない**」の 2 点セット:
`FORCE_T` を **0.5 秒**にして、見られている時は **smoothstep のイージング**で動かす
（`runTweens` / `runSwings` / `runLamps`）。
★当たり判定は **動き出す瞬間に外す**こと。先に外すと閉じた板をすり抜け、
最後まで残すとつんのめる。

イージングは「つながる演出」ではない — 音も光も粒子も無い。
**瞬間移動でカクッとさせないためだけ**にある。

**幾何の性質（設計上の重要事項）**: 角度差は視線に対して**横方向に敏感・奥行きに鈍感**。
1 点というより「F を通る 1 本の線」の上が正解になる。だから確定域は「細長い帯」になり、
プレイヤーの仕事は**左右の立ち位置を合わせること**になる。これを踏まえて焦点は
**廊下の中心から少し外して**置いてある（中心に置くと真っ直ぐ歩くだけで勝手に解ける）。

## ★規則は 1 つではなくなった（2026-09-06 の 3 回目の作り直し）

「解き方がずっと繰り返しで飽きる」という指摘に対して、**相似変換 1 本で押し通すのをやめた**。
いまは 5 つの規則がある。どれも「見たものが、そうなる」の枠内だが、**探し方がまるで違う**。

| 規則 | 成立条件 | 手触り |
|---|---|---|
| A **相似**（既定） | 焦点 F から見て破片が本物と重なる | 立ち位置を探す（継ぎ目 1〜16） |
| B **触れる** | 2 点が【画面の上で重なる】。焦点を使わない | 奥行きに寛容・向きに厳しい。遠くの柱と手前の板を一直線に並べる |
| C **巡る** | 破片ごとに別の焦点。1 枚ずつ実体化する | 一箇所では終わらない。歩き回って組み上げる |
| D **直視しない** | 継ぎ目が周辺視（24〜68°）にある時だけ | 正面に据えると**絶対に決まらない**。目を逸らしたまま合わせる |
| E **暗の一瞬** | 明滅する照明が暗い間だけ | 位置を合わせてから、暗くなる瞬間を待つ |

規則 B〜E は `Conn(..., touch=/per_shard=/peri=/dark=)` で切り替える。
`shard(k, ents, focus=...)` で**破片ごとに焦点**を持てる（C と「二つ同時」に使う）。

★★**距離の足切りは規則ごとに要る**。相似規則に `FOCUS_LOCK` を入れたのと同じ理由で、
触れる規則にも上限が要る（角度差は距離に反比例するので、**遠ざかると 2 点が勝手に重なる**）。
入れ忘れて、ステージの反対側 **240m 先から継ぎ目19 が確定した**。

★北の橋と出口の階段は **x をずらす**こと。同じ x に重ねると、組み上がった階段が橋の真上に来て
**橋の頭上が 1m しか空かず通れなくなる**（机上検査の頭上判定で捕まえた）。

**7/8 の数学**: 浮遊姿 D を 2 通りに解釈させるには `D = F + k(X - F)` を 2 組み満たせばよい。

「西に立つと東の橋、東に立つと西の橋」という交差が自然に出てくる（狙って作ったのではなく、式がそう言った）。

## 第五幕 — 環の間（継ぎ目 22〜25 / 2026-09-07 追加）

「解き方が一緒」「すぐ解けて難しさがない」「橋と扉ばかり」への答え。数えると、
21 本のうち **扉/戸口が 5・橋/渡り板が 10** ＝ 15 本が同じ 2 種類の結果だった。
しかもどれも **一問一答**（印に立って見る → その場で終わり）で、継ぎ目どうしに関係が無い。

第五幕は **扉も渡し板の橋も 1 つも出さず**、継ぎ目どうしを **連鎖**させる。
広さは 34 x 44m（ここまでで最大）、中央に部屋の全幅を横切る深さ 6m の井戸。

| # | 規則 | 何をするか | 確定域 | 結果 |
|---|---|---|---|---|
| 22 | **F かくれて合わせる**（新） | 偽の板が見えている限り決まらない。**柱の陰に入れて隠す** | 1.80 m² | 井戸に**床が閉じる** |
| 23 | **A + 投影の分離**（新） | **床に落ちた影**に浮遊物をはめる。目標が初めて目に見える | 3.19 m² | 影の場所ではなく、その先に**段**ができる |
| 24 | **A + 偽の印 + 連鎖** | 印が 3 つ。2 つは嘘。22/23 を解いて**棚の上**に立たないと成立しない | 1.17 m² | 北壁から**片持ちの段**が生えて踊り場へ |
| 25 | **A×4 + E + 連鎖**（仕上げ） | 1 点で**北・南・東・西を同時に**満たし、さらに**明かりが落ちる 1 秒**を待つ | 0.76 m² | **北壁が割れて開く** |

* **規則F「かくれて合わせる」** は新しいランタイム規則。`occl = dict(p=[点], boxes=[[箱]])` で、
  **目 → 点の線分が箱を通っている間だけ**成立する。机上検査 `sim_liminal.occluded` と
  ランタイム `hidden()` は同じ式にしてある（片方だけ入れると、机上で測る確定域が実際より広くなり、
  床の目印が「印の上なのに繋がらない」場所に置かれる）。
* **床の影**（`floor_shadow()`）は破片の浮遊姿勢を焦点から床へ投影したもの。
  これまでの継ぎ目は目標が一切見えず「浮き方」だけが頼りだったので、探し方がまるで変わる。
  ★影どうしは必ず重なる（階段を真上から見れば帯が重なる）ので、高さを 12mm ずつ変える
  （机上検査 [6] の許容は 6mm）。
* **連鎖**は `needs` に加えて、**焦点そのものを前の継ぎ目が作った足場の上に置く**（`minY/maxY`）。
  順番に解かないと立てないので、机上検査の「解く前は行けない」がそのまま順序の検査になる。
* ★**塞ぎ板は破片にしない**。出口の板を破片にすると、当たり判定が付くのは確定した後なので
  **解く前に出口を通り抜けられる**（机上検査で捕まえた）。塞ぎ板は最初から実在させ、
  確定したら沈める（この作品の既存の作法どおり）。
* ★**浮遊中の破片が柱を突き抜けていた**（k=0.40 で 7cm）。遮蔽に使う柱の近くへ破片を
  浮かせる時は、k を上げて柱の向こうへ出すこと。
* ★**偽の板は浮遊中の破片と同じ見かけにする**。原寸で置くと一目で別物だと分かってしまう。

### 難しさの決め方（較正ツールの上書き）

`calib_marks.py` は「印の上ならどこに立っても繋がる」を絶対条件にして lock を決めるので、
放っておくと **印を大きく取るために lock が緩み、確定域が広がって易しくなる**
（継ぎ目24 は一度 6.57m² まで広がり、「どの印でも解ける」＝ 偽の印の意味が消えた）。
仕上げの数問は `MIN_MARK_BY` / `MIN_WL_BY` で **小さくても本当の印**を許して締める。
締めるための地の設計は「**近い対象を 1 つ混ぜる**」＝ 角度は距離に反比例するので、
遠い対象だけだと鈍く、近い対象が 1 つあるだけで確定域は一気に締まる。

## 踏んだ罠（次に触る時に効く）

### ★★床の目印は機械で決める（`source/calib_marks.py`）

第一幕の 2 つを手で直した後、第四幕でも同じ事が起きていた（島の印 1.5m 四方のうち
繋がるのは **10〜19%**、継ぎ目20 に至っては **6%**）。手で測って直すやり方は続かない。
いまは **全部の印を機械が決める**:

```
python source/calib_marks.py            測って表示するだけ
python source/calib_marks.py --write    gen_liminal.py の LOCKS / SOFT / MARKS を書き戻す
python source/gen_liminal.py            シーンを作り直す
```

「**印の上ならどこに立っても繋がる**」を絶対条件にして、2 つの軸で探す:

* `SOFT` … 破片のずらし量 `k' = 1 - (1-k)·soft`。1 へ寄せるほど勾配がなだらかになり、
  **lock を緩めずに**確定域が広がる。ただし浮き方が控えめになるので **0.72 が下限**
  （継ぎ目5 の k=0.16 は soft 0.4 で 0.66 になり「極小」に見えなくなる）
* `LOCKS` … 許容角。soft で足りない時だけ譲る

結果は `docs` ではなく `gen_liminal.py` の表が正。机上検査の **[5] 床の目印** が
「印の上ならどこでも繋がるか」を毎回見張るので、lock をいじっても嘘の印は残らない。

★較正ツール自身で踏んだ罠が 2 つある。どちらも**同じ形の間違い**:
1. **測る前に元の k へ戻す**こと。`gen_liminal` は既に SOFT を通した形を作っているので、
   そのまま測ると「もう弱める必要なし」と誤判定して表が空になり、勾配が元へ戻る
2. **破片の干渉は部品ごとに見る**こと。破片の外接箱でまとめて見ると、階段のように
   互い違いに置いた破片は弱めていなくても必ず重なり、全部の候補が弾かれる

### ★★床の目印は【確定域の形】に合わせる。四角い印は嘘になる

「印の上に立っても全然つながらない」と言われて測ったら、第一幕の斜めの橋（継ぎ目2）は
**1.6m 四方の印のうち 11% しか当たっていなかった**。確定域は橋の方向へ伸びた
**幅 26cm の斜めの帯**で、印はその上に四角く被せてあっただけだった。
継ぎ目1（最初の戸口）も同じで **13%**。

確定域は「点」ではなく **F と対象を結ぶ方向へ伸びた細長い管**（横に敏感・奥行きに鈍感）。
だから印は必ず

* **帯の向き**に合わせて回す（継ぎ目2 は yaw 40°）
* **帯より小さく**する（印が確定域からはみ出た瞬間に「印の上なのに繋がらない」になる）

判定を締めた回に lock を 1.4 → 0.7 まで落としたのが直接の引き金だった。
**判定を締めるときは、必ず印との被覆率を測り直すこと。**

| | 直す前 | 直した後 |
|---|---|---|
| 継ぎ目1 | lock 1.3° / 印 1.5×1.5 四角 / 被覆 **13%** | lock 2.0° / 印 0.55×1.10 / 被覆 **100%** |
| 継ぎ目2 | lock 0.7° / 印 1.6×1.6 四角 / 被覆 **11%** | lock 2.0° / 印 0.80×2.30 を 40° 回転 / 被覆 **100%** |

広げ方は lock を緩めるだけでなく **k を 1 へ寄せて勾配をなだらかにする**のが効く
（継ぎ目2 は `(1.0, 0.72, 0.53, 0.40)` → `(1.0, 0.80, 0.64, 0.52)`。
同じ角度の許容でも確定域が 3 倍になる）。浮き方は少し控えめになるが、
「印の上ならどこでも繋がる」方がはるかに大事。

★机上検査の「広すぎる」上限は 1.80 → **5.00 m²** へ緩めた。`STILL`（1.10m/s 以下でないと
確定しない）を入れた時点で、広い ＝ 歩いていて勝手に確定する、ではなくなっている。

### ★★「くっついたのがすぐ分かる」対策 = 変化の見落としを実装する

破片を実体へ寄せる瞬間は、**視線が動いている / 歩いている**のどちらかが成立するまで待つ
（`MASK_TURN=55°/s` / `MASK_MOVE=1.2m/s`、上限 `WELD_WAIT=0.45s`）。人間はその間の
局所的な変化をほとんど検出できない（サッカード抑制・change blindness）。
寄せ方も瞬間移動ではなく `WELD_T=0.18s` のイージング。
プレイヤーは合わせて、歩き出して、**気づいたら足場がある**。

判定そのものも締めた: `DWELL` 0.28 → **0.36 秒**、さらに **`STILL=1.10m/s` 以下**でないと
確定しない（通りすがりで決まらない）。lock も測り直して確定域を **0.16〜0.52 m²** に揃えた
（以前は 0.22〜1.42 m² とばらついていて、広い所は「合っていないのに決まる」＝ガバガバだった）。

★★**目に見える変化は、破片が寄り切ってから始めること**。先に始めると塞ぎ板やシャッターが
【浮遊姿勢のまま】動き出して「急にでっかくなって変な所へ飛ぶ」ように見える。
`pending` の適用条件に `全ての破片が done` を足してある。

### ★★破片を動かす mover は【実体の座標】から作る（シャッターが巨大化するバグ）

`c5.mover(p, (p["transform"]["position"] + 上へ 4.35m))` と書いていたが、
`p` は既に `shard()` が **k=0.16 に縮めた後**の座標だった。結果、確定して原寸に戻った板が
**10m 手前の宙へ飛ぶ** ＝「シャッターを開けるとモデルがでっかくなる」バグ。
→ `Conn.mover_by(e, (dx,dy,dz))` を使う（`real_pos()` から作る）。丁番と同じ罠。

### ★★丁番が「焼き込んだ座標」を使っていた ＝ 扉が飛んでから回る（2026-09-06 に修正）

`Conn.hinge()` は `e["transform"]["position"]` をそのまま焼き込んでいた。ところが扉板は
**破片でもある**ので、その値は `shard()` が縮めた後の座標だった。結果、確定して扉が開く瞬間に
**扉が 3m 手前・17cm 上へ飛んでから回る**（継ぎ目 4 で実測: 実体 (6.100, 4.500, 79.800) に対し
焼き込み値は (5.946, 4.668, 76.832)）。これが「ドアの開閉がおかしい」の正体。

直し方は 2 段構え:
1. **実行時は焼き込みを使わない**。`openDoor()` が **その場の transform** を読んで丁番まわりに回す。
   確定時点で破片は既に k=1 へ戻っているので、これが常に正しい閉扉姿勢になる
2. 生成側の `Conn.hinge()` も `Conn.real_pos()`（shards の記録から実体位置を引き直す）を使う。
   焼き込み値は机上検査と目視デバッグ用

★基準回転も足し込むこと（`rotation.y + deg`）。上書きすると、壁向きに yaw を持った扉が横を向く。
★エンジンの yaw は行ベクトル系なので `(x,z) -> (x cosθ + z sinθ, -x sinθ + z cosθ)`。
  符号を間違えると扉が壁側へ開く。

### ★破片は目の近くに置かない（確定域が消える）

継ぎ目 12 の最初の板を k=0.30 で置いたら、破片が **目から 0.66m** の位置に来た。
近すぎる破片は首を少し振るだけで見かけが暴れるので、確定域が 0.02m²（1 マス）まで潰れる。
**一番手前の一枚を「最初から実在する踏み板」にして破片を遠ざける**と 0.38m² まで回復した。
おまけに「何を組もうとしているか」の見本にもなる。
