## 1. 何が間違っていたか

v5〜v9 の仕掛けは**全部「自分の大きさが変わる」の言い換え**だった。

| v9 までの装置 | 実際に起きること |
|---|---|
| 継ぎ目(先細りの廊下) | 大きさが変わる |
| 大きさの門(sizegate) | 大きさが変わる |
| 連続スケール場(field) | 大きさが変わる |
| 背後改変(morph) | 家具が動く |
| 偽の廊下(fake) | 絵が嘘 |

**大きさが変わるのは錯覚ではない。**プレイヤーは 3 回目でルールを学習し、以降は驚かない。
指摘の「ガリバートンネルと同じ」はそのとおりで、**世界は最初から最後まで
ユークリッド空間のまま**だった。部屋の並びは正しく、歩いた距離と方角は嘘をつかない。

## 2. v10 の原理 —【つながり方そのものを嘘にする】

> **継ぎ目の向こうは、こちら側から見えていた場所とは限らない。**

大きさはほとんど動かさない。代わりに**部屋の位相(どこがどこに繋がっているか)**を壊す。

これが「気づかないうちに錯覚する」の条件を満たす唯一の設計だと考えた理由:

- 目の前で何かが**変わらない**。だから見ていても気づけない
- 壊れるのは**プレイヤーが勝手に作っている心の地図**だけ
- 気づくのは「東へ 40m 歩いたのに、ホールの**西側**に立っている」時 =
  **自分の記憶の方を疑う**。これが「脳がバグる」の正体

## 3. 新しい装置

### 3-1. ★継ぎ手(port / link) — 中心装置

口の奥は **4.2m の暗い筒**で、両端の筒は**寸法も材質も灯りも同じ**。
筒の**真ん中(2.1m)**の面を越えた瞬間に、相手の筒の同じ横位置・同じ姿勢へ置き換える。

```python
PORT("a_e", "A", wall="E", off=-17.0)      # 壁に開ける
PORT("a_u", "A", at=(-14.0, -10.0), into="E")   # 部屋の中に単体で立てる(joint.gltf の筐体)
JOIN("a_e", "b_w")                          # 両通行
LINK("i_n", "i_s", times=2)                 # ★最初の 2 回だけ別の所へ出す
LINK("i_n", "a_n")                          # 3 回目からこちら
```

★**なぜ「筒の真ん中」なのか(実測で決めた)**

転送の瞬間に見えているのは「筒の奥にある面」だけ。その面までの距離が
**入る側(奥の板まで `D-P`)と出る側(向こうの口まで `P`)で違うと、
画角が変わって切り替わりが一目で分かる。**

| 設定 | 実測 |
|---|---|
| D=2.0 / P=1.55 | 転送直後に向こうの部屋が**画面の 7 割**。誰でも気づく |
| D=4.2 / P=2.1 | 前後とも **2.1m 先の同じ大きさの長方形**。変わるのは中身の明るさだけ |

`P = D/2` にすると、前後で**位置も大きさも同じ長方形**になり、絵としては
「奥のシャッターが開いた」にしか見えない。

★**それでも残る明るさの落差は、画面を暗くして消す**(`Junction.lua` の `portDark`)。
転送面に近いほど画面を落とす。**暗い筒の中でさらに暗くなるだけなので演出としては見えない**。
位置で決まるので**引き返しても同じように暗くなる** = 仕掛けだと気取られない。

★**筒は真っ黒にしてはいけない。** 0.03 まで落としたら「転送前は暗黒 / 転送後は部屋の光で灰色」
になり、**明るさの落差そのものが切り替わりを教えた**(実測)。薄暗いが見えている(0.072)が正しい。
両端の筒は同じ物なので、見えていても区別が付かない。

★**横の余裕(MG)は 0 に近くすること。** 0.3 も空けると口の縁と筒の側壁の間にポケットができ、
斜めから見ると**そこから母屋の明るい壁が覗く**(実測)。

### 3-2. ★エイムズの部屋(ames) — 本物の目の錯覚

理想の直方体の 8 隅を、覗き穴 V から伸びた直線の上で `s = 1/(1 + α·横位置)` 倍する。
**同次座標では線形 = 射影変換**なので、次の 2 つが同時に成り立つ:

- **面は面のまま**(床も天井も壁も平面 → 当たり判定は傾けた板 1 枚ずつで厳密に置ける)
- **V から見た絵は理想の直方体と 1 画素も違わない**

左奥は 1.46 倍遠くて 1.46 倍大きい。そこへ**左右まったく同じロッカー**を置くと、
**左は小さく右は大きく見える**。このゲームは「什器は絶対寸法 = 唯一の物差し」で
組んであるので、**その物差しが嘘をつく部屋**になる。

★**歪めた床は必ず水平へ戻すこと。** 射影で歪んだ床は「戸口から奥へ伸びる線」を軸に
7 度傾いた平面になる。そのままだと**戸口の左右で床が 60cm 食い違い、壁の下に
虚空へ抜ける隙間が空く**。その軸まわりに転がして水平へ戻せば母屋の床とぴったり繋がる
(覗き穴が 21cm 横へずれるだけ。立体視の無い一人称では誰にも分からない)。
`check_ames` が床の水平を 2cm 以内で検査する。

### 3-3. 見張り(watchers) — 視界に入っている間は 1mm も動かない

動く瞬間が**存在しない**ので「動いた」とは絶対に思えず、「さっきと違う」としか感じない。
目を離した回数だけ近づき、`near` で止まる。

★**止まる距離を 1 体ずつ変えること。** 全部同じだと全員が同じ輪に並んで仕掛けだと分かる。
★**近すぎる(2m)と板が画面を埋めて何なのか読めない**(実測)。5〜7m が良い。
★人型は**暗く塗る**(`scene:setColor`)。白いままだと暗い倉庫で一番明るい物になる。

### 3-4. 忍び寄り(creeps) — 歩いた分だけ天井が下りる

速さを**歩く速さに縛る**ので「動いている物」としては見えない。
★進み具合は**戻らない(ラチェット)**。引き返しても元通りにはなっていない。
第3面では長廊の天井が 1.9m 下りる。**輪(times=2)と組むと、2 周目は最初から低い**。

### 3-5. 傾き(rolls / room tilt) — 平衡感覚

- `rolls` … 歩く位置で**視界だけ**を転がす(FreeLook が `camRoll` を読む)。1 秒あたり 2 度以下なので、傾いていく最中は見えない
- 部屋の `tilt` … 部屋の**全部**(床・壁・天井・什器・照明・当たり判定)を歩く向きの軸まわりに転がす

両方を同じ角度(9 度)にすると、**部屋は水平に見えるのに体だけが横へ流れる**
(実測: 5 秒立っているだけで 0.36m 西へ滑る)。錯覚小屋(Mystery Spot)と同じ状況。

★**転がす軸は「入る壁の法線」にすること。** その向きなら南北の壁は自分の平面から出ない。
口は大きめ(hole=1.4)に開けて**水平な襟(collar)**で塞ぐ。
→「建物は傾いているのに継ぎ手だけが水平」という絵になる。
★襟の板は `HW - w/2` を **`(HW + w/2)/2` に置く**。`(w + HW)/2` に置くと口の縁との間に
隙間が残って虚空が覗く(v10 開発中に踏んだ)。

## 4. 面 —「継ぎ目の館」1 面だけ(`stagedemo3`)

部屋 7 つ + 別棟 1 つ。世界座標では互いに 60〜100m 離れているが、
継ぎ手で繋いであるのでプレイヤーには**ひと続きの施設**に見える。

| | 部屋 | 寸法 | 装置 |
|---|---|---|---|
| A | 受入ホール | 40 x 40 x 14 | 幅 14m の谷 / 柵 / ドリーズーム / 背後改変 |
| B | 仕分け廊 | 36 x 9 x 5 | 届かない扉(角度固定) |
| D | 機械室 | 26 x 26 x 9 | 偽の廊下(強制遠近法) |
| E | (別棟) | 9 x 15 x 5 | **エイムズの部屋** |
| F | 傾斜廊 | 9 x 30 x 4.4 | 視界が 9 度転がる |
| G | 傾いた部屋 | 16 x 16 x 6 | **部屋ごと 9 度傾いている** |
| H | 保管庫 | 22 x 16 x 5.5 | **見張り 5 体** |
| I | 長廊 | 9 x 30 x 4.4 | **輪(3 周)+ 天井が 1.9m 下りる** |

### 間取りが全部を決めている

- **柵(z=-13, 1.7m)** … 始まりの帯を閉じる。跨げるのは x2 だけ = 一生跨げない
- **谷(z=0, 幅 14m)** … 跳べない。出口はこの向こう

**最初の 10 秒で「見えている物は全部、歩いては行けない」が分かる。**
出口の門も、機械も、谷の向こう岸も、全部見えている。

### 道筋(総当たり検査もこの 8 手を確認している)

```
A(始まりの帯) → a_e → B の西
B を東へ 36m  → b_e → ★A の西側(柵の向こう)  ← 東へ歩いて西に出る
A の機械      → a_u → D 機械室(2.9m の機械の中が 26m の部屋)
D の北        → 別棟 E(エイムズ)→ e_x → F
F(視界が傾く) → f_n → G(部屋ごと傾いている)
G             → g_n → H(見張り)
H             → h_n → I 長廊
I を三度歩く  → i_n → ★A の谷の向こう岸 → 出口
```

★**オチ**: 最後の継ぎ手を抜けると、**最初のホールの谷の向こう岸**に立っている。
振り返れば、自分が立っていた場所と、入っていった機械が、谷の向こうに見える。
**一度も谷を渡っていないのに。**

### 折り返しを必須にした方法

「東の戸(a_e)を通らずに機械(a_u)へ行けてしまう」と装置が半分飛ばされる。
**柵と谷を同じ軸(z)に並べる**と、ホールが 3 本の帯に割れる:

| 帯 | z | 中身 |
|---|---|---|
| 始まりの帯 | -20 〜 -13 | 出発点 / a_e |
| 中の帯 | -13 〜 -7 | a_w(折り返しの出口) / a_u(機械) |
| 向こう岸 | 7 〜 20 | 出口 / a_n |

柵も谷も**跨げない**ので、中の帯へ入る道は a_e → B → b_e だけになる = 折り返しが必須。
★**柵と谷を違う軸に置いてはいけない。** 柵は部屋の全幅に張るので、谷を横切って
**虚空の上に柵が浮く**。同じ軸なら交差しない。

## 6. 見た目(施設に見せるために足したもの)

- **床をコンクリートに**(`R(..., floorMat="concrete")`)。カーペットのままだと事務所に見える
  ★**廊下(tunnel)の床も同じ材質にすること。** 偽の廊下だけカーペットだったので、
  **床の色だけで偽物だと分かった**(実測)
- **見通せる柵(`fence.gltf`)**。v9 の `barrier` は塞いだ板で、40m のホールに置くと
  **視界の下半分が全部その板になり**「見えているのに行けない」という設計が成立しない。
  ★白い壁の前に白い柵を置くと**見えない**。濃い材質にして黒く浮かせる
- **新しいモデル**: `joint`(継ぎ手ユニットの筐体) / `jframe`(継ぎ手の枠) /
  `rack`(棚 2.40m) / `drum`(ドラム缶 0.88m) / `sign`(吊り標識) / `fence`
- **露出を面ごとに落とせるように**(`exposure`)。灯り 25 個の 40m ホールは 1.0 だと床が真っ白に飛ぶ

## 7. 踏んだ罠(v10 で新しく増えたもの)

- ★★**転送の見え方は「奥の面までの距離」で決まる。** 入る側と出る側で違うと一目で分かる。`P = D/2`
- ★★**筒を真っ黒にすると逆に目立つ。** 明るさの落差そのものが手掛かりになる
- ★**Blender のモデルを `build_divider()` の中に足すと出ない。** `run_kit.py` は
  `JX_MANIFEST_ONLY=True` で回るので、`build_all/build_rooms/build_divider` は**丸ごと飛ばされる**。
  新しいモデルは `build_v10()` に置くこと(fence がこれで 2 回消えた)
- ★★**モデルが存在しないままシーンを開くと、そのエンティティは丸ごと落ちる。**
  再生成 → Blender → **シーンを開き直す**の順を守る(`reload_assets` だけでは戻らない)
- ★**継ぎ手の口には扉板を立てない。** `wall_model` は全部の door 開口に扉板を置くので、
  継ぎ手が「開きっぱなしの扉の奥の穴」になる(`self.noleaf`)
- ★**部屋の全体を回すときはグループの目印(marker)を動かさない。** 子が付いて回る
- ★**エンジンの Transform は行ベクトル・ZXY 順**(`Rz(z)·Rx(x)·Ry(y)`)。
  傾けた板や傾けた部屋は**行列で組んでから分解する**。三角関数を手で展開すると必ず規約を取り違える
- ★**Play 直後は開幕カメラ(cine)が回っていて OnUpdate が早期 return する。**
  MCP から仕掛けを試すときは**先に 400 フレーム進めてから**でないと「動かない」と誤診する
