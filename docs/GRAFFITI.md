# 壁の落書き（終盤 9 枚 + 第二幕の白い部屋 1 枚）— 2026-09-09

**「先に来た誰かが、解き方を壁に書き残していった」**

第一幕（3 枚）と第三幕（5 枚）には**額縁つきの案内板**がある。
終盤（第四幕 5 本・第五幕 4 本）には何も無く、しかも規則が毎回違うので、
初見では取っ掛かりが 1 つも無い。そこへ **絵だけの落書き 9 枚**を壁へ直接書いた。
**あとから第二幕の「白い部屋」（継ぎ目 10）にも 1 枚足して、合計 10 枚**。

* **文字・数字・記号文字は 1 つも使っていない**（この作品の大原則）
* 語彙は既存の案内板と同じ ── 棒人間 / 目 / 破線の視線 / 足跡 /
  **実線 = 本物・破線 = まだ無い** / × / 太い矢印（「こうなる」）
* **答えは描かない**。座標も、どの印が本物か（継ぎ目 24）も描かない。
  描くのは「**どこに立ち・どこを見て・何が何に重なるか**」だけ

## 3. 決まりごと（外すと壊れる）

### 3.1 ★向きは Blender 側だけで直す（180 度）

落書きは箱プリミティブの **-Z 面**へ貼る。このエンジンの箱の -Z 面は
`u` が -x 向き・`v` が上下逆なので、貼った絵は**見た目 180 度回る**。
`source/ui_icons/build_signs.js` の `ROT180` とまったく同じ理由。

`blender_graffiti.py` では**カメラを視線まわりに 180 度回して焼いている**
（`ROT180 = True`）。**gen_liminal.py 側では辻褄合わせを一切していない。**
両方でやると元に戻るので、**逆さまに見えたら `ROT180` を False にする**、片方だけ。

### 3.2 ★★下端は「真下の歩ける面 + 1.80m」より上（見えない壁の罠）

`add_walk_colliders()` は
**「primitive=box + テクスチャあり + 当たり判定なし」**を片っ端から掴んで
静的な当たり判定を足す。落書きは `shader` と `materialTextureOverrides` の
**両方**を持つので、`glow()` のような「シェーダーだけの板」の除外には掛からない。

助かるのは高さの規則の方だけ ── **箱の下端が床から 1.80m 以上なら対象外**。
だから落書きは必ずこの帯に置く（案内板 `SIGN_Y=2.24` / 下端 1.91 とほぼ同じ）。

**真下の面は場所ごとに違う**ので、呼ぶ側が計算して `y` を渡すこと:

| 落書き | 真下の歩ける面 | 中心の高さ | 下端 |
|---|---|---|---|
| C10（幅 1.90 なので別計算）| 白い部屋の床 `SILL2` | `SILL2 + 2.60` | `+1.92` |
| C18/C19/C20/C21/C17 | 第四幕の床 `Y4` | `Y4 + 2.36` | `+1.90` |
| C22（柱の南面）| 第五幕の床 `Y5` | `Y5 + 2.32` | `+1.91` |
| C23（東の壁）| `Y5` | `Y5 + 2.42` | `+1.91` |
| **C24** | **棚の天端 `Y5+0.60`** | `Y5 + 3.00` | 棚 `+1.96` |
| **C25** | **踊り場の天端 `Y5+2.40`** | `Y5 + 4.84` | 踊り場 `+2.00` |

C24 / C25 を「床から 2.36」で置くと、棚・踊り場から見て 1.8m に満たず
**当たり判定が付いて見えない壁になる**。

★名前で例外にしなかった理由: 同じ規則が `source/fix_colliders.js` にもあり
（Python の無い環境から直すため）、名前の例外を作ると片方だけ直すことになる。
**高さで守る**方が両方で正しい。

### 3.3 傾きは絵に焼き込む（実体を回さない）

落書きらしく見せる傾きは `blender_graffiti.py` の `SHEETS` の第 3 引数
（±1.1〜2.0 度）で**絵の側へ焼き込む**。実体を roll させると、
壁に貼った板の隅が壁へ潜って**絵が切れる**。

実体側の `yaw` は基準（0 / ±90 / 180）から **±2.3 度**だけずらしてある。
これで「掲示物ではなく書き置き」に見えるうえ、
机上検査 [6]（同一平面）が軸に乗った箱しか見ない作りなので**検査からも外れる**。
0.045m 浮かせてあるので、隅の出入りは最大 `0.72 * sin(2.3°) = 0.029m` ＝ 壁に潜らない。

### 3.35 ★★実機で最初に出た 2 つの不具合（どちらもシェーダーで直した）

**(a) 絵が鏡像と二重写しになった。**
落書きは箱プリミティブなので、絵は **-Z 面と +Z 面の両方**に貼られる。
このエンジンのカスタムシェーダー経路は**裏面を切っていない**ので、
奥の +Z 面に貼られた「左右反転した同じ絵」が手前の絵に重なって描かれ、
**左右対称な別の絵**に見えていた（人が真ん中に立ち、左右に同じ物が並ぶ絵になる）。

`SV_IsFrontFace` は巻き方とラスタライザ設定に依存して当てにならないので、
**視点空間で面の向きと視線を直接比べて**捨てている（座標系の左右手に依らない）:

```hlsl
float3 Pv = mul(float4(i.worldPos, 1.0f), view).xyz;   // カメラ→面
float3 Nv = mul(i.normal, (float3x3)view);             // 面の法線
clip(-dot(normalize(Nv), normalize(Pv)) - 0.02f);      // 手前を向いた面だけ残す
```

**(b) 明るい壁で落書きが消えた。**
暗い柱の上では白い線がよく読めるのに、**第五幕の踊り場**（仕上げの明滅バンクの真下で
壁がほぼ白い）では白いチョークがまったく読めなかった。かといって暗い線にすると
今度は柱や暗い区画で消える。

→ **PNG を 2 層で焼く**ようにした。同じ種（seed）で 2 度描き、
1 回目は線を `HALO=28` 単位だけ**太らせて黒**、2 回目は素の太さで**白**。
焼き上がりは **アルファ = 太らせた覆い / 赤 = 芯かどうか**。
エンジン側は `色 = lerp(暗い縁, チョーク, 赤)` に組み直す。

明るい壁では暗い縁が、暗い壁では白い芯が形を出す ＝ **どちらでも読める**。
`grow` は `Ink` が持っていて、線幅にも塗り図形の半径にも効く。
揺らぎは種から決まるので **2 枚は 1 ピクセルもずれない**。

★縁取りのアルファ倍率は **0.88**。最初 0.62 にしたら、明るい壁で結局読めなかった。

### 3.4 b0 の並び（`assets/shaders/Graffiti.hlsl`）

```
effectValue(1)  ← shaderEffectValue    擦れ
_reserved(3)    ← shaderParamsB        [むらの細かさ, 四辺で消す幅, 縁取りの暗さ]
shaderParams(4) ← shaderParams         [r, g, b, 濃さ]
```

`gen_liminal.py` の `water()` のコメントにある並びと**同じ**。
1 つでもずれると値が別の変数へ入る。
**コンパイルに失敗しても「直前の有効なバイトコードを維持」して黙って動く**ので、
シェーダーを直したら必ず `dx12_engine.log` を grep すること。

### 3.5 ★落書きは灯りに依らない（意図的）

このエンジンのカスタムメッシュ経路には**点光源が届かない**。b1 に来るのは
平行光と環境光だけで、この作品の太陽は `intensity=0`（屋内）。
素直に陰影を付けると落書きは常にほぼ真っ黒で、暗い区画では一文字も読めない。

落書きは「読めること」が唯一の仕事なので、明るさは `shaderParams.rgb` で固定した
（`ReconnectInk` と同じ考え方）。**ただし明るくしすぎない** ── 0.75 を超えると
自分で光って見えて、リミナル空間の明暗の縞（この作品の絵そのもの）が壊れる。
実際に使っているのは **0.66〜0.74**。

副作用として良かったこと: 継ぎ目 21 と 25 の落書きは**明滅バンクの真下**にあるので、
壁は明滅するのに**絵だけは暗い 1 秒の間も読めたまま**になる。
絵が言っている「消えた一瞬を待て」が目の前で起きる。

### 3.55 ★遠くから読ませる 1 枚は【線を太く】する（縮小で消える罠）

継ぎ目 10 の落書きだけは **13.7m 先**から読ませる。ここで 3 回撮り直した:

| 試した事 | 結果 |
|---|---|
| 終盤と同じ線の太さ・幅 1.90m | 入口からは**ただの灰色の染み**。何も読めない |
| 芯を炭色・縁取りを白へ**裏返す** | **もっと悪い**。面積の広い縁取りが白いので余計に壁へ沈む |
| **線を 1.5 倍に太らせる** + 幅 2.10m | 入口から人・戸口・吊り灯が分かる ＝ 目にとまる |

**効いたのは色ではなく線の太さ**。遠くでは 1 本の線が 1 画素未満に縮み、
縁取り・芯・透明が混ざって壁の色へ寄る（ミップ）。太さがそのまま読みやすさになる。

縁取りの暗さは **0.07**（終盤は 0.035）。真っ黒 0.015 まで落とすと遠目はほぼ変わらないのに、
**近くで線が「中抜きの管」に見える**ので、近くの見え方を採った。

### 3.6 まわりに何があるかも見ること

継ぎ目 24 の落書きは最初 `x=77.4` に置いたが、**真上に非常口の標識**（`W5_lure2` = x 77.0）
があって、緑の標識と落書きが上下でくっついた 1 枚の掲示物のように見えた。
`x=75.3` へ寄せて直してある。壁に貼る物は**標識・扉枠・破片と近すぎないか**を
実機で必ず見ること（机上検査は「重なっていない」ことしか見ない）。

## 4. Blender 側の実装で踏んだ罠

1. **Grease Pencil を使わない。** Blender 5.2 の GPv3 は API が 4.x と別物で、
   bpy から線を積む書き方が通用しない。**平たいメッシュ直書き**にした
   （線分 = 四角形 / 端と継ぎ目 = 8 角形の円盤）。曲線 + `bevel_depth` も試したが
   端が丸くならず、結局円盤を足すので同じことだった。
2. **図形ごとに z を 3e-5 ずつ足す。** 完全な同一平面だと z ファイティングでちらつく。
3. **手描きの揺らぎは低い周波数の正弦 3 本だけ。** 点ごとに乱数を振ると線が毛羽立ち、
   エンジンの FXAA でちらつく。
4. **`view_transform` は `'Standard'`。** AgX/Filmic のままだと白が 0.9 くらいに
   焼き下げられ、エンジンで色を掛けた時に思ったより暗くなる。
5. **world を作らないと EEVEE が落ちる。** しかも既定ノードを**名前で引かない**こと
   （Blender 5.2 では `"Background"` という名前では入っていない）。`nd.type` で探す。
6. **`__file__` は MCP から exec すると無い。** `run_graffiti.py` は
   `JUNCTION_ROOT` → `__file__` → 既定パス の順で拾うようにしてある。
7. 焼く大きさは **448px 高**。BC7 の時間は画素数に比例するので
   （`source/ui_icons/build_signs.js` の冒頭に実測がある）、9 枚あるここは上げすぎない。

### 絵そのもので踏んだ罠（実際に描いて見比べて直したもの）

* **× を灯りに重ねない。** 同じ太さの線どうしなので重ねると星印になり、
  何を否定しているのか読めない。真下へ離して打つ。
* **庇に方杖（筋交い）を入れない。** 線が太いので三角が塗り潰れて「旗」に見えた。
  **L 字だけ**で庇に見える。
* **暗がりの横縞は、消えている灯りの側にだけ敷く。** 全幅に敷くと、
  点いている灯りと × が縞に埋もれる。
* **連鎖の段は離して描かない。** 棚と繋げずに描いたら、宙に浮いた別の板に見えた。
